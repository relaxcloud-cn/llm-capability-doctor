# C01 题库草案：文本理解 24 题 + 指令执行 20 题

版本：c01-bank/draft-1
父设计：issue-46（子域划分）、issue-17（题库身份）
方法来源：文本理解块参考 SQuAD 2.0 抽取式问答与不可答题设计；指令执行块参考 IFEval 可验证约束与逐约束校验。
题库身份：全部为产品原创中文题（方法借鉴，不搬数据），身份标 `product-original`。

统一提示词（追加在每题任务后）：
```
只依据题目给出的材料和条件回答。先给最终答案；同时满足题目列出的所有输出要求。
材料没有提供的信息必须明确说明未知，不要使用外部知识补全。
```

判分总则：
- 文本理解块：判"内容对错"。`correct` = 命中期望答案或其任一等义表达且不含禁含值；`wrong` = 答错、漏答或编造。
- 指令执行块：判"内容 + 逐约束"。每条约束独立校验；全过才 `correct`，内容对但违反任一约束记 `incomplete` 并定位到具体约束，内容错记 `wrong`。
- 等义表达、禁含值、顺序规则逐题声明，判分前不做"差不多"的宽松解释。

## 二、指令执行块（20 题）

判分结构：`content`（内容规则）+ `constraints`（逐条校验）。以下材料均短小受控，重点在约束。

共用材料：项目甲预算30万、华东、进行中，负责人小林；项目乙预算50万、华北、已完成，负责人小周。

## 约束校验器清单（实现侧）

```
max_chars(n)            归一化后字符数 ≤ n
must_contain(s)         含子串 s（归一化后）
must_not_contain(s)     不含子串 s
keyword_min_count(s,n)  s 出现次数 ≥ n
json_object             全回答可被 JSON 解析且为对象
json_field_count(n)     顶层字段数 = n
json_required_fields    必含指定字段名集合
line_count(n)           非空行数 = n
paragraph_count(n)      空行分段数 = n
wrapped_title           含 [[...]] 形式的标题
starts_with(s)          回答以 s 开头
ends_with(s)            回答以 s 结尾
no_char(c)              不含字符 c
quoted_output           首尾为配对引号
exact_order(seq)        给定项按序出现
```

## 与既有实现的对齐说明

- 判分需要在 `acceptance` 上新增复合结构：`content: 内容规则` + `constraints: Vec<校验器>`；内容规则沿用 ExactAny(含别名)/ContainsAll/Numeric。
- `ScoreLabel` 语义按 issue-46：correct = 内容+全约束；incomplete = 内容对但漏/违反约束；wrong = 内容错或编造；pending = 无法唯一映射。
- 每题 1 次请求，temperature 0，max_tokens 256，非流式；总请求数 44。
