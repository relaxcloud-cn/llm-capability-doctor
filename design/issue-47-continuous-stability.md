# Issue #47：连续运行稳定性观察设计

版本：`performance-continuous-stability/v1`  
父任务：[#18](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/18)  
实现交接：[#27](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/27)

本文回答“固定负载下连续运行一段时间，是否变慢或错误增多”。它不提供稳定性总分、自动合格线、生产 SLA 或长期可靠性保证；重复执行归入本项，不新增重复成功率类别。

## 1. 固定负载与时窗

| 条件 | 固定值 |
| --- | --- |
| 输入 | 约 512 token 的受控文本 |
| 目标输出 | 256 token |
| 并发 | 2 |
| 预热 | 2 次，必须等待完成 |
| 正式派发窗 | 600 秒或 1,200 次请求，先到为止 |
| 单请求超时 | 120 秒 |
| 排空窗 | 派发窗关闭后最多 120 秒 |
| 分桶 | 按 60 秒派发/终态时间桶 |

预热不进入正式指标。达到请求上限时记录实际时长，不通过重复循环凑满时长；窗口关闭后的在途请求进入排空、超时或取消状态，不从分母删除。

## 2. 观察和分母

每次派发记录请求 ID、派发时间、首响时间、完整时间、终态、错误类别、输出长度、是否取消和证据引用。按派发时间统计负载与派发数，按终态时间统计吞吐和错误事件，不能把两个时间轴的分母混在一起。

每分钟补齐该派发桶的完整比例、首响和完整耗时；末尾请求即使在排空阶段完成，仍归入原派发桶。派发窗结束后仍在途的请求保留在派发分母，并分别记录排空完成、超时和取消。

结果至少展示：实际观察时长、预热/正式/排空请求数、完整/错误/超时/取消数、每分钟首响/完整耗时、每分钟吞吐、错误事件和输出长度覆盖。

## 3. 首尾趋势

首尾趋势只使用第一个和最后一个完整分钟桶。两桶各至少 10 个有效请求时，才计算中位数相对变化；否则只展示原值、样本数和“样本不足”。零基值、缺失值和无完整桶不能计算百分比。

首尾对比必须确认模型、请求模式、输入/输出目标和并发条件一致。不同输出长度、请求体大小、负载档位或服务配置的变化不自动归因于稳定性退化。

## 4. 保护与停止

本项不自动重试。出现 429、权限错误或共享保护条件时，终止继续派发并保存已完成观察；保护停止后的高负载组不自动恢复。网络错误、服务错误、超时和客户端取消分别记录，不汇总成“模型错误”。

停止原因必须是可审计事件：达到请求上限、时间窗关闭、保护停止、外部取消或执行器故障。若只运行两分钟就限流，报告只说明实际两分钟和限流原因，不写成十分钟通过。

## 5. 状态和客户展示

| 观察 | 展示 |
| --- | --- |
| 正常完成 | 完整计数和耗时进入正式指标 |
| 服务/网络错误 | 保留错误类型和时间桶，不归因业务质量 |
| 超时 | 归回原派发桶，保留慢请求和排空状态 |
| 客户端取消 | 单独记录，不改写为服务失败 |
| 样本不足 | 不计算首尾百分比，显示原值和覆盖缺口 |
| 窗口无异常 | 只说明该固定窗口未观察到异常，不证明长期稳定 |

## 6. 证据结构

每轮保存固定条件、窗口起止、请求 ID、派发和终态时间、时间桶、首响/完整时间、响应模式、输出长度、错误/超时/取消原因、排空轨迹、保护停止事件、取消来源和原始脱敏证据。指标必须能从单请求记录重新计算；不得只保存聚合数字。

## 7. 受控验收案例

| 案例 | 行为 | 预期 |
| --- | --- | --- |
| STAB-01 | 600 秒内稳定完成 | 显示实际窗口和每分钟指标，不生成 SLA |
| STAB-02 | 第 120 秒开始限流 | 在约 2 分钟停止派发并记录原因，不写十分钟通过 |
| STAB-03 | 首分钟只有 6 个有效请求 | 不计算首尾百分比，保留样本数 |
| STAB-04 | 最后 3 个请求在排空阶段完成/超时 | 归回派发桶，完成、超时和取消分开 |
| STAB-05 | 首尾输出长度不同 | 展示条件差异，不自动归因服务退化 |
| STAB-06 | 客户端主动取消 | 保存取消来源，不归因模型失败 |
| STAB-07 | 十分钟没有错误 | 只报告窗口内未观察到异常 |

## 8. 验收标准

| AC | 检查 | 预期 |
| --- | --- | --- |
| AC-01 | 固定条件审查 | 输入、输出、并发、预热、派发、超时和排空窗口明确 |
| AC-02 | 时间桶和分母审查 | 派发按派发时间，吞吐/错误按终态时间，末尾慢请求不删除 |
| AC-03 | 首尾趋势审查 | 每桶至少 10 个有效请求才计算相对变化，零基/缺失不计算 |
| AC-04 | STAB-02/STAB-06 | 限流、保护停止和客户端取消不混淆、不自动重试 |
| AC-05 | STAB-03/STAB-05/STAB-07 | 样本不足、条件变化和无异常窗口不被夸大解释 |
| AC-06 | 证据重算 | 聚合指标可由单请求记录重算，限制和停止原因可追溯 |

本设计只形成 #18 的连续稳定性输入，不代表执行器已实现，也不授权对客户模型开展未经确认的持续请求。
