# Issue #46：文本理解与指令执行题库设计

版本：`capability-instruction-following/v1`  
父任务：[#17](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/17)  
实现交接：[#26](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/26)

本文测量模型能否依据给定材料回答正确内容，并完整满足明确的输出要求。内容正确和指令约束分开记录；不重复 #16 的 JSON/消息接口测试，不测工具执行、长材料、推理竞赛或 Agent 任务。

## 1. 范围与题量

共 44 题：文本理解块 24 题（材料事实、条件筛选、信息不足各 8 题）+ 指令执行块 20 题（单项约束 12 题、多项约束 8 题）。单项约束扩为 12 题是为了让中文可用的 IFEval 式约束类型每类至少覆盖一次；多项约束 8 题测 2-4 条约束叠加。每题首轮生成 1 份回答，不从多次生成中挑选最优结果。

| 子项 | 编号 | 题量 | 固定目标 |
| --- | --- | --- | --- |
| 材料事实理解 | C01-1-01~08 | 8 | 从短材料回答有确定依据的问题，区分未提供信息 |
| 条件筛选与归纳 | C01-2-01~08 | 8 | 按明确条件筛选对象或事实，不做主观文风评分 |
| 单项输出要求 | C01-3-01~12 | 12 | 字段、列表项数、必须包含和禁止包含的要求 |
| 多项要求同时满足 | C01-4-01~08 | 8 | 内容正确并同时满足两个以上约束 |
| 信息不足处理 | C01-5-01~08 | 8 | 没有材料依据时承认缺失，不补造事实 |

方法来源：文本理解块参考 SQuAD 2.0 抽取式问答与不可答题设计；指令执行块参考 IFEval 可验证约束清单与逐约束程序化校验，中文不适用的约束（全大写、字母频率等）已剔除。题目全部为产品原创中文受控材料，不搬运基准数据，不宣称 IFEval 官方成绩。具体题目见 `design/c01-question-bank.md`。

所有样本使用简体中文受控原创材料，版本中固定语言、题目、答案集合、必需事实点、合法别名、顺序规则、约束和来源身份。题量是首版设计参数，不代表统计代表性。

## 2. 样本契约

每题保存：`sample_id`、材料、问题、固定提示、期望答案、必需事实点、允许等义表达、指令约束列表、禁止内容、顺序/数量规则、信息充分性、版本、内容哈希和来源身份。

统一提示：

```text
只依据题目给出的材料和条件回答。先给最终答案；同时满足题目列出的所有输出要求。材料没有提供的信息必须明确说明未知，不要使用外部知识补全。
```

题目只在确实需要时要求解释或计算式，不要求公开隐藏思维链，不因回答更长而加分。

## 3. 五类题型规则

### 3.1 材料事实理解

材料包含 2-5 个明确事实，问题只有一个可核验答案。至少 2 题要求回答材料未提供的字段，正确答案是“未提供/无法判断”。

### 3.2 条件筛选与归纳

每题给出布尔、阈值或集合条件，答案为筛选后的对象/事实集合。对象顺序、重复项和空集合规则提前固定；不以语言流畅度替代集合验收。

### 3.3 单项输出要求

每题只设置一个主要约束，例如固定字段、固定项目数、必须包含指定词或禁止包含某项。内容答案另行保存，不能把格式满足误写成事实正确。

### 3.4 多项要求同时满足

每题组合 2-4 个约束，如“只列超过阈值的项目、按金额降序、只输出两行、不得添加说明”。逐约束记录通过/失败，整题只有全部满足才正确。

### 3.5 信息不足处理

材料故意缺少关键事实，或存在多个无法区分的候选。正确答案必须说明缺失/不确定并避免编造；若题目要求提出澄清问题，则澄清字段必须完整。

## 4. 评分口径

主指标为“整题完整正确数 / 已评分有效题数”。整题必须同时满足内容答案和所有必需指令约束；详情分别列内容正确、逐约束满足、首次违反约束和典型错误。

| 标签 | 条件 | 处理 |
| --- | --- | --- |
| `correct` | 内容、必要事实和全部约束均正确 | 进入有效分母和正确数 |
| `wrong` | 内容错误、漏事实、筛选错误、编造或任一硬约束违反 | 进入有效分母和错误数 |
| `incomplete` | 有可解析回答但缺少必要内容/约束，无法整题通过 | 进入有效分母，单独统计 |
| `pending` | 等义表达或题目规则无法唯一映射 | 不进入自动正确率，转人工复核 |
| `missing` | 无响应、执行异常或题目未执行 | 不进入有效分母，记录覆盖缺口 |

合法等义表达、大小写、标点、数组顺序和数字容差必须在题目中显式声明。IFEval 的严格/宽松口径只可作为独立诊断参考，不能覆盖本产品主结果；翻译、改写或新增材料后不得宣称官方完整成绩。

## 5. 正反例

材料：“A 项目预算 3 万，B 项目预算 5 万，负责人未提供。”要求：“只列预算超过 4 万的项目；另说明负责人是否已知。”

| 回答 | 标签 | 原因 |
| --- | --- | --- |
| `B；负责人未知。` | `correct` | 内容和两项要求均满足 |
| `B；材料未说明负责人。` | `correct` | 合法等义表达 |
| `A、B；负责人未知。` | `wrong` | 筛选条件错误 |
| `B；负责人李某。` | `wrong` | 无依据补造事实 |
| `B` | `incomplete` | 缺少第二项要求 |
| 客户端超时 | `missing` | 无有效执行结果，不计内容错误 |

另需覆盖：事实正确但违反列表数量、禁用词出现、顺序错误、只满足部分约束、信息不足时强行回答和内容正确但格式不合规。

## 6. 证据与范围

每题保存材料/题目指纹、请求设置、原始模型输出、解析内容、必需事实差异、逐约束结果、标准化过程、执行状态和限制。禁止用二次生成挑选结果，禁止把另一模型的一句话裁决当作充分证据；API key 不进入证据。

与 #39 的结构化输出证据可以关联，但“JSON 合法”不等于内容正确；与 #41/#42 的能力题库按样本 ID 分开计分，避免重复计算同一失败。

## 7. 受控验收案例

| 案例 | 条件 | 预期 |
| --- | --- | --- |
| IF-R01 | 材料给出唯一答案 | 正确事实可核验 |
| IF-R02 | 关键字段未提供 | 明确未知，不编造 |
| IF-R03 | 筛选条件和空集合 | 集合结果和顺序按题目规则判断 |
| IF-R04 | 内容正确但少一项输出约束 | 整题不正确，逐约束定位 |
| IF-R05 | 内容正确但违反禁用词/数量/顺序 | 内容与指令结果分开记录 |
| IF-R06 | 合法等义表达 | 按预先声明规则通过 |
| IF-R07 | 超时或无有效响应 | `missing`，不混入内容错误分母 |

## 8. 验收标准

| AC | 检查 | 预期 |
| --- | --- | --- |
| AC-01 | 统计题型和题量 | 五类共 44 题（8+8+12+8+8），版本与编号稳定 |
| AC-02 | 材料事实和缺失信息 | 有依据答案、未知和编造可区分 |
| AC-03 | 单项/多项约束 | 内容正确与逐约束满足分开，任一硬约束失败可定位 |
| AC-04 | 等义表达和反例 | 只按预先声明的归一化处理，不临时放宽规则 |
| AC-05 | 执行异常与待复核 | missing、pending、wrong 不混淆，缺测不计 0 分 |
| AC-06 | 范围与证据 | 不重复接口结构、其他能力或 Agent，原始输出和判定可追溯 |
