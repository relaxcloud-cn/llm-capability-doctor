# Issue #42：信息提取与结构化填写题库设计

版本：`capability-information-extraction/v1`  
父任务：[#17](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/17)  
实现交接：[#26](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/26)

本文只冻结题库和评分方法。它测量模型能否从受控材料中找到正确字段、区分对象、处理缺失和解释冲突，不测结构化协议本身、推理难度或业务行业知识。

## 1. 范围与题量

共 40 题，五类各 8 题。每题一份结构化回答；题目、材料、字段 schema、期望状态和允许归一化均在样本版本中固定。

| 类别 | 编号 | 覆盖点 |
| --- | --- | --- |
| 单对象字段提取 | E01-E08 | 明确属性、值标准化、日期和金额 |
| 多对象区分 | O01-O08 | 同名、相似标识、多记录字段对应 |
| 对象关系归属 | R01-R08 | 项目、地点、订单和成员归属 |
| 缺失信息处理 | M01-M08 | 未提供、明确为空、不适用、不可推断 |
| 冲突及更新信息 | U01-U08 | 更新时间、优先规则、未规定冲突 |

所有材料为简体中文受控原创内容，不依赖联网、现实常识或特定行业知识。题量表示首版设计范围，不宣称覆盖所有行业表单。

## 2. 样本与输出契约

每个样本保存：`sample_id`、材料原文、任务说明、输入语言、字段 schema、字段状态、期望对象、允许归一化、禁止编造字段、来源身份、版本和指纹。

统一要求：

```text
只填写材料明确支持的字段。未提供、明确为空和不适用必须按题目 schema 表示，不要补充材料外信息。只输出指定结构。
```

字段状态固定为：`value`（有值）、`unknown`（材料未提供）、`null`（明确为空）、`not_applicable`（题目声明不适用）。题目必须明确允许哪些状态，模型不能用省略字段替代要求的状态。

## 3. 五类题型

### 3.1 单对象字段提取

每题一个明确对象，字段 3-5 个，覆盖姓名、金额、日期、枚举和别名。金额单位、日期格式和大小写归一化在题目中提前声明；未经声明不得转换。

### 3.2 多对象区分

每题 2-4 个对象，至少一半样例含同名或相似标识。输出必须按稳定对象 ID 归属字段，不能把 A 的联系人填到 B，也不能因字段值相同而省略对象。

### 3.3 对象关系归属

材料包含项目-地点、订单-联系人、成员-部门等关系。每题明确关系方向和允许多值形式；只要关系方向反了、跨对象串值或漏掉必要关联，整题不正确。

### 3.4 缺失信息处理

分别覆盖未提供、明确空字符串、明确“无”、不适用和信息不足。期望 schema 固定使用 `unknown`、`null` 或 `not_applicable`，不允许把未知填成常识值，也不允许用空字符串隐式代替未知。

### 3.5 冲突及更新信息

一部分样例明确给出更新时间或优先级，另一部分故意不提供解决规则。明确规则时选择满足规则的值并保留来源；无规则时必须标记冲突/无法确定，不能静默选择最后出现或最熟悉的值。

## 4. 评分口径

主指标为整题完整正确数 / 已评分有效题数。字段诊断只用于解释，不按字段数量加权，避免字段多的题隐性扩大分值。

| 标签 | 条件 | 计分处理 |
| --- | --- | --- |
| `correct` | 所有要求字段、对象、状态和必要关系均正确 | 进入有效分母和正确数 |
| `wrong` | 有效回答但存在错填、漏填、对象串值、无依据填写或冲突处理错误 | 进入有效分母和错误数 |
| `incomplete` | 结构可解析但缺少整题必要字段/对象，无法判为完整正确 | 进入有效分母，单独统计 |
| `pending` | 题目或归一化规则无法唯一映射，需要人工复核 | 不进入自动正确率 |
| `missing` | 无响应、执行异常或题目未执行 | 不进入有效分母 |

格式错误与值错误分开记录：原始输出不可解析时，整题不正确，但不得把所有字段都诊断为值错误。允许的日期、金额单位、别名、大小写和数组顺序归一化必须由样本显式声明。

## 5. 正反例

材料：订单 A 联系人为小林；订单 B 金额为 200 元；未给出订单 B 联系人。要求填写 B 的金额和联系人，未知联系人用 `unknown`。

| 回答 | 标签 | 原因 |
| --- | --- | --- |
| `{"amount":200,"contact":"unknown"}` | `correct` | 字段完整，未知状态正确 |
| `{"amount":200,"contact":"小林"}` | `wrong` | 把 A 的值串到 B，且无依据填写 |
| `{"amount":200}` | `incomplete` | 缺少题目要求的未知状态字段 |
| `{"amount":"200元","contact":"unknown"}` | 按样本规则 | 若金额字段允许单位归一化则正确，否则类型错误 |
| `{"amount":200,"contact":null}` | `wrong` | 未提供不等于明确为空 |

必须另有反例覆盖：同名对象、反向关系、额外编造字段、明确空值被误判未知、更新时间逆序、无规则冲突被静默解决和非法 JSON。

## 6. 来源与证据

40 题标记 `product_original`，引用 `agentcheck://capability/information-extraction/v1/<sample_id>`。SGD 只作为 schema、槽位和状态标注的方法参考；不复制上游题目、任务名或成绩，也不以其他项目许可证替代数据许可条件。

每题证据保存材料指纹、字段 schema 指纹、请求设置、原始模型输出、解析结果、字段级差异、状态判定路径、执行序号和限制。结构化模式可以作为固定条件复用 #39 证据，但不能把格式通过当内容正确。

## 7. 验收标准

| AC | 检查 | 预期 |
| --- | --- | --- |
| AC-01 | 统计五类题型和题量 | 每类 8 题，共 40 题，编号、版本和字段 schema 稳定 |
| AC-02 | 单对象、多对象和关系样例 | 对象 ID、字段和值的对应关系可独立核验 |
| AC-03 | 缺失、空值、不适用和信息不足 | 四种状态不混淆，不以省略或常识补值代替 |
| AC-04 | 有规则冲突和无规则冲突 | 有规则按规则取值，无规则保留冲突/不确定 |
| AC-05 | 归一化和格式反例 | 只使用预先声明的归一化；格式问题不冒充所有字段值错误 |
| AC-06 | 来源与证据审查 | 原创身份、版本指纹、原始输出和字段诊断可追溯 |
