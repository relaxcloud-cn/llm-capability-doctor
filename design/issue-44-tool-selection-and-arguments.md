# Issue #44：工具选择与参数填写题库设计

版本：`capability-tool-selection/v1`  
父任务：[#17](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/17)  
实现交接：[#26](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/26)

本文测量模型在任务语境中是否选对工具、填对业务参数，并能在不应调用或信息不足时保持边界。它不测工具调用协议本身（#36），不执行工具，不要求跨轮次恢复或真实业务操作（Agent 模块负责）。

## 1. 题量与子项

共 40 题，五类各 8 题，每题一份决策/调用方案。工具均为受控虚构接口，题目提前固定允许的工具集合、参数 schema、调用顺序和等效组合。

| 子项 | 编号 | 覆盖点 |
| --- | --- | --- |
| 工具选择 | TS01-TS08 | 相近干扰工具、目标与工具能力匹配 |
| 业务参数填写 | PA01-PA08 | 日期、对象、单位、枚举和范围 |
| 多目标调用组合 | MC01-MC08 | 调用集合、顺序和目标-参数对应 |
| 不应调用 | NC01-NC08 | 4 题无需工具、4 题没有匹配工具 |
| 必需信息不足 | MI01-MI08 | 澄清缺参，不编造参数完成调用 |

所有题目为简体中文产品原创内容，标记 `product_original`，不宣称完整 BFCL 成绩。BFCL 仅作工具/参数匹配方法参考。

## 2. 固定工具契约

每道题的候选工具可以从以下受控集合选择，名称和 schema 在样本内固定：

```json
[
  {"name":"lookup_order","parameters":{"order_id":"string"}},
  {"name":"cancel_order","parameters":{"order_id":"string","reason":"enum:duplicate|changed_mind"}},
  {"name":"lookup_delivery","parameters":{"order_id":"string","include_history":"boolean"}},
  {"name":"lookup_weather","parameters":{"city":"string","date":"YYYY-MM-DD","unit":"enum:celsius|fahrenheit"}}
]
```

工具描述必须明确能力和副作用；候选工具之间保留至少一个相近但错误的干扰项。题目不要求工具真的存在，也不允许模型通过执行结果补全缺失业务信息。

## 3. 任务与答案契约

每个样本保存：任务材料、候选工具及 schema、必要业务字段、允许的调用集合/有序序列、等效组合、禁止调用条件、澄清要点、预期状态、版本和指纹。

统一提示：

```text
根据任务目标选择工具并填写有依据的参数。没有匹配工具时说明不能完成；缺少必需信息时先提出最小澄清问题，不要猜测。只输出决策或调用方案，不执行工具。
```

## 4. 五类判定

### 4.1 工具选择

题目提供 2-4 个候选工具，其中至少一个语义相近但不满足目标。通过要求选中的工具集合与目标匹配；调用结构合法但选错工具仍为错误。

### 4.2 业务参数填写

从明确材料中提取日期、对象、单位、枚举和范围参数。未声明的日期转换、单位转换、别名归一化不自动允许；参数缺失、越界、类型错或无依据填写分别记录。

### 4.3 多目标调用组合

任务包含 2-3 个目标，样本预先声明允许的集合或有序序列。等效组合仅在样本明确列出时允许；多余调用、漏调用、目标-参数串位和顺序错误独立诊断。

### 4.4 不应调用

4 题要求直接回答，正确答案是“不调用”；4 题提供的工具均不能完成任务，正确答案是“无匹配工具并说明原因”。不因没产生调用直接扣分，也不把拒绝测试当成正确。

### 4.5 必需信息不足

缺少订单号、城市、日期等必填信息时，正确答案必须指出缺失字段并提出最小澄清问题。编造参数、套用上下文中其他对象的值或直接调用均为错误。

## 5. 评分口径

主指标为任务决策完整正确数 / 已评分有效题数。整题必须同时满足调用/不调用决定、工具集合、业务参数和题目约束；不按工具名字符串单一匹配。

| 标签 | 条件 | 处理 |
| --- | --- | --- |
| `correct` | 工具决策、参数、调用数量/顺序和边界处理全部正确 | 进入有效分母和正确数 |
| `wrong` | 选错、漏调、多调、参数错误、无依据填写或缺参仍调用 | 进入有效分母和错误数 |
| `incomplete` | 有决策但缺少必要调用/参数或澄清要点 | 进入有效分母，单独统计 |
| `pending` | 题目声明的等效方案无法唯一映射 | 不进入自动正确率 |
| `missing` | 无响应、执行异常或题目未执行 | 不进入有效分母 |

“不应调用”是正向答案；“没有匹配工具”和“缺少参数”必须分别判定。不能通过 `tool_choice`、`required` 等参数替模型完成本应自主决定的题目。

## 6. 正反例

候选工具：`lookup_order(order_id)`、`cancel_order(order_id, reason)`。任务：“查看 A123 是否已发货，不要取消订单。”

| 回答 | 标签 | 原因 |
| --- | --- | --- |
| 调用 `lookup_order`，`order_id=A123` | `correct` | 目标、工具和参数均匹配 |
| 调用 `cancel_order` | `wrong` | 副作用和目标均不匹配 |
| 调用查询工具，`order_id=A132` | `wrong` | 业务参数错误 |
| 未给订单号时追问订单号 | `correct` | 缺参时提出最小澄清 |
| 未给订单号却编造 A123 | `wrong` | 无依据填写 |
| 直接说“我无法操作”但有匹配工具和完整参数 | `wrong` | 不应把可完成任务当作无匹配 |

另有反例覆盖：同名对象串值、单位/日期错误、多目标漏调用、等效组合未声明、无工具可用时强行调用和无工具题仍产生调用。

## 7. 证据与范围

每题证据保存任务和材料指纹、候选工具 schema 指纹、模型原始输出、解析后的调用方案、工具集合/顺序、字段级差异、澄清问题要点、状态和限制。工具不执行，不保存虚构执行结果；API key 不进入证据。

结构化输出模式可复用 #39 的固定条件，但格式合法不等于任务选择正确；#36 的工具调用结构错误只作为关联诊断，不重复记为独立事故。没有工具能力的服务，能力前提单列，不把整类缺测当作 0 分。

## 8. 验收标准

| AC | 检查 | 预期 |
| --- | --- | --- |
| AC-01 | 统计五类题型和题量 | 每类 8 题，共 40 题，编号、schema 和版本稳定 |
| AC-02 | 相近干扰工具和业务参数 | 选错工具、错参、越界和无依据填写可独立定位 |
| AC-03 | 多目标调用 | 调用集合、顺序、等效方案、漏调和多调按题目规则判定 |
| AC-04 | 不应调用和无匹配工具 | 正确不调用、无匹配说明与错误拒答不混淆 |
| AC-05 | 必需信息不足 | 最小澄清正确，编造参数和串用其他对象值为错误 |
| AC-06 | 范围和证据审查 | 不执行工具、不扩大为 Agent，原始输出和诊断可追溯 |

## 9. 交接

#26 接入时按整题接受规则评分并保留诊断字段；工具调用协议由 #36、结构化输出由 #39、真实执行闭环由 Agent 模块分别负责。本设计不新增外部工具、web search、memory 或多轮执行环境。
