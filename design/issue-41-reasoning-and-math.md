# Issue #41：逻辑推理与计算题库设计

版本：`capability-reasoning-math/v1`  
父任务：[#17](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/17)  
实现交接：[#26](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/26)

本文只冻结题型、答案和评分口径，不执行模型、不生成模型成绩。目标是测量模型能否依据题目中给定的事实和规则完成基础推导；不要求公开内部思维链。

## 1. 范围与题量

共 40 题，五类各 8 题。每题一次正式回答；执行异常、无效响应和题目缺陷单独记录，不混入有效错误分母。

| 类别 | 编号 | 覆盖点 |
| --- | --- | --- |
| 条件判断 | C01-C08 | 满足/不满足、边界值、互斥条件、条件缺失 |
| 时间与顺序 | T01-T08 | 明确日期排序、先后关系、并列、不可确定顺序 |
| 数量比较 | Q01-Q08 | 大小、差值、比例、单位换算、相等边界 |
| 基础计算 | M01-M08 | 加减乘除、百分比、平均值、四舍五入、单位 |
| 多条件推导 | I01-I08 | 两到三条规则组合、冲突条件、信息不足和无解 |

题目均为产品原创受控材料，语言为简体中文，答案、单位、精度、舍入方式和时间基准写入样本对象。题目不依赖联网、当前日期、专业知识或现实常识补充。

## 2. 固定题目结构

每个样本必须包含：`sample_id`、类别、题目文本、给定事实、规则、问题、期望答案、允许等义表达、单位、数值容差、舍入规则、信息充分性、版本和来源身份。题目正文不得把答案或评分提示泄露给模型。

统一提示：

```text
只依据题目给出的事实和规则作答。先给最终答案；如题目要求单位，必须带单位。信息不足或无唯一答案时明确说明，不能补充题外事实。
```

不要求展示完整推理过程。只有样本明确声明需要“列出计算式”时，才核验可观察的最终式子或关键中间量；文字长短不加分。

## 3. 五类题型约束

### 3.1 条件判断

每题给出 2-4 条布尔或阈值规则，至少 2 题命中边界值，至少 1 题包含互斥条件，至少 1 题明确信息不足。答案为“满足/不满足/无法判断”之一，并保留触发规则编号。

### 3.2 时间与顺序

使用固定日期或相对顺序，不使用当前日期。每题最多 6 个事件，覆盖严格先后、同日并列、条件不足和跨月边界。排序题按完整顺序验收；无法确定时必须指出不确定位置。

### 3.3 数量比较

明确单位和换算关系，覆盖直接比较、差值、比例、相等边界和单位换算。答案必须包含数值和指定单位；容差仅在样本明确声明时生效。

### 3.4 基础计算

覆盖整数、小数、百分比、加权平均和简单统计。每题固定小数位和舍入方式，除数为零或数据不足时要求说明无法计算，不允许自行假设。

### 3.5 多条件推导

最多组合 3 条明确规则，覆盖唯一解、冲突规则、信息不足和无解。信息不足与无解必须区分：前者补充信息后可能有解，后者在现有规则下不存在满足条件的结果。

## 4. 评分口径

主指标为“结果完整正确题数 / 已评分有效题数”。每题只有在最终结论、必要数值、单位和必要条件全部正确时计为 `correct`。

| 标签 | 条件 | 分母 |
| --- | --- | --- |
| `correct` | 结论和必要表达均满足接受规则 | 进入有效评分分母 |
| `wrong` | 得到有效回答但数值、单位、条件或排序错误，或信息不足时编造 | 进入有效评分分母 |
| `incomplete` | 回答可解析但缺少必要部分，无法完成整题验收 | 进入有效评分分母，单独统计 |
| `pending` | 语义有回答但题目规则无法唯一映射，需人工复核 | 不进入自动正确率，单独统计 |
| `missing` | 无响应、执行异常或题目未执行 | 不进入有效评分分母 |

允许的等义表达（如“65 元”和“人民币六十五元”）由样本接受规则明确列出。不得用泛化的模糊相似度替代规则；数字、单位、集合和排序必须结构化校验。

## 5. 正反例

固定示例：物品单价 25 元，买 3 件，满 70 元减 10 元，无其他费用，实付多少元？

| 回答 | 标签 | 原因 |
| --- | --- | --- |
| `65 元` | `correct` | 计算和折扣条件均正确 |
| `人民币六十五元` | `correct` | 允许等义表达 |
| `75 元` | `wrong` | 漏用折扣条件 |
| `60 元` | `wrong` | 计算错误 |
| `需要知道运费` | `wrong` | 题目已明确无其他费用 |
| `无法判断` | `wrong` | 题目事实充分，不应回避 |

受控反例还必须覆盖：数值正确但单位错误、排序只答部分、比例与差值混淆、信息不足却编造、无解却给出任意解、服务超时和题目缺陷。

## 6. 来源与身份

本首版 40 题均标记 `product_original`，来源引用为 `agentcheck://capability/reasoning-math/v1/<sample_id>`。研究 BBH 固定快照和 DROP 论文只用于题型参考，不把上游名称、数据、提示或评分脚本冒充为本产品原题；若未来改编上游材料，必须单独标记 `adapted`、保存许可和变更指纹。

## 7. 验收标准

| AC | 检查 | 预期 |
| --- | --- | --- |
| AC-01 | 统计五类题型和题量 | 每类 8 题，共 40 题，编号和版本稳定 |
| AC-02 | 核对事实、规则、单位和时间基准 | 不依赖联网、当前日期或题外常识，答案条件明确 |
| AC-03 | 正确、等义、错误和缺失信息反例 | 结果、单位、必要条件和“无法判断”可按固定规则区分 |
| AC-04 | 无效执行、题目缺陷和待复核 | 不混入有效错误或正确率分母，原因单独留存 |
| AC-05 | 来源身份和变更指纹 | 原创/改编身份可追溯，不冒充 BBH/DROP 原始完整成绩 |
| AC-06 | 交给未参与起草者复核 | 无需猜测容差、舍入、单位或信息充分性即可重算答案 |
