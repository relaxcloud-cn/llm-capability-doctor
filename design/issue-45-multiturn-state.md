# Issue #45：多轮对话与条件承接题库设计

版本：`capability-multiturn-state/v1`  
父任务：[#17](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/17)  
实现交接：[#26](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/26)

本文测量模型在同一请求历史中是否保留有效条件、接受新条件、放弃已撤销条件并区分对象。它不测跨请求自动记忆、不重复 #16 的最小历史接收、不搭建 Agent 工作区。

## 1. 题量与对话结构

共 40 段完整对话，五类各 8 段。每段固定 3 个用户回合和 3 个模型回答位置；计分单位是完整对话，不把 120 个回合冒充 120 个独立样本。

| 类别 | 编号 | 目标 |
| --- | --- | --- |
| 追问与补充 | MT01-MT08 | 在原目标上增加明确事实，继续完成任务 |
| 条件修改 | MC01-MC08 | 后续新值替换旧值，其他条件不变 |
| 条件撤销 | MR01-MR08 | 撤回限制后不继续沿用过期条件 |
| 对象切换 | MO01-MO08 | A/B 两个对象来回询问，不串用状态 |
| 保留未变要求 | MP01-MP08 | 修改一个条件时保留其余任务要求 |

所有材料为简体中文受控原创内容，不依赖当前日期、联网或现实常识。每段脚本固定版本、事实、规则、已撤销条件和答案接受规则。

## 2. 对话输入契约

后续请求必须携带真实的 system、user、assistant、user 历史；不得用标准答案替换模型上一轮回复。每一轮记录完整消息指纹、当前有效状态、已失效状态、期望输出和实际输出。

每段脚本包含：`conversation_id`、三轮用户消息、唯一对象/条件标识、状态变更类型、有效事实表、撤销事实表、保留要求、期望答案、允许等义表达、版本和指纹。

统一提示：

```text
只依据本段对话中仍然有效的事实和要求回答。后续消息明确修改或撤销的条件优先；未提供的信息不要猜测。按当前轮问题回答，并保留仍未改变的要求。
```

## 3. 五类脚本规则

### 3.1 追问与补充

第 1 轮建立对象和目标，第 2 轮补充一个事实或要求澄清，第 3 轮要求基于完整状态回答。补充事实只能新增，不得隐式覆盖旧值。

### 3.2 条件修改

第 2 轮明确“改为/更新为”新日期、金额或要求。第 3 轮必须使用新值，同时保留未修改条件。旧值不得继续进入最终答案。

### 3.3 条件撤销

第 2 轮明确撤回一个限制，例如“取消只列工作日”。第 3 轮检查模型是否停止沿用已撤销条件；撤销只影响指定条件，不删除其他有效事实。

### 3.4 对象切换

至少两个对象拥有相似字段或同名值。第 2、3 轮切换询问对象，答案必须绑定当前对象 ID；A 的预算、负责人或状态不得串到 B。

### 3.5 保留未变要求

任务包含格式、单位、排序或字段完整性要求。第 2 轮只修改一个事实；第 3 轮同时检查新事实和原有格式/单位/排序要求，不能只答修改字段。

## 4. 评分口径

主指标为“连续三轮均正确的完整对话数 / 已评分有效对话数”。逐轮正确、首次偏离轮次、偏离类型只作诊断。

| 标签 | 条件 | 处理 |
| --- | --- | --- |
| `correct` | 三轮输出均符合当前有效状态和答案规则 | 进入完整对话正确数 |
| `wrong` | 任一轮出现有效条件承接错误、对象串用、过期条件沿用或未保留要求 | 进入完整对话错误数；首次错误永久保留 |
| `incomplete` | 某轮有回答但缺少必要字段，不能完成该轮验收 | 进入有效分母，单独统计 |
| `pending` | 题目或等义答案无法唯一映射 | 不进入自动正确率 |
| `missing` | 无响应、执行异常或对话未完成 | 不进入有效分母；单独记录完成度 |

若前一轮已出现有效错误，后续轮次即使答对，整段仍为 `wrong`；若尚未观察到错误但后续因执行异常中断，整段为 `missing/inconclusive`，不得只保留已走完的优秀样本。

## 5. 说明样例

| 回合 | 用户消息 | 当前有效状态与期望 |
| --- | --- | --- |
| 1 | 项目 A 预算 100 元，负责人小林。 | A：100 元、小林 |
| 2 | A 预算改为 120 元，负责人不变；新增项目 B，预算 80 元。 | A：120 元、小林；B：80 元、负责人未知 |
| 3 | 分别列出 A、B 的预算和负责人。 | 使用 A 新预算，不把小林填给 B |

错误示例包括继续写 A 为 100 元、将小林赋给 B、只回答预算而漏负责人、或因新建 B 删除 A 的负责人。最后一轮答对不能覆盖第 2 轮有效错误。

## 6. 执行异常与证据

单段对话初测 1 次；有效回答不符合规则时可以按统一执行策略复核，但复核不能覆盖首次有效错误。网络、认证、限流、超时和响应截断保持执行异常，不改写为条件承接失败。异常发生在已观察有效错误之后时，同时保留 `wrong` 和未完成标记。

每段证据保存：消息历史、每轮状态快照、实际模型输出、解析结果、事实增删改轨迹、首次偏离轮次、执行序号、版本指纹和限制。API key 不进入证据。

## 7. 受控验收案例

| 案例 | 条件 | 预期 |
| --- | --- | --- |
| MT-R01 | 第二轮补充事实 | 第三轮同时使用旧事实和新事实 |
| MT-R02 | 第二轮修改金额 | 最终只使用新金额，其他字段保留 |
| MT-R03 | 第二轮撤销筛选条件 | 最终不沿用撤销条件，未撤销条件仍有效 |
| MT-R04 | A/B 对象来回切换 | 每轮绑定当前对象，不串值 |
| MT-R05 | 只修改一个字段但保留单位/格式要求 | 新字段和未变要求均满足 |
| MT-R06 | 中间轮有效错误、最后轮正确 | 整段仍为 `wrong`，首次偏离可追溯 |
| MT-R07 | 中途超时且之前无有效错误 | 标记未完成，不计入正确或错误分母 |

## 8. 验收标准

| AC | 检查 | 预期 |
| --- | --- | --- |
| AC-01 | 统计题型和轮次 | 五类各 8 段，共 40 段，每段 3 个用户回合 |
| AC-02 | 修改、撤销和保留要求 | 新条件优先，撤销条件失效，未变要求保留 |
| AC-03 | 对象切换 | 对象状态不串用，当前轮目标可独立核验 |
| AC-04 | 完整对话评分 | 逐轮诊断与整段分母分开，首次有效错误不被覆盖 |
| AC-05 | 执行异常 | 未完成和有效错误不混淆，异常不伪造成模型失败 |
| AC-06 | 证据审查 | 消息历史、状态轨迹、实际输出和首次偏离可追溯 |

## 9. 交接

#26 接入时必须使用真实模型历史和预先固定的状态表，不把上一轮模型错误当作事实，不扩展为跨会话记忆或 Agent 工作区。#16 只负责消息格式/最小历史接受，本设计负责条件变化后的内容正确性。
