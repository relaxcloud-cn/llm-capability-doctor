# 模型规格实测：七类测试方法与判定规则

版本：1.0
整理日期：2026-09-11
关联任务：[#16](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/16)
交接任务：[#25](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/25)

本文是模型规格实测的正式设计输入，不是检测器实现，也不是某个模型的实测结果。所有示例均为受控测试材料。真实运行时必须记录请求、响应、配置、时间、重试和原始证据。

## 1. 目标与边界

本模块回答当前接入的模型服务“支持什么、实际验证到哪里、有哪些限制”，不回答模型能力强弱，不生成能力总分，不替代 Agent 任务验收，也不把一次网络成功解释为能力通过。

接口范围为 OpenAI 风格的 Chat Completions。除流式输出项外，默认使用非流式请求。服务身份、URL、模型名、认证方式和运行环境属于本次检测对象，结论不直接归因于模型本体。

首版固定七类：

| 编号 | 类别 | 本项要回答的问题 | 不回答的问题 |
| --- | --- | --- | --- |
| S01 | 上下文容量 | 在固定输出余量条件下，服务实际接受并完成到多大输入；总窗口边界能否被证据支持 | 长材料理解质量、最大输出能力 |
| S02 | 输出长度 | 显式输出上限是否被接受和执行；自然结束与达到上限能否区分 | 最大输出排行榜、内容质量 |
| S03 | 常用参数 | P02-P06 是否接受以及控制是否生效 | 未列参数的兼容性、随机性参数质量 |
| S04 | 工具调用 | 能否按给定工具和参数生成正确的非流式调用 | 工具执行、回传、续答、规划和工具选择能力 |
| S05 | 结构化输出 | 能否返回合法 JSON，以及能否满足给定结构 | 业务字段是否正确、业务任务质量 |
| S06 | 消息与多轮输入 | 消息角色和历史消息是否被接受，最小跨轮信息是否保持 | 长期记忆、跨会话记忆、复杂对话质量 |
| S07 | 流式输出 | 普通文本和工具调用的增量能否接收、组装并正常结束 | 首字节延迟、吞吐、并发和稳定性 |

输出长度不是上下文容量的替代项；流式输出不是性能测试的替代项；S04 的工具生成不是 Agent 闭环的替代项。

## 2. 统一执行契约

### 2.1 测试前固定条件

每个检测记录必须包含以下条件：

| 字段 | 要求 |
| --- | --- |
| endpoint | 完整请求地址或脱敏后的稳定标识 |
| model | 原样记录模型名，不尝试鉴定后台真实模型 |
| protocol | Chat Completions；未知协议不得伪装为兼容 |
| request settings | 温度、工具、输出格式、流式开关等完整记录 |
| test version | 本文版本、类别编号、样例编号和题目指纹 |
| environment | 客户端版本、操作系统、代理/网关和测试时间 |
| evidence | 脱敏请求、HTTP 状态、完整响应或完整事件序列、解析结果 |

同一个样例的比较请求只能改变正在验证的一个因素。认证失败、服务不可达、全局限流等环境阻断不应被重复发送到所有样例；应停止该分支并标记执行异常。

### 2.2 结果状态

原始证据与客户显示状态分开保存。检测器不得丢弃首次有效失败。

| 状态 | 使用条件 | 禁止解释 |
| --- | --- | --- |
| `accepted` | HTTP 和协议层接受了字段，但没有足够行为证据 | 不得写成参数已生效或能力已通过 |
| `effective` | 受控对照证明目标控制改变了行为 | 不得扩大到未测取值或任意组合 |
| `verified_range` | 在明确记录的输入、输出或 schema 范围内完成并满足规则 | 不得写成服务理论最大值 |
| `unsupported` | 有效响应明确拒绝或明确不支持该能力 | 不得从一次环境错误推出 |
| `failed` | 有效响应违反了本项规则 | 不得被后续偶然成功覆盖 |
| `inconclusive` | 没有足够有效证据，通常由超时、限流、截断或计数缺失造成 | 不得冒充通过或失败 |
| `not_applicable` | 当前协议、配置或样例条件不适用 | 不得计为失败 |

`accepted`、`effective` 和 `verified_range` 是不同层级的事实，报告可以同时保存。例如某参数可以是 `accepted`，但生效状态为 `inconclusive`。

### 2.3 重试和停止

统一规则如下：

1. 首次有效响应不符合规则时，保留该失败；同一请求和设置最多追加两次复核。
2. 超时、限流、连接中断、无效 HTTP 响应等执行异常最多追加两次重试；取得有效响应后转入内容判定。
3. 重试不会改变题目、设置或证据版本，也不会递归触发新的复核。
4. 同一类别中的单个样例失败，不停止其他独立样例；全局认证或服务阻断除外。
5. 没有取得足够有效结果时使用 `inconclusive`，不使用“失败”掩盖证据缺口。

### 2.4 固定执行矩阵

下表冻结首版的样例数量和初测次数。表中“复核 2 次”只在首次取得有效但不符合规则的响应时触发；“异常重试 2 次”只在执行异常时触发。它们不是统计可靠性承诺，也不允许无限重试。

| 类别 | 初测样例与次数 | 固定输入/设置 | 复核与异常上限 | 停止边界 |
| --- | --- | --- | --- | --- |
| S01 上下文容量 | 从 1,024 起按 2 倍阶梯；接近边界时二分，每个档位初测 1 次 | 固定 system、唯一填充、输出上限 256、固定计数来源 | 有效容量拒绝相邻档复核 2 次；执行异常重试 2 次 | 取得相邻成功/明确容量拒绝，或计数/原因不足时停止并标 `inconclusive` |
| S02 输出长度 | 3 档：小上限、中上限、自然结束，各 1 次 | 同一编号序列提示；每档只设置一个输出上限字段 | 有效规则失败复核 2 次；执行异常重试 2 次 | 保存 finish reason、实际文本和 usage；自然结束不再扩探 |
| S03 常用参数 | P02-P06 各至少 1 个区分性对照；控制组和基线组各 1 次 | 同一 prompt、工具和其他设置，只改变目标参数 | 对照有效但不符合预期复核 2 次；执行异常重试 2 次 | 完成该参数的接受/生效判断；对照不可区分时停止为 `accepted` 或 `inconclusive` |
| S04 工具调用 | 7 类样例，各 3 组参数，每组初测 1 次 | 工具定义完整；参数覆盖字符串、数字、布尔、枚举、嵌套对象、数组及多调用 | 有效调用错误复核 2 次；执行异常重试 2 次 | 完成该样例组；不因单项失败停止其他样例 |
| S05 结构化输出 | 普通文本、合法 JSON、指定结构各 1 次 | 同一短文本；按模式分别设置 `response_format` | 有效解析/schema 失败复核 2 次；执行异常重试 2 次 | 解析、schema 或明确拒绝证据齐全后停止 |
| S06 消息与多轮 | M01-M04 各 1 次 | 固定角色组合和唯一历史标记；不跨请求 | 有效消息/续答失败复核 2 次；执行异常重试 2 次 | 完成当前角色组合；不扩展到未列角色或跨会话 |
| S07 流式输出 | 普通文本、工具调用各 1 次 | `stream: true`，固定事件样例和正常结束要求 | 有效组装/结束失败复核 2 次；执行异常重试 2 次 | 收到正常结束或明确错误；客户端主动停止单独记录 |

所有类别均采用“初测一次、有效失败复核两次、执行异常重试两次”的上限解释；没有有效证据时不得因为重试次数耗尽而改写成 `failed`。

## 3. S01 上下文容量

### 3.1 测试目标

测量在固定最小输出余量下，服务可接受并完成的最大输入 token 数。结果表达为“已验证到 N tokens”或“未取得边界证据”，不写成模型声明的最大上下文窗口。

### 3.2 输入和设置

使用可由客户端确定内容的 ASCII 填充块，并在首尾加入唯一标记，避免服务端缓存或重复内容造成误判。每个请求使用同一 system 消息和同一短用户指令；`max_tokens` 或等价输出上限固定为 256，temperature 固定为 0（若字段不适用则记录未设置）。

输入阶梯默认从 1,024 tokens 开始按 2 倍增长，接近目标边界时使用二分探测；产品实现必须记录实际输入计数来源。优先级为服务 `usage.prompt_tokens`，其次为经过版本化的本地计数器；只有计数可信时才允许声明 token 范围。

### 3.3 通过和停止条件

一次输入档位只有在 HTTP 2xx、响应可解析、结束原因可观察且回复包含指定唯一标记时才算完成。遇到上下文超限、明确长度拒绝或可靠截断，在相邻档位复核后形成边界；遇到超时、限流、网关错误或 token 计数缺失，只能形成证据缺口。

最高成功档只能写成“成功完成到 N tokens”。只有失败档和成功档共同形成相邻边界，并且失败原因明确属于输入容量时，才可写“边界约在 N-M tokens”；否则不得推断上限。

### 3.4 反例

| 场景 | 正确结果 | 错误结果 |
| --- | --- | --- |
| 96K 成功，128K 因网关超时 | 已验证到 96K，边界无法确认 | 结论为最大上下文小于 128K |
| 128K 输入被拒绝并明确提示上下文超限 | 记录明确拒绝，并与相邻成功档形成边界 | 记为网络错误或直接整套服务不可用 |
| 输入计数仅按字符估算且无版本化 tokenizer | `inconclusive` | 把字符数写成 token 数 |

## 4. S02 输出长度

### 4.1 测试目标

验证服务是否接受并执行明确的输出上限，并区分自然结束、达到上限、截断和执行异常。本项不寻找最大输出长度。

### 4.2 输入和设置

使用要求输出固定编号序列的受控提示，例如“只输出从 001 开始的连续编号，不要解释”。分别测试小上限、中上限和一个自然结束对照。优先使用当前服务支持的 `max_completion_tokens`；若协议明确使用 `max_tokens`，记录所用字段，不同时发送两者。

每个上限档至少保存服务返回的 `finish_reason`、usage completion token 计数（如有）和实际文本。内容提早停止不能仅凭文本长度判为达到上限。

### 4.3 判定

| 事实 | 判定 |
| --- | --- |
| 字段被接受，且受限请求稳定以长度上限结束 | `effective`，范围仅限该字段和档位 |
| 字段被接受，但没有 finish reason 或其他结束证据 | `accepted` 或 `inconclusive` |
| 服务明确拒绝字段 | `unsupported` |
| 受限响应在有效完成前被截断 | `failed` 或 `inconclusive`，取决于截断原因是否可确认 |
| 自然结束早于设置上限 | 自然结束事实，不证明上限失效 |

## 5. S03 常用参数

### 5.1 固定清单

首版只检测 P02-P06。P01 及其他参数不因客户端默认行为而隐式加入。

| 编号 | 参数 | 受控行为 |
| --- | --- | --- |
| P02 | `tool_choice: "none"` | 提供工具但禁止模型调用 |
| P03 | `tool_choice: {"type":"function","function":{"name":"..."}}` | 指定一个工具并检查调用对象 |
| P04 | `tool_choice: "required"` | 要求至少生成一个工具调用 |
| P05 | `parallel_tool_calls: false` | 双调用任务最多生成一个工具调用 |
| P06 | `stop` | 在固定停止标记前结束文本生成 |

### 5.2 方法

每个参数使用同一输入、工具定义和其他设置的对照请求，只改变目标参数。每个参数至少包含一个能区分“默认行为”和“受控行为”的样例；P03 和 P05 使用两个工具或两个调用目标，避免题目本身强迫出唯一结果。

参数字段被接受只产生 `accepted`。只有对照组和控制组的预期行为差异被观察到，且差异不是随机一次变化，才产生 `effective`。同一控制样例的首次有效失败必须保留，复核成功只能作为附加证据。

随机性参数不在本清单中；任何需要通过多次采样判断的参数都不得用单次不同输出证明生效。

### 5.3 反例

| 场景 | 正确结果 |
| --- | --- |
| `tool_choice: "none"` 被接受，但默认组和控制组都没有调用 | `accepted`，生效证据不足 |
| `required` 被接受，控制组出现合法调用，未强制组允许自然回答 | `effective` |
| `stop` 请求 2xx，但文本自然结束在标记之前且没有结束原因 | 未确认生效，不写成通过 |

## 6. S04 工具调用

### 6.1 范围

只验证非流式响应能否生成符合工具定义的调用。不执行工具，不回传 tool 消息，不要求续答，不评价模型是否会选择合适工具。

### 6.2 固定工具和样例

工具定义必须在请求中完整给出，题目直接提供所有参数值，不考推理。至少覆盖以下参数形态：字符串、数字、布尔值、枚举、嵌套对象、数组。

| 样例 | 内容 | 必查事实 |
| --- | --- | --- |
| T01 | 单个工具，字符串参数 | 工具名、JSON 可解析、必填值 |
| T02 | 单个工具，数字和布尔参数 | 类型和值 |
| T03 | 单个工具，枚举参数 | 枚举值和工具名 |
| T04 | 单个工具，嵌套对象 | 层级和内部必填字段 |
| T05 | 单个工具，数组 | 数组类型、元素类型和顺序要求 |
| T06 | 同一工具调用两次 | 两次调用均存在，参数不串位 |
| T07 | 两个不同工具各调用一次 | 工具与参数对应，保留调用数量 |

每种样例使用 3 组参数，每组初测 1 次。有效响应不合格时对同一输入和设置追加 2 次复核；执行异常最多补试 2 次。样例之间独立运行。

### 6.3 判定

合法调用必须同时满足：响应包含接口规定的工具调用；工具名称正确；参数可解析；必填字段、类型和值符合样例；多调用数量和对应关系正确。没有调用、漏调用、普通文字代替调用、参数串位或有效 JSON 但 schema 不符均为 `failed`。

通过只覆盖对应工具、参数形态、调用数量和非流式模式；不扩大到任意 schema、任意嵌套深度或流式调用。

## 7. S05 结构化输出

### 7.1 两个独立问题

合法 JSON 与指定结构必须分开测量：前者只验证语法，后者验证字段、类型和约束。两者都不评价字段内容是否完成业务目标。

### 7.2 测试方法

使用相同短文本，分别发送普通文本请求、JSON 模式请求和指定 JSON Schema 请求（仅在服务声明支持且接口适用时）。每个请求带唯一标记和最小字段集合，避免把业务抽取误当结构化输出能力。

| 子项 | 成功条件 | 失败条件 |
| --- | --- | --- |
| 合法 JSON | 内容去除协议包装后可被标准 JSON 解析器解析 | 解析失败、夹杂不可解析前后文 |
| 指定结构 | JSON 解析成功，必填字段存在，字段类型和枚举约束满足 | 缺字段、类型错误、额外字段违反明确 schema |

字段被接受但没有可解析响应为 `accepted` 或 `inconclusive`，不能为通过。服务明确拒绝模式字段为 `unsupported`；HTTP 错误或超时不作为结构能力失败。

## 8. S06 消息与多轮输入

### 8.1 测试目标

验证服务是否接受常见消息角色，以及在同一请求携带历史消息时能否完成最小的跨轮信息传递。该项不测试跨请求记忆。

### 8.2 样例

| 样例 | 请求 | 成功条件 |
| --- | --- | --- |
| M01 | system + user | 返回非空、可解析的 assistant 消息 |
| M02 | system + user + assistant + user | 最后一轮正确引用历史中唯一标记 |
| M03 | 多条 user 消息和一条 assistant 历史 | 能区分当前问题与历史标记，结束正常 |
| M04 | 适用时加入 tool 消息，但不要求工具闭环 | 消息被接受；不适用则记录 `not_applicable` |

每个样例的唯一标记只出现于一个历史位置。答案要求只确认标记，不要求长篇生成。角色被拒绝、消息格式错误或响应为空时按有效响应内容判定；认证、网关和超时等异常保持 `inconclusive`。

结论仅覆盖已测角色组合和“同一请求携带历史”模式，不写成支持任意消息序列或跨会话记忆。

## 9. S07 流式输出

### 9.1 范围和交接

流式输出分为普通文本和工具调用两种场景。检测客户端必须保存原始 SSE 事件顺序、事件内容、终止事件和组装结果；传输分块数量不等于模型内容增量数量。

本节定义 #16 的七类总规范；事件级解析器、完整 fixture 和更细的异常样例由直接子任务 [#40](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/40) 继续维护。#40 的细化不得改变本节的范围和状态语义。

### 9.2 普通文本

请求固定 `stream: true`，提示返回带首尾唯一标记的短文本。成功必须同时满足：收到可识别的内容增量；按协议顺序组装出完整预期文本；收到正常结束信号；客户端没有主动停止连接。

空内容事件可以是合法事件，不单独判失败。部分文本后连接断开、终止原因缺失或组装结果不完整为 `failed` 或 `inconclusive`，取决于服务是否给出明确有效错误。

### 9.3 工具调用

请求携带一个简单工具并开启流式，模型应增量返回工具名称、调用标识和参数片段。参数片段不要求每个事件都是完整 JSON；只有全部片段按调用标识组装后仍不可解析或不符合 schema，才判定为有效失败。

不执行工具，不回传结果，不要求续答。多调用、截断、错误事件和客户端主动停止分别留存，不能把“收到部分参数”写成完整成功。

## 10. 客户规格表

客户视图必须同时显示结论、已测范围、条件、限制和证据位置。示例不是实测结果：

| 类别 | 结果示例 | 条件和限制 | 证据 |
| --- | --- | --- | --- |
| 上下文容量 | 已验证到 96,000 tokens | 固定输出余量 256；128,000 档超时，边界未确认 | `evidence://S01/128k` |
| 输出长度 | `max_tokens` 已验证生效 | 仅验证 128 和 256 两档；不代表最大输出 | `evidence://S02/256` |
| 常用参数 | P02 `accepted`，P04 `effective` | 结论只覆盖对应对照样例 | `evidence://S03/P04` |
| 工具调用 | 数字参数通过，数组参数未通过 | 非流式；不含工具执行闭环 | `evidence://S04/T02` |
| 结构化输出 | JSON 通过，指定结构未验证 | schema 仅包含已列字段 | `evidence://S05/schema-1` |
| 消息与多轮 | M02 通过 | 同一请求内历史；不含跨会话记忆 | `evidence://S06/M02` |
| 流式输出 | 普通文本通过，工具参数组装未完成 | 不含性能结论 | `evidence://S07/tool` |

“未通过某个规格子项”不等于整套服务不可用；总体使用结论由后续模块依据刚性规则和 Agent 证据生成。

## 11. 判定反例集

| 事实 | 不应得出的结论 | 正确记录 |
| --- | --- | --- |
| HTTP 2xx，但 `tool_choice` 控制前后行为没有区分 | 参数已生效 | `accepted`，生效证据不足 |
| 一次请求超时 | 模型不支持该能力 | `inconclusive`，执行异常 |
| 最高输入档成功，未测试更高档 | 最大上下文就是该档 | `verified_range`，只到该成功档 |
| 输出自然提前结束 | 输出上限失效 | 记录自然结束，不作失效结论 |
| 流式收到多个参数片段 | 工具调用完整成功 | 等待组装、解析和结束证据 |
| JSON 可解析但缺 schema 必填字段 | 指定结构通过 | 结构化输出子项 `failed` |
| 可选 tool 消息在当前协议不适用 | 整套服务失败 | `not_applicable` |
| 复核成功覆盖首次有效错误 | 本项通过 | 保留首次 `failed`，附加复核证据 |

## 12. 证据包与交接

每个子项至少生成一个可定位证据包，包含：

1. 脱敏后的请求及固定设置；
2. HTTP 状态、原始响应或完整事件序列；
3. 解析器版本、计数来源、实际长度和结束原因；
4. 初测、复核、异常重试之间的关系；
5. 原始状态、客户状态、适用范围和限制；
6. 题目/工具/schema 指纹及本文版本。

交接给 #25 的接口是：类别编号、样例编号、固定配置、状态、已验证范围、证据引用和限制。#25 不得从 `verified_range` 推导未测能力，不得把 `accepted` 计入通过，不得重新解释本规则中的异常状态。

## 13. #16 验收记录

本 PR 的文档自检对应 Issue #16 的 AC。正式人工验收仍需由未参与起草者按下表执行并记录版本、命令、证据位置和结果：

| AC | 检查动作 | 文档落点 | 通过证据 |
| --- | --- | --- | --- |
| AC-01 | 逐类核对七类输入、步骤、结束和判定 | 第 1、3-9 节 | 七类均无未决执行占位项 |
| AC-02 | 检查接受但未生效、单次变化和对照案例 | 第 2、5、11 节 | 只产生 `accepted` 或证据不足 |
| AC-03 | 检查最高成功档、自然结束、边界不确定 | 第 3、4、11 节 | 不冒充最大输入或输出 |
| AC-04 | 检查不适用、有效失败和环境异常 | 第 2、8、9、11 节 | 不混淆 `not_applicable`、`failed`、`inconclusive` |

验收记录格式固定为：

```text
AC 编号 -> 材料及版本 -> 检查方法或运行命令 -> 预期与实际
-> 证据位置 -> 验证结果 -> 修订提交
```

没有执行的检查必须标记为“未执行”，不能写成“通过”。本文完成后，#25 可以开始实现数据结构和检测器；真实模型测试和独立复核不因本文合并而自动完成。
