# 其他服务与历史结果对比：首版范围与可比条件

版本：1.0
整理日期：2026-09-11
关联任务：[#22](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/22)
交接任务：[#35](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/35)

本文冻结补充对比的首版范围和可比条件。本文不实现排行、历史管理或对比页面，不把不同条件下的结果合并成模型优劣结论。

## 1. 首版范围决策

| 对比形式 | 首版结论 | 原因 |
| --- | --- | --- |
| 官方 Chat Completions 结构基线 | **纳入** | #20 的 BC01-BC14 是固定参考结构，属于当前检测的第一视图 |
| 同一服务、同一配置的复测 | **纳入有限记录** | 用于查看同条件事实变化，不承诺自动归因或质量趋势 |
| 同一服务的不同模型/版本 | **延后** | 必须先固定题库、规则、负载和运行环境，不能用记录名称推导变化 |
| 不同服务的横向对比 | **延后** | 服务网关、部署、限流、模型版本和参数可能同时变化，不先做排行 |
| 不同部署/平台/网关的对比 | **延后** | 需要拆分接入、平台和模型因素；首版不做归因实验 |
| 历史结果自动趋势和排名 | **延后** | 数据生命周期、版本迁移和可比条件尚未作为首版功能确认 |

首版因此只交付两件事：每次检测结果绑定完整对象和条件；在当前记录内展示 #20 官方参考结构对比。其他服务和历史结果可以作为明确标注的外部材料或人工对照，不进入默认总览、排名或总体结论。

## 2. 检测记录身份

每条记录必须绑定以下身份字段，缺失时不能称为同条件结果：

| 字段组 | 必填字段 |
| --- | --- |
| 服务归属 | endpoint 稳定标识、服务/网关名称（若用户提供）、model 原样值 |
| 接入条件 | protocol、认证方式类别、客户端版本、代理/网关标识 |
| 运行环境 | 操作系统、运行版本、时区、测试时间、执行器版本 |
| 规则版本 | 规格/能力/性能/Agent/基线设计版本、题库和规则指纹 |
| 测试条件 | 输入输出长度、并发、温度等设置、流式开关、工具/schema |
| 证据归属 | run ID、样本 ID、证据包 ID、脱敏状态、生成时间 |

API Key、完整密钥、客户业务数据和未脱敏敏感字段不进入比较标签。endpoint 可以保存稳定脱敏标识，但必须能在授权环境中区分不同服务归属。

## 3. 可比条件矩阵

### 3.1 结果层级

不同结果只能在同一层级比较：

| 结果层级 | 可比较的最小条件 | 可表达的结果 |
| --- | --- | --- |
| 结构基线 | 同一 BC 版本、同一变体和同一字段匹配规则 | 结构相同/差异/证据不足 |
| 规格实测 | 同一类别、样例、设置和输入档位 | 各自已验证范围和限制 |
| 能力跑分 | 同一题库版本、语言、提示、答案规则和运行设置 | 各自 `C/V`、覆盖和错误类型 |
| 性能实测 | 同一负载矩阵、协议、窗口、计时和计数口径 | 条件化延迟、吞吐和异常 |
| Agent 实测 | 同一 OMP 版本、样本、权限、工具和判定规则 | 条件化任务状态和证据 |

结构差异不能直接与能力分数比较；能力分数不能直接与性能数字相加；Agent 失败不能由其他模块高分抵消。

### 3.2 条件差异和处理

| 差异 | 是否仍可比较 | 必须如何展示 |
| --- | --- | --- |
| 只改变服务/模型，其余条件完全相同 | 有限可比较 | 标明仅观察相关，不归因于裸模型本体 |
| 题库版本不同 | 不可比较成绩 | 可展示各自结果，禁止计算提升幅度 |
| 提示或评分规则不同 | 不可比较成绩 | 标注规则差异，禁止并排排名 |
| 输入/输出长度不同 | 仅同档位比较 | 分档展示，不混合速度或正确率 |
| 并发、窗口或超时不同 | 不可直接比较性能 | 展示各自条件和异常，禁止推导承载能力 |
| OMP/客户端/网关不同 | 需单独分层 | 不把差异直接归因于模型 |
| 同一条件但时间不同 | 可作为复测记录 | 显示运行时间、环境变化和证据缺口 |
| 当前配置与历史配置不一致 | 不可作为当前结果 | 旧结果绑定旧配置，不能覆盖当前结论 |

只有明确标注为“同条件”和具备完整身份、版本、设置与样本指纹，才允许计算有限差异；“看起来相同”不满足条件。

## 4. 同条件复测

首版可以保留同一服务、同一配置和同一规则版本的多次记录，但默认只展示记录并列，不自动生成稳定性趋势或“变好/变差”结论。

同条件复测至少要求：

1. endpoint、model、protocol 和接入配置一致；
2. 题库、样本、提示、schema、工具和规则版本一致；
3. 性能比较时负载、窗口、计时和计数来源一致；
4. Agent 比较时 OMP、权限、工具和工作区策略一致；
5. 客户端、网关、运行环境和测试时间均有记录；
6. 每条差异能回到对应证据包，缺失条件显示为不可比。

满足条件时，客户可以查看“记录 A 与记录 B 的条件化事实差异”。报告不得把差异直接解释成模型升级、退化或根因；根因分析属于后续专项设计。

## 5. 跨服务对比的延后规则

不同服务结果默认只各自展示，不产生总榜、胜负、提升比例或“更适合 Agent”的自动结论。只有未来同时满足以下条件，才可以新增明确的对比功能：

- 题库、提示、语言、答案规则和版本完全一致；
- 服务协议、参数、输出模式和工具 schema 可比；
- 性能负载、超时、窗口、并发和计数来源一致；
- Agent 执行器、工作区、权限和样本一致；
- 结果状态、缺测、异常和证据分母一致；
- 报告措辞明确是接入服务条件下的观察，不是裸模型排名。

不满足任一条件时，可以显示“不可比原因”，不能通过删除异常、换分母或只挑共同成功样本制造可比结果。

## 6. 历史结果与配置切换

历史记录永久绑定生成时的服务、模型、配置、规则、环境和时间。切换当前配置时：

| 场景 | 正确行为 |
| --- | --- |
| 当前配置尚未检测 | 显示“当前配置未检测”，不引用旧结果作当前结论 |
| 旧配置已有报告 | 允许查看旧报告，明显标注旧身份和旧时间 |
| 规则版本升级 | 旧结果保留原规则，不自动迁移为新规则成绩 |
| 题库或样本变化 | 新旧结果分别计分，禁止直接计算变化幅度 |
| 部署/网关变化 | 视为新接入对象，不能覆盖原服务记录 |
| 旧证据缺失或脱敏不足 | 显示不可比/证据不足，不补齐身份字段 |

首版不提供完整历史删除、迁移、批量重算或自动趋势功能；这些属于后续数据生命周期和产品交互设计。

## 7. 客户结果示例

以下文字均为展示示例：

| 情况 | 客户可见表达 | 禁止表达 |
| --- | --- | --- |
| 当前服务与 #20 结构参考比较 | “BC03：`message.content` 路径一致；值差异不计结构问题” | “内容不同，因此模型不兼容” |
| 同配置两次复测 | “同条件记录 A/B：P50 由 0.8 s 变为 1.1 s，环境无变化证据” | “模型性能退化 37.5%” |
| 不同题库版本 | “记录 A 使用题库 v1，记录 B 使用题库 v2，不可直接比较” | “B 比 A 提升 10 分” |
| 当前配置没有结果，旧配置有结果 | “当前配置未检测；可查看旧配置报告” | “沿用旧报告判断当前配置可用” |
| 两个服务只测了不同并发档 | “并发条件不同，结果不可比” | “服务 A 承载力更强” |

官方参考基线优先放在当前记录的结构视图；补充对比不能挤掉当前服务的范围、限制和证据缺口。

## 8. 纸面验收集

| 样例 | 条件 | 预期 |
| --- | --- | --- |
| V01 | 两次结果只改变 `message.content` 值 | 结构相同，不标红 |
| V02 | 两次结果题库版本不同 | 不计算成绩差异，显示不可比 |
| V03 | 两次性能结果输入长度不同 | 分档显示，不合并 P50 |
| V04 | 当前 model 改变但旧报告仍存在 | 旧报告绑定旧 model，当前结论保持未检测 |
| V05 | 两服务协议和题库相同但网关不同 | 可展示条件化事实，不能归因裸模型或排名 |
| V06 | 一次结果缺失环境版本 | 显示证据不足，不补默认环境 |
| V07 | 同条件复测存在 429 限流 | 异常保留，不删除后计算漂亮速度 |
| V08 | 结构字段顺序变化 | 结构相同，不标红 |
