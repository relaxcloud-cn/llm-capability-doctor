# 模型能力跑分：六类题库、验收与计分规则

版本：1.0
整理日期：2026-09-11
关联任务：[#17](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/17)
交接任务：[#26](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/26)

本文冻结首版模型能力跑分的题库形态、评分单位和报告口径。本文不是模型实测结果，不是官方基准成绩，不实现执行器，不运行真实模型。所有示例数字和题目均为设计样例。

## 1. 产品目标与范围

本模块回答“模型在固定任务上的表现强弱和典型错误是什么”，不回答接口是否支持、不回答服务是否整体可用，也不替代智能体实测。

首版固定六类，每类 5 个子方向、每个子方向 8 个基础样本，共 40 个逻辑计分单位。40 是可复核的产品起始题量，不是统计代表性保证；增加或减少题量必须通过题库版本变更。

| 编号 | 能力类别 | 五个子方向 | 题量 |
| --- | --- | --- | --- |
| C01 | 文本理解与指令执行 | 材料事实、条件筛选、单项约束、多项约束、信息不足处理 | 5 x 8 = 40 |
| C02 | 信息提取与结构化填写 | 单对象字段、多对象关系、字段类型、缺失值、冲突信息 | 5 x 8 = 40 |
| C03 | 工具选择与参数填写 | 工具选择、参数填写、参数类型、多个工具、正确不调用 | 5 x 8 = 40 |
| C04 | 多轮对话与条件承接 | 条件保持、条件更新、条件撤销、对象切换、历史区分 | 5 x 8 = 40 |
| C05 | 长材料理解与信息利用 | 定位、跨段关联、干扰排除、长度变化、材料内计算 | 5 x 8 = 40 |
| C06 | 逻辑推理与计算 | 条件判断、时间顺序、数量比较、基础计算、多条件推导 | 5 x 8 = 40 |

不加入编程、专业知识榜单、文学质量、通用排行榜、总分、服务可用性门槛或性能指标。题目不要求模型公开隐藏思维链；只验收题目声明的最终答案和可观察约束。

## 2. 与其他模块的边界

| 主题 | #16 模型规格实测 | #17 模型能力跑分 |
| --- | --- | --- |
| 工具 | 给定工具和参数，检查能否生成非流式调用 | 从任务中选工具、填参数，并识别正确不调用 |
| 结构化输出 | 检查 JSON 和 schema 是否可生成 | 检查结构中业务字段是否正确 |
| 多轮 | 检查角色、历史消息和最小续答 | 检查更新、撤销、对象切换后的任务结果 |
| 上下文 | 测量输入容量和边界证据 | 只在已有可靠输入范围内比较长材料任务 |

同一请求的证据可以被多个模块引用，但同一个错误不能因为展示在两个模块而重复计入总体事故。#16 的 `unsupported`、`inconclusive` 或未验证前提不得被 #17 偷换成另一种接口模式继续答题。

## 3. 题库身份与候选基准

### 3.1 题库身份

每个样本必须标记以下身份之一：

| 身份 | 报告称谓 | 必须记录 |
| --- | --- | --- |
| 原版 | 仅当完整遵守来源版本、数据、提示和评分器时使用“原版” | 来源提交/版本、样本 ID、提示、评分器和使用条件 |
| 抽样或改编 | “中文改编”“受某基准启发的子集”等 | 源题 ID、改动、新题 ID、题库版本和评分变化 |
| 原创 | 产品自有题库名称和版本 | 材料、题目、答案、规则和修订历史 |

首版采用“研究方法参考 + 产品原创/明确改编题库”的组合，不声称官方完整基准分数，不把外部数据或代码未经核对直接打包进产品。外部候选的许可证、数据版本和执行条件单独归档，未核对的候选不能进入正式题库。

### 3.2 候选方法的采用边界

| 候选 | 可借鉴的方向 | 首版处理 | 不得作出的结论 |
| --- | --- | --- | --- |
| IFEval | 可验证指令、逐约束检查、严格/宽松口径分离 | 参考约束设计；中文改写后使用产品题库名 | 不报完整 IFEval 成绩或排名 |
| Schema-Guided Dialogue | schema、状态和多轮条件组织 | 参考对话状态样例；只保留产品需要的受控任务 | 不把领域对话覆盖当作通用能力 |
| BFCL | 工具选择、参数和正确不调用 | 参考工具任务结构；与 #16 的工具规格检查分开 | 不把工具生成通过当作 Agent 成功 |
| Multi-IF | 多轮指令和条件承接 | 参考多轮变化类型；固定为产品自己的脚本 | 不混合不同语言和版本的官方分母 |
| RULER | 合成长材料、定位和干扰控制 | 参考长度变量和材料构造；不做上下文容量探测 | 不把改编分数当 RULER 原版成绩 |
| BBH / DROP | 逻辑、计算和材料内推导 | 参考题型；优先原创确定答案题 | 不引入编程、专业知识或隐藏推理评分 |

每份正式题库都要写明“原版、抽样/改编或原创”。只要翻译、改提示、改答案规则、换材料、改变样本集合或评分器，就不能继续使用原版完整成绩名称。

## 4. 统一题目数据结构

每个逻辑计分单位至少包含：

| 字段 | 内容 |
| --- | --- |
| `id` | 稳定题目 ID，修订后保留旧 ID 和新版本关系 |
| `category` / `subdomain` | 六类编号和五个子方向 |
| `dataset_identity` | 原版、抽样/改编或原创 |
| `source_ref` | 来源版本、源题 ID 或原创材料记录 |
| `language` | 首版主测中文；英文样本不得混入中文分母 |
| `prompt` | 完整输入，包括材料、要求和输出约束 |
| `expected` | 参考答案、必须事实、允许别名和容差 |
| `acceptance` | 可执行评分规则及禁止的宽松解释 |
| `generation_settings` | 模型、接口、temperature、输出格式等 |
| `revision` | 题库版本、规则版本和题目指纹 |

首版语言规则为中文优先：六类主成绩使用中文题库，英文或双语扩展单独建题库、单独报告分母，不与中文题混成一个百分比。中文改编题不能冠以外部英文题库的完整原版成绩。

## 5. 六类题库设计

### 5.1 文本理解与指令执行

每个子方向 8 题，覆盖材料事实、条件筛选、单项输出、多项同时满足和信息不足处理。题目预先写明必须事实、禁止内容、列表数量、顺序和空值处理。

主结果要求内容答案正确且全部必需约束满足。格式不重要的题允许等义表达；明确要求 JSON、列表或字段的题按对应约束验收。

### 5.2 信息提取与结构化填写

每个子方向 8 题，材料中至少包含可区分的对象、属性和关系。样本覆盖字段缺失、对象同名、冲突值、类型要求和不得编造。

评分同时核对字段名、对象归属、值、类型和缺失处理。模型明确声明“材料未提供”在题目允许时算正确；自行补造未给信息为有效错误。

### 5.3 工具选择与参数填写

每个子方向 8 题，给出 2-4 个工具及完整 schema。任务包括应调用的工具、正确参数、多个工具关系和明确不应调用工具的场景。

本类验收的是任务决策，不是 #16 的接口结构：工具名称、调用数量、参数和值必须与题目要求一致；题目要求不调用时，普通回答或明确澄清均可按预设规则通过。工具不执行、不回传结果，不要求续答。

### 5.4 多轮对话与条件承接

每个子方向 8 段完整对话，每段 3-5 轮。每段只设置一个主要变化，并在脚本中明确当前有效条件、被撤销条件、对象和目标答案。

整段主结果要求所有要求的回合均正确。某一回合出现有效错误后，整段记为有效错误；后续连接异常不删除已确认错误。仅有执行异常且没有有效错误时，整段记为未完成。

### 5.5 长材料理解与信息利用

每个子方向 8 个逻辑任务，每个任务可有短、中、长三个长度变体。长度变体用于观察变化，不自动增加独立题量；报告按长度分别展示，同一基础任务的变体关系必须保留。

材料长度只能使用 #16 已取得可靠证据的范围。若某长度超出已验证输入范围，标为未覆盖，不发送请求，也不补 0 分。题目答案必须只依赖材料本身，不要求联网或现实常识。

### 5.6 逻辑推理与计算

每个子方向 8 题，固定事实、规则、单位、时间基准、精度和舍入方式。答案优先使用确定性规则，数值题允许题目预先声明的容差，排序和集合题允许预先声明的等价表达。

不要求隐藏推理过程。题目只有在明确要求可观察中间结果时，才检查该结果；文字长短、解释风格和未要求的步骤不影响得分。

### 5.7 固定提示模板

正式题库中的每条 prompt 都必须由下表对应模板生成，并把材料、约束、答案和评分规则固化到题目文件。模板只是结构，不代表可以在运行时临时改写题意。

| 类别 | 固定 prompt 结构 | 输出约束 |
| --- | --- | --- |
| C01 | `材料：{facts}\n任务：{requirements}\n只回答任务，不补充材料外事实。` | 按题目声明的事实点、约束和信息不足规则评分 |
| C02 | `材料：{records}\n请按字段表填写：{schema}\n缺失字段写“未提供”。` | 字段、对象、类型、值和缺失处理必须全部可核验 |
| C03 | `任务：{task}\n可用工具：{tool_schemas}\n请给出工具决策和参数；题目要求不调用时明确说明。` | 工具名、调用数量、参数和值或正确不调用均需符合题目规则 |
| C04 | `对话历史：{turns}\n当前请求：{latest}\n只依据当前有效条件回答。` | 每一轮的保持、更新、撤销和对象关系按脚本评分 |
| C05 | `材料（长度档位 {length}）：{document}\n问题：{question}` | 只能依据材料回答；未覆盖长度不执行、不计分 |
| C06 | `已知事实：{facts}\n规则：{rules}\n问题：{question}\n给出最终答案和单位。` | 数值、单位、精度、顺序和信息不足处理按题目固定规则评分 |

所有模板使用中文主测题库、temperature 0、固定模型和固定接口；题目文件额外记录允许答案、禁止答案、容差、样本身份和版本。模板、材料或评分规则任何一项变更都会产生新的题库版本。

## 6. 执行设置与重复规则

### 6.1 首版固定执行

每个逻辑计分单位初测 1 次，不从多次回答中挑选最好结果。默认使用 temperature 0；若服务不接受该设置，记录实际设置，不把设置异常改写成答题错误。

执行异常（超时、连接断开、限流、认证或网关错误）最多追加 2 次，仍没有有效响应则记为未完成。取得有效响应后直接评分，不通过重试洗掉有效错误。

执行器必须固定题库版本、提示、设置、模型标识和环境；禁止在运行中临时换题、改答案、调宽松阈值或改变语言分母。

### 6.2 有效、无效和缺测

| 情况 | 处理 |
| --- | --- |
| 有效回答且满足全部规则 | 记 `C`（correct） |
| 有效回答且违反规则 | 记 `W`（wrong） |
| 有效回答但规则无法确定，或题目存在待裁决歧义 | 记 `Q`（pending） |
| 执行异常没有有效回答 | 记 `I`（incomplete） |
| 未执行、前提不满足或不适用 | 记 `M`（missing/not measured） |

`W` 不因后续中断消失；`I` 和 `M` 不冒充错误；`Q` 不冒充正确。题目缺陷要保留原证据、建立修订关系，并使用同一修订规则重新计算受影响样本。

## 7. 计分与汇总

对每个类别和子方向分别记录：

- `N`：计划逻辑计分单位数；
- `C`：正确单位数；
- `W`：有效错误单位数；
- `Q`：已有回答但规则暂不能裁决的单位数；
- `I`：执行异常导致未完成的单位数；
- `M`：未执行或前提不满足的单位数；
- `V = C + W`：已评分有效单位数；
- `coverage = V / N`：有效评分覆盖率；
- `score = C / V`：仅在 `V > 0` 时展示的已评分正确率。

每个单位只能进入 C、W、Q、I、M 之一，因此 `N = C + W + Q + I + M`。如果 `V = 0`，显示“无有效成绩”，不显示 0% 或 100%。

客户主视图展示 `C/V`、`V/N`、典型错误和条件。六类只分别展示，不计算加权总分、不设六类总分线、不用分类成绩抵消 Agent 阻断或规格失败。

### 7.1 手工核算样例

五个逻辑单位的结果为：C、C、C、W、I。则 `N=5`、`C=3`、`W=1`、`I=1`、`V=4`，报告显示“正确 3/4，已评分 4/5，1 项未完成”。不能显示成“正确 3/5”或把未完成样本当作错误。

四段多轮对话中，一段全对、两段出现有效错误、另一段尚无有效错误但执行异常，则 `C=1`、`W=2`、`I=1`，主结果为 `1/3`，覆盖为 `3/4`。

### 7.2 五类评分校验样例

下表是评分器必须能够复现的最小校验集。样例中的类别和题目内容是说明材料，不是正式 240 题题库。

| 样例 | 模型输出/执行事实 | 预期分类 | 计分原因 |
| --- | --- | --- | --- |
| 正确 | 题目要求“列出预算超过 4 万的项目”；回答“B；负责人未提供。” | `C` | 内容、筛选条件和信息不足处理均满足 |
| 错误 | 同一题回答“A、B；负责人李某。” | `W` | 错误筛选并编造材料外事实 |
| 合法替代 | 题目要求 25 x 3 - 10；回答“人民币六十五元” | `C` | 数值和单位等义表达在允许答案集合内 |
| 缺少信息 | 题目要求从材料读取负责人，但材料没有负责人；回答“无法从材料确定负责人。” | `C` 或 `Q` | 题目若预先允许声明缺失则为 C，否则规则不足时为 Q，不得临时判错 |
| 无效执行 | 请求超时，未取得任何有效回答 | `I` | 执行异常单列，不进入有效错误分母 |

另外，题目本身无唯一答案、评分规则未覆盖合法表达或裁决资料缺失时记 `Q`；未执行或前提不满足时记 `M`。这些状态都必须在报告中保留原因和证据。

## 8. 等义答案、语义评分与裁决

优先使用可执行规则：标准化大小写和空白、已列别名、数值容差、集合/顺序规则、字段类型和必需事实。规则未覆盖的表达不直接判错；如果无法可靠裁决，记 `Q` 并记录待补规则。

对于归纳类题目，预先定义必要事实点、禁止事实和信息不足处理。参考答案逐字不同不等于错误；“另一模型认为正确”也不是充分裁决证据。首版不指定裁判模型，不因裁判方便而删除难判样本。

## 9. 客户成绩单示例

以下数字均为虚构：

| 类别 | 主结果 | 覆盖和限制 | 典型错误 |
| --- | --- | --- | --- |
| 信息提取 | 正确 31/40 | 已评分 40/40 | 对象串值、缺失字段编造 |
| 工具选择 | 正确 27/35 | 已评分 35/40；待评分 2、未完成 2、未执行 1 | 错工具、参数遗漏、错误调用 |
| 多轮条件 | 连续全对 28/40 段 | 逐轮偏离另列 | 更新条件未覆盖旧条件 |
| 长材料 | 4K 与 16K 分开列出 | 64K 未覆盖，不补 0 分 | 干扰段落、跨段关系遗漏 |

详情页必须能追溯到题库版本、题目、配置、原始回答、评分规则和证据引用。改编、翻译、抽样和原创题库不得与原版榜单混排。

| AC | 检查动作 | 文档落点 | 通过证据 |
| --- | --- | --- | --- |
| AC-01 | 核对六类、候选采用边界和题库身份 | 第 1、3、5 节 | 每类有 40 个逻辑单位和明确选用理由 |
| AC-02 | 输入同义答案、等效工具和正确不调用 | 第 5、8 节 | 依据预先答案集合/规则验收，不机械逐字比较 |

独立复核记录格式固定为：

```text
AC 编号 -> 材料及版本 -> 检查方法或运行命令 -> 预期与实际
-> 证据位置 -> 验证结果 -> 修订提交
```

本 PR 的文档自检不等于真实题库执行或评分器验收。交接给 #26 的内容是：六类题库字段、题目身份、固定运行设置、评分单位、缺测状态、聚合公式和客户展示字段。
