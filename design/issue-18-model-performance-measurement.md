# 模型性能实测：五类负载与计量口径

版本：1.0
整理日期：2026-09-11
关联任务：[#18](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/18)
交接任务：[#27](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/27)

本文冻结首版性能实测的指标、负载、窗口、异常和展示口径。本文不实现压测器，不请求客户模型，不声称任何服务已经达到性能标准。所有示例数字均为设计示例。

## 1. 目标与五类范围

本模块回答“在明确条件下，服务等待多久、输出多快、有限并发如何变化、短时连续运行发生什么、长度变化带来什么影响”。结果必须带实际负载、长度、时间窗口、样本数和异常数量。

首版固定五类：

| 编号 | 类别 | 客户问题 | 首版范围 |
| --- | --- | --- | --- |
| P01 | 响应等待 | 多久开始看到正文，多久完整结束 | 流式正文首响、流式完整耗时、非流式完整耗时 |
| P02 | 生成速度与流畅度 | 正文输出有多快，中间停顿多久 | 内容块间隔、正文速率、最大停顿 |
| P03 | 并发承载 | 并发增加时速度、完成量和异常如何变化 | 并发 1/2/4/8 的有限阶梯 |
| P04 | 连续运行稳定性 | 固定短时窗口内是否变慢或错误增多 | 并发 2、最多 600 秒或 1,200 次请求 |
| P05 | 长输入与长输出性能 | 输入、输出和历史变长时性能如何变化 | 长材料、有限长输出、历史消息与等长度平铺对照 |

不测最大上下文、最大输出、最大用户数、费用、缓存差异、硬件占用、突发恢复、业务答案质量、Agent 闭环或性能总分。流式工具调用功能归 #16/#40；本模块默认只测文本生成。

## 2. 与其他模块的边界

| 主题 | 本模块处理 | 不得替代 |
| --- | --- | --- |
| 输入长度 | 在 #16 已验证范围内选择有限档位 | 不重新探测上下文容量 |
| 输出长度 | 预先指定目标长度并记录实际长度 | 不寻找最大输出或替代 #16 输出长度规格 |
| 响应质量 | 记录非空、协议完整和长度达标 | 不替代 #17 能力评分 |
| 工具/Agent | 默认不执行工具、不回传、不续答 | 不替代 #19 Agent 实测 |
| 可用性 | 展示性能事实和异常 | 不根据无业务门槛的数字自动判“可用/不可用” |

同一请求被多个模块引用时复用证据 ID，不重复统计为独立请求或独立事故。性能数据的归因只能写成当前服务、当前配置和当前环境下的观察。

## 3. 统一指标字典

### 3.1 时间线

客户端在向 HTTP 客户端交付请求、开始发送前记录 `t_send`；不包含调度器等待。每条请求至少记录以下事件：

| 事件 | 定义 | 是否进入主指标 |
| --- | --- | --- |
| `t_first_event` | 收到第一个可解析协议事件，可能为空 | 仅详情 |
| `t_first_reasoning` | 首个可识别推理片段（若协议可区分） | 仅详情 |
| `t_first_visible` | 首个非空白、用户可见正文内容 | 流式正文首响 |
| `t_complete` | 收到正常结束证据并消费完响应 | 流式/非流式完整耗时 |
| `t_error` | 收到明确错误或连接以错误终止 | 异常时间，不进入成功分布 |
| `t_cancel` | 客户端主动停止或保护停止 | 取消时间，单列 |

流式正文首响为 `t_first_visible - t_send`。空事件、角色事件、纯推理片段不能提前结束首响等待。非流式没有可观察的正文首响，只记录完整耗时。

完整耗时为 `t_complete - t_send`，必须有正常结束证据；错误、超时、截断和取消保留耗时但不混入正常完成分布。

### 3.2 长度和速率

优先使用服务返回的 usage token；否则记录可复现的客户端计数来源。没有可靠 token 计数时可以展示字符速率和内容块间隔，但不得伪造 `tokens/s`。

| 指标 | 公式或规则 | 样本要求 |
| --- | --- | --- |
| 正文首响 | `t_first_visible - t_send` | 必须出现非空正文 |
| 完整耗时 | `t_complete - t_send` | 必须正常结束 |
| 内容块间隔 | 相邻用户可见正文事件时间差 | 只用正文事件，不把空事件当正文 |
| 正文速率 | 可核实正文 token / 正文生成时间 | token 计数不可核实时不展示 |
| 最大停顿 | 同一响应中正文事件的最大间隔 | 至少有两个正文事件 |
| 单请求吞吐 | 完整请求数 / 测量窗口秒数 | 只计窗口内正常完成 |
| 最终完成比例 | 到终态的完整请求数 / 已派发请求数 | 排空阶段补齐终态 |

百分位只在有效样本数和样本集合可见时展示。P50/P95 不能把错误、超时或取消偷偷过滤成“成功速度”；成功分布和全请求状态必须同时展示。

### 3.3 聚合和条件

每个结果至少带：模式、输入长度、目标输出、实际输入/输出、并发、预热次数、正式次数、窗口、计时来源、正常完成数、错误数、超时数、取消数和长度未达标数。

不同长度、并发、协议、模型、客户端或时间窗口不合并为一条速度线。没有客户明确的响应时限、吞吐要求或稳定性 SLA 时，不自动产生合格线。

## 4. 五类固定负载矩阵

下表冻结首版设计数值。它们是产品执行上限，不是官方推荐、客户授权或性能通过线。单请求总超时为 120 秒；性能请求默认不自动重试。

| 类别 | 输入/目标输出 | 并发 | 预热 | 正式测量 |
| --- | --- | --- | --- | --- |
| 响应等待 | 512 / 256 tokens | 1 | 流式、非流式各 3 次 | 两种模式各 40 次，单模式最多 80 分钟 |
| 速度与流畅度 | 512 / 1,024 tokens | 1 | 3 次 | 流式 40 次，最多 80 分钟 |
| 并发承载 | 512 / 256 tokens | 1、2、4、8 逐档 | 每档一轮并发预热 | 每档派发最多 120 秒或 300 次，之后最多排空 120 秒 |
| 连续运行 | 512 / 256 tokens | 2 | 2 次 | 派发最多 600 秒或 1,200 次，之后最多排空 120 秒 |
| 长材料 | 2,048、8,192、32,768 / 256 tokens | 1 | 每档 3 次 | 每档 15 次，最多 30 分钟 |
| 长输出 | 512 / 1,024、2,048 tokens | 1 | 每档 3 次 | 每档 15 次，最多 30 分钟 |
| 历史增长 | 4、16、32 条交替消息，每条约 128 tokens / 256 tokens | 1 | 每档每种形态 3 次 | 历史组和平铺对照各 15 次，最多 30 分钟 |

P05 的三组长度观察是一个五类中的子矩阵，不新增第六类。长材料档必须位于 #16 已验证输入范围内；无法核实的档位跳过并记为前提不足，不用更短档位冒充该档。

## 5. 调度、预热与窗口

预热请求与正式请求分开记录，不进入正式分母。预热失败保留，不用成功预热覆盖。并发采用闭环调度：在途请求达到目标并发后，结束一个才补一个；记录实际并发曲线和客户端调度空隙，不承诺固定请求率。

每个并发档按 1、2、4、8 顺序执行，档间空闲 10 秒并记录顺序。派发窗口到达时间或请求数上限即关闭；之后只保留排空阶段，不把排空完成请求回填到窗口吞吐。

窗口吞吐按正常完成事件发生在派发窗口内计算；最终完成比例按已派发请求追踪到排空或取消后的终态计算。两套分母在报告中分开，窗口末尾的慢请求不能被删除。

连续运行每 60 秒生成一个时间桶。按派发时间桶展示请求最终状态和延迟，按完成时间展示吞吐；首尾趋势只有在两个完整桶各至少 10 个有效请求时才计算相对变化，否则只展示原值和样本数。

## 6. 异常与保护停止

性能请求不自动重试；需要复测时创建新的轮次，保留原轮次全部证据。权限、限流、客户端故障和服务错误分别归因。

| 触发 | 动作 | 统计表达 |
| --- | --- | --- |
| 单请求超时、5xx、异常断流 | 记录终态；未触发保护时按闭环补位 | 异常数量增加，不进入正常完成速度分布 |
| 401/403 或权限明确失效 | 停止当前服务后续派发 | 接入阻断，不归因为速度问题 |
| 429 限流 | 关闭当前档，排空在途，不自动升档 | 记录限流，不推导最大并发 |
| 连续 5 次服务/网络失败，或终态异常比例达到 20% 且已有至少 20 个终态 | 保护停止当前档 | 阈值是保护条件，不是通过线 |
| 用户停止、客户端故障、证据写入失败 | 停止派发，保留已取得事实 | 实际观察不足，不写成完成测试 |

保护停止后不自动执行更高并发档或连续运行组。不同失败原因不能混成一个“模型变慢”结论。

## 7. 长度和异常的双层展示

完整返回不等于达到目标长度，更不等于业务答案正确。每条请求同时记录：协议终态、实际长度、目标档是否达标、异常类型和是否进入指标分母。

如果 40 次中只有 4 次达到目标输出长度，报告必须显示“长度覆盖不足”和 `4/40`，不能只展示这 4 次的速度。自然结束的短答保留在全请求视图，不能悄悄删除或当作快速成功。

## 8. 客户结果示例

以下数字是虚构的设计示例：

| 结果 | 示例展示 | 必须同时显示 |
| --- | --- | --- |
| 响应等待 | 正文首响 P50 0.8 s；完整耗时 P50 5.2 s | 流式、单并发、512/256、正常 38/40、超时 2 |
| 生成流畅度 | 正文块间隔 P95 90 ms；最大停顿 1.4 s | 正文事件数、token 计数来源和缺失计数 |
| 并发承载 | 并发 4 窗口吞吐 0.8 请求/s | 实际并发、窗口时长、超时 3、限流 2 |
| 连续运行 | 观察 10 分钟，完整 186/190 | 并发 2、每分钟桶、异常和是否提前停止 |
| 长输出 | 目标 2,048，实际中位数 1,610，达标 4/15 | 长度覆盖不足，不称为 2,048-token 稳定性能 |

主视图采用“数值 + 条件 + 异常”；没有用户要求时不显示“合格/不合格”。详情可展开完整时间线、原始响应、实际长度、请求 ID 和证据引用。

## 9. 设计反例

| 观察 | 正确表达 | 错误表达 |
| --- | --- | --- |
| 先空事件、推理片段，1.2 秒后出现正文 | 正文首响 1.2 秒；前两事件仅详情 | 首事件即首响 |
| 40 次中 2 次超时，38 次正常 | 成功延迟分母 38，全请求分母 40 | 删除超时后称 40 次稳定 |
| 一个内容块包含多个 token | 记录块间隔；仅在计数可靠时算 token 速率 | 一个块等于一个 token |
| 窗口内完成 90 个，排空再完成 10 个 | 窗口吞吐 90/窗口秒数，排空完成另列 | 把排空 10 个回填吞吐 |
| 目标 2,048，实际自然结束 100 | 完整返回但长度未达标 | 当作 2,048-token 快速成功 |
| 600 秒计划在 120 秒被限流停止 | 观察 120 秒，记录限流和未完成计划 | 写成十分钟稳定通过 |
| 客户端只维持实际并发 3 | 标记目标 8、实际 3，结果不可作并发 8 成绩 | 报告“已验证并发 8” |
