# Issue #50：长输入与长输出性能设计

版本：`performance-length-variation/v1`  
父任务：[#18](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/18)  
上下文边界：[#38](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/38)  
实现交接：[#27](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/27)

本文分别观察材料输入、输出目标和历史消息变长后的首响、完整耗时、正文速率、停顿和异常。它不测长材料理解（#43），不重新探测最大上下文（#38），不搜索最长输出，也不恢复已撤销的 P01 输出参数专项。

## 1. 统一固定条件

全部配置使用流式、单并发、`temperature=0`、同一模型和服务。每个配置预热 3 次，正式请求不自动重试，单请求超时 120 秒，每个配置正式组最长 30 分钟。相同已执行条件可以关联已有证据，但不重复计为新增样本。

输出目标档只表示有限任务，不是最大输出声明。达到目标的 80%-120% 才进入对应目标长度性能视图；自然结束的短答仍保留在完整请求视图。

## 2. 三组矩阵

### 2.1 长材料组

输入目标为 2,048、8,192、32,768 token，目标输出固定 256 token，每档 15 次正式请求。材料由固定头部、可重复中性段落和尾部校验标记构成；材料哈希、参考计数、服务实际 `usage.prompt_tokens` 和输出预留必须保存。

档位只有在 #38 已取得可靠输入接受证据时才执行。无法确认的档位标记前提不足，不降档后再把结果写成原档位。

### 2.2 长输出组

输入固定约 512 token，目标输出为 1,024、2,048 token，每档 15 次正式请求。提示词只要求输出固定、可计数的受控内容，避免业务推理差异。记录目标长度、实际正文长度、首响、完整耗时、正文速率、块间隔、短答和截断。

实际输出 100 token 不得被写成 1,024-token 目标档性能；同时不能因目标未达到就删除该请求或自动判性能失败。

### 2.3 历史长度组

当前问题、材料和目标保持一致，历史组使用 4、16、32 条交替 user/assistant 消息，每条约 128 token；每档历史组和等总输入长度平铺组各 15 次。两组必须匹配总输入计数、当前问题、材料哈希、输出目标和封装开销。

历史消息只是同一请求的消息组织，不是 Agent 连续执行或跨请求记忆。总长度无法匹配时标记不可比，不把差异归因于历史结构。

## 3. 指标和可比性

每个请求至少记录：输入参考/实际 token、消息条数和封装开销、目标/实际输出长度、正文首响、完整耗时、正文字符/token 速率（按 #49 规则）、块间隔、终态、错误、超时、截断、取消和证据。

结果按长度档独立展示：首响、完整耗时、正文速率、间隔、异常、目标长度入组数和未入组数。不同输入长度的耗时增加本身不等于性能失败；长输出总耗时增加但单位正文速率稳定时，应展示长度影响而非直接标退化。

历史组和平铺组只有在总输入量、内容难度、当前问题、输出目标和其他设置可比时才计算差异；否则只报告各自原值和不可比原因。

## 4. 停止和异常

达到已验证输入范围上限、请求体/代理限制、配置时间上限或全部可用档位后停止。认证、限流、网络、超时、网关拒绝、客户端截断和服务自然短答分别记录；不自动重试，不把环境异常写成模型性能失败。

单请求结果不能作为该长度档的代表性结论。档位覆盖不足时显示样本数和限制，不用成功子集掩盖未完成请求。

## 5. 反例

| 观察 | 正确表达 |
| --- | --- |
| 32K 未被 #38 可靠验证 | 该档不执行，不能降到 8K 后冒充 32K |
| 目标 2,048，实际 100 token | 保留短答，排除目标长度视图，不删除请求 |
| 长输出总耗时更长、单位速率相同 | 说明长度影响，不自动判性能退化 |
| 历史组比平铺组多 30% 输入 | 标记不可比，不归因消息组织 |
| 代理按字节拒绝长请求 | 环境限制，不归因上下文或性能 |

## 6. 受控验收案例

| 案例 | 条件 | 预期 |
| --- | --- | --- |
| LEN-01 | 2K/8K 在已验证范围内 | 各档 15 次，指标和实际计数可重算 |
| LEN-02 | 32K 超出可靠范围 | 不执行该档，保留前提缺口 |
| LEN-03 | 长输出短于目标 | 正常短答单列，不进入目标长度性能视图 |
| LEN-04 | 长输出总耗时上升但字符速率稳定 | 展示长度影响，不生成退化结论 |
| LEN-05 | 历史/平铺总输入匹配 | 可比较消息组织差异 |
| LEN-06 | 历史/平铺总输入不匹配 | 不比较，不归因历史结构 |
| LEN-07 | 超时、限流、网关限制或客户端截断 | 保留异常，不当作模型性能失败 |

## 7. 证据结构

每组保存固定配置、长度档、材料/消息哈希、参考与服务 token 计数、封装开销、输出预留、目标/实际长度、时间线、事件序列、终态、异常原因、入组状态、组间可比性和原始脱敏证据。聚合指标必须能从单请求记录重算；API key 不进入证据。

## 8. 验收标准

| AC | 检查 | 预期 |
| --- | --- | --- |
| AC-01 | 三组矩阵和数量 | 长材料 3 档、长输出 2 档、历史 3 档加平铺对照，各档 15 次 |
| AC-02 | #38 前提交接 | 未确认输入档位不执行、不降档冒充、不改写容量结论 |
| AC-03 | 输出长度入组 | 目标 80%-120% 进入目标视图，短答保留且不隐性删除 |
| AC-04 | 历史/平铺可比性 | 总输入、内容、问题、输出目标和封装开销匹配后才比较 |
| AC-05 | LEN-03/LEN-04/LEN-07 | 长度影响、短答、异常和截断不被包装成性能失败或成功 |
| AC-06 | 证据重算 | 首响、完整耗时、速率、间隔、入组和限制可追溯、可重算 |
| AC-07 | 范围审查 | 不重复容量探测、不测理解质量、不搜索最大输出、不恢复 P01 |

本设计只形成 #18 的长度变化输入，不代表执行器已实现，也不代表任何真实服务已经完成这些档位的测量。
