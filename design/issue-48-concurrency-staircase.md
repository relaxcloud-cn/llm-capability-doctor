# Issue #48：并发承载有限阶梯设计

版本：`performance-concurrency-staircase/v1`  
父任务：[#18](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/18)  
实现交接：[#27](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/27)

本文回答“同时处理多个请求时，等待、输出速度、完成量和异常如何变化”。只执行预设阶梯，不搜索最大承载量、不换算最大用户数、不增加突发、恢复或开放速率测试。

## 1. 固定条件

| 条件 | 固定值 |
| --- | --- |
| 输入 | 约 512 token 受控短文本 |
| 目标输出 | 256 token |
| 响应模式 | 流式；各请求使用相同配置 |
| 并发阶梯 | 1、2、4、8，按低到高顺序 |
| 预热 | 每档 1 轮，等待该轮结束，不计正式指标 |
| 档间空闲 | 10 秒 |
| 正式派发窗 | 每档最多 120 秒或 300 次实际请求，先到为止 |
| 单请求超时 | 120 秒 |
| 排空窗 | 派发截止后最多 120 秒 |

并发表示同时在途请求数，不是用户数。采用闭环补位：一个请求正常结束后才为同一档补入下一个请求，不承诺固定请求/秒；保存实际并发曲线、调度空隙和请求生命周期。

## 2. 派发、终态与吞吐

每个请求保存目标并发、实际并发、派发时间、首响时间、完整时间、终态、错误、输出长度、请求模式和证据引用。

- 目标并发与实际并发分别展示；客户端无法维持目标值时标记“负载不足”，不报告该档已验证。
- 窗口吞吐只统计派发窗口内正常结束的请求，分母为窗口时长；异常、超时和未完成请求不计入成功吞吐。
- 派发截止后在排空窗口完成的请求单列，只用于补齐该批次最终完成比例，不回填原窗口吞吐分子。
- 排空结束仍在途的请求分别记录为超时、取消或未完成，不从派发队列分母删除。

## 3. 每档展示

每档至少展示：目标/实际并发、正式派发数、正常完成数、排空完成数、超时/错误/取消数、完整比例、窗口吞吐、正文首响、完整耗时、单请求速率、输出长度和调度空隙。

单请求体验指标从正常完整请求计算；窗口吞吐与完整比例分开，不用成功子集隐藏异常。高并发下输出变短时，同时显示目标达标比例和实际长度，不能用短答制造高吞吐结论。

## 4. 保护与升档

性能请求不自动重试。出现 429、认证失效或共用保护条件时，停止当前档并停止自动升档；保存已派发请求、在途请求和异常证据。保护阈值是停止条件，不是性能通过线，也不能推出“模型最大并发”。

达到请求数上限时记录实际窗口；提前停止时记录停止事件和未执行档位。任何缺失首响、完整结束或实际并发证据的档位只能标记 `inconclusive`。

## 5. 结果边界

| 观察 | 正确表达 |
| --- | --- |
| 配置并发 8，实际只能维持 3 | 负载不足；不报告已验证并发 8 |
| 并发 4 遇到限流 | 记录限流和升档停止；不称最大并发为 4 |
| 窗口后完成 10 个请求 | 作为排空结果单列，不抬高窗口吞吐 |
| 高并发输出变短 | 展示长度短缺和完整比例，不能直接归因服务退化 |
| 所有档位完成无异常 | 只说明该固定窗口内未观察到异常，不代表生产容量或 SLA |

## 6. 受控验收案例

| 案例 | 条件 | 预期 |
| --- | --- | --- |
| CONC-01 | 四档均维持目标并发 | 每档独立记录体验、吞吐、完成比例和证据 |
| CONC-02 | 8 档实际并发只有 3 | 标记负载不足，不写已测并发 8 |
| CONC-03 | 4 档收到 429 | 停止该档和升档，不自动重试，保留异常 |
| CONC-04 | 派发截止后仍有请求完成 | 排空单列，不回填窗口吞吐 |
| CONC-05 | 高并发输出低于目标 | 记录长度短缺，不用短输出提高吞吐解释 |
| CONC-06 | 客户端调度存在空隙 | 保存实际并发曲线，不假设目标并发持续成立 |
| CONC-07 | 单请求超时和取消 | 分别记录终态，不从派发分母删除 |

## 7. 证据结构

每档和每请求保存固定配置指纹、目标/实际并发轨迹、派发/首响/完整/错误/取消时间、窗口和排空边界、响应事件、输出长度、终态、保护停止原因和原始脱敏证据。聚合指标必须能从请求记录重算；API key 不进入证据。

## 8. 验收标准

| AC | 检查 | 预期 |
| --- | --- | --- |
| AC-01 | 固定条件和阶梯 | 仅使用 1/2/4/8 四档，参数、预热、空闲和窗口明确 |
| AC-02 | 实际并发与闭环补位 | 目标并发、实际并发、调度空隙可区分，负载不足不冒充覆盖 |
| AC-03 | 吞吐和排空 | 窗口吞吐与排空完成分开，异常请求不计成功吞吐但不删除 |
| AC-04 | 保护停止 | 429、认证失效和共享保护停止当前档及升档，不自动重试 |
| AC-05 | CONC-04/05/07 | 排空、长度短缺、超时和取消不被夸大或隐藏 |
| AC-06 | 范围审查 | 最高档只叫最高已测并发，不推导极限、用户数或 SLA |
| AC-07 | 证据重算 | 每档聚合可由单请求生命周期和事件重算 |

本设计只形成 #18 的有限并发输入，不代表执行器已实现，也不授权对客户服务施加未经确认的负载。
