# Issue #37：常用参数支持测试设计

版本：`specification-common-parameters/v1`  
关联：[#16](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/16)  
交接：[#25](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/25)

本文冻结首版 P02-P06 的受控输入、对照、判定和证据要求。P01、P07-P13 不属于本设计；请求成功只证明接口接受，只有对照行为满足规则才可标记 `effective`。

## 1. 统一固定条件

所有样例使用同一模型、同一服务地址、`temperature=0`、非流式 Chat Completions、同一工具 schema 和同一短上下文。每项 3 组固定输入，初测 1 次，共 15 个初测请求。

有效响应违反规则时，对同一请求追加最多 2 次复核，并保留首次有效失败；超时、连接中断、限流等执行异常最多追加 2 次重试。复核和重试不改变参数、提示词、工具定义或样例指纹。

工具固定为 #36 的 `lookup_weather` 与 `lookup_air_quality`；仅使用参数控制，不执行工具、不评价工具选择质量。

## 2. P02 禁止工具调用

请求同时提供两个工具，设置 `tool_choice: "none"`。3 组提示词分别要求普通短答、要求解释一个天气事实、要求回答两个城市的差异。

- 通过：响应可解析且 `tool_calls` 缺失或为空，返回普通 assistant 内容。
- 未通过：返回任意工具调用。
- 未完成：认证、网络、限流或响应截断导致无法判断。
- `effective` 需要同一组输入在不使用 `none` 的对照条件下有工具调用，而控制组没有；只有控制组请求成功不能证明控制生效。

## 3. P03 强制指定工具

请求同时提供两个工具，设置 `tool_choice` 指定 `lookup_weather`。3 组参数覆盖字符串、数字和枚举值。

- 通过：至少一个工具调用，且每个调用的函数名为 `lookup_weather`，参数可解析并符合 schema。
- 未通过：调用另一工具、普通文字替代调用、参数不可解析或必填字段/类型错误。
- 未完成：没有足够有效响应。
- `effective` 需要与 `tool_choice: "auto"` 对照，证明控制组实际选择被指定工具覆盖；不要求 auto 对照必然选择另一个工具。

## 4. P04 强制产生工具调用

提供两个工具，设置 `tool_choice: "required"`。3 组提示词都要求执行可由工具完成的查询，但不指定具体工具。

- 通过：至少产生一个可解析工具调用。
- 未通过：返回普通文字、空调用、非法参数或没有任何调用。
- 通过不评价选择哪个工具，也不代表工具执行成功。
- `effective` 需要与 `tool_choice: "auto"` 的请求对照，证明 `required` 使本来可能直接回答的输入进入工具调用分支。

## 5. P05 禁止一次生成多个调用

设置 `parallel_tool_calls: false`，提示同一轮查询两个城市。3 组输入分别要求天气双城市、天气加空气质量、同一工具两次调用。

- 通过：响应最多包含一个工具调用；普通文字或零调用只在题目允许时另记为“无调用”，不能自动写成多调用控制通过。
- 未通过：单个响应包含两个或更多工具调用。
- 本项只检查响应中的调用数量，不检查服务是否并发执行，也不要求 `parallel_tool_calls: true` 必须产生多个调用。
- `effective` 需要与相同输入但不设置该参数的对照比较调用数量边界。

## 6. P06 停止标记控制

设置 `stop: ["<END>"]`，提示生成固定短句并在末尾加入停止标记。3 组输入使用不同唯一标记。每组另执行不设置 `stop` 的自然结束对照。

- 通过：响应在停止标记处结束，返回内容不包含 `<END>`，并且对照响应没有在相同位置自然结束。
- 未通过：内容继续越过标记、返回标记本身，或在无停止标记对照同样位置自然结束导致无法证明控制作用。
- 未完成：服务拒绝参数、响应截断、没有可比较的对照或执行异常。
- 不把“响应很短”单独视为停止生效；必须有同输入对照和停止位置证据。

## 7. 证据与状态投影

每项保存参数名和值、完整请求设置指纹、工具定义指纹、初测/复核/重试序号、HTTP 状态、脱敏响应、解析出的调用数量/名称/参数、对照结果、判定路径和证据引用。API key 不进入记录。

客户界面显示“通过／未通过／未完成”，详情中同时展示 `accepted` 与 `effective` 的事实层级。未测 P01、P07-P13 不显示为通过、失败或不支持。

## 8. 验收标准

| AC | 检查 | 预期 |
| --- | --- | --- |
| AC-01 | 5 项 × 3 组固定输入 | 15 个初测样例、稳定版本和指纹 |
| AC-02 | P02、P03、P04 工具控制 | 禁止、指定、强制调用的响应差异可独立判定 |
| AC-03 | P05 多调用输入 | `parallel_tool_calls=false` 只按响应调用数量判定 |
| AC-04 | P06 停止标记和自然结束对照 | 只有对照可排除自然结束时才可判定生效 |
| AC-05 | 有效失败复核、执行异常重试、明确拒绝 | 首次有效失败保留，`unsupported` 与 `inconclusive` 不混淆 |
| AC-06 | 未纳入参数检查 | P01、P07-P13 不被扩大测试或写入结论 |

## 9. 交接约束

本设计补齐 #16 的 P02-P06 方法和证据，不修改已确认范围，不恢复 P01。#25 接入时必须把请求接受、控制生效和模型任务结果分成不同状态；工具实际执行和 Agent 闭环继续归属 Agent 模块。
