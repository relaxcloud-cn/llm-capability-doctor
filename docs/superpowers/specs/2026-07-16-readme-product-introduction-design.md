# README 产品介绍改版设计

## 目标

将项目根目录的 `README.md` 完全替换为面向客户和项目相关方的中文产品介绍。新 README 聚焦工具开发背景、核心使用流程与设计考量，不保留原技术手册中的检测项明细、命令示例、协议说明和判定边界。

## 内容边界

- 仅整理用户提供的信息，不新增未经确认的功能、参数或兼容性承诺。
- 保留项目中文名“LLM Capability Doctor（大模型能力诊断工具）”。
- 明确现场操作由检测脚本和本地 Skill 组成。
- 完整列出网络连通性、上下文长度上限、并发性能、工具调用能力、思维链能力和敏感词过滤策略六类检测维度。
- 突出两步现场流程、检测项分级和报告证据可追溯性。

## Markdown 结构

1. 使用一级标题展示项目名称，并用引用块呈现一句话定位。
2. “工具开发背景”使用简洁段落说明问题与开发目的。
3. “核心使用流程”使用四步编号列表，体现脚本准备、现场执行、日志导出和本地报告生成的顺序。
4. 使用醒目的简短引用强调现场仅需“执行脚本、解析日志”两步。
5. “设计核心考量”使用三列表格展示考量、设计方式和价值，便于横向扫描。

## 验收标准

- `README.md` 的旧内容被完全替换。
- 用户提供的所有关键信息均被保留，语义不发生改变。
- 标题、编号列表、强调文本和表格符合标准 Markdown 语法。
- 排版在常见 GitHub/GitLab Markdown 渲染器中无需额外 HTML 或外部资源即可清晰显示。
- 不修改项目中的其他业务文件，也不处理现有未跟踪日志与报告。
