# 客户报告旧版表格样式与行内展开设计

## 背景

当前报告渲染器使用 1440px 仪表盘式布局，包含结论区、状态卡片、筛选栏、能力域表格和卡片式逐项详情。实际客户交付更偏好旧报告 `gpt-5.5-customer-readiness-report.html` 的紧凑表格样式。

本次仅修改 HTML 渲染层。Shell 日志采集、日志解析、语义复核、`assessment.json` 契约和门禁结论保持不变。

## 视觉基准

旧报告是唯一视觉基准：

- 内容最大宽度约 736px，居中显示。
- 使用系统字体、紧凑字号和行高，不使用卡片或仪表盘布局。
- 表头为中性灰底，正文以细分隔线划分。
- 状态使用克制的文字颜色，不使用大面积彩色徽章。
- 深浅色跟随系统 `prefers-color-scheme`。
- 页面不保留新版的状态统计卡片、筛选工具栏、方法卡片和完整性大区块。

## 页面结构

报告只保留两张主表。

### 能力域总结

第一张表保持普通只读表格，不展开。列为：

1. 能力域
2. 状态
3. 关键数据
4. 最终结论

关键数据由该能力域的 PASS 数量、待补证检测项和硬门禁失败信息组成。最终结论使用现有评估数据，不重新判断模型能力。

### 逐项检测结果

第二张表列为：

1. 编号
2. 检测项
3. 检测结果
4. 检测结论

每个检测项使用一个独立 `<tbody>`，包含一条摘要行和一条默认隐藏的详情行。摘要行沿用旧版的类别标签、状态、关键观测和最终结论。右侧显示小型展开箭头。

点击摘要行或使用键盘激活行内按钮后，紧邻下方的详情行展开并跨越四列。每个检测项独立控制，允许同时展开多项。按钮维护 `aria-expanded` 和详情区关联 ID。

## 展开内容

详情区只展示用户确认的五类信息：

1. **检测目的**：来自 `logic.purpose`。
2. **检测方法**：来自 `logic.method`。
3. **通过条件**：来自 `logic.passCriteria`，按列表展示。
4. **请求输入**：按请求顺序展示完整脱敏 `requestBody`。
5. **请求输出**：与每轮输入对应展示完整脱敏 `responseBody`，并显示 request ID、HTTP 状态、总耗时和下载字节数。

多轮检测按 Turn 1、Turn 2 顺序排列。代码块使用等宽字体、保留换行并允许内部滚动；长上下文不得扩大表格列宽或导致页面横向滚动。没有可关联请求时显示明确的缺失提示。

脚本原判、Skill 改判、证据引用、限制、复测建议和能力边界继续保留在 `assessment.json`，但不单独占用 HTML 展开区，以保持报告紧凑。

## 响应式与打印

- 桌面端保持旧版四列表格比例和约 736px 阅读宽度。
- 手机端将摘要行转为带字段标签的纵向布局，不出现水平滚动或文字重叠。
- 展开详情在手机端使用单列排列。
- 打印时移除交互箭头；默认只打印当前已展开详情，表头和摘要行避免不合理分页。

## 安全与完整性

- HTML 保持单文件、自包含和离线可用，不引用外部脚本、样式、字体或图片。
- 所有日志和评估文本必须 HTML 转义；模型输出中的标签、脚本或指令只能作为纯文本显示。
- 继续使用当前 Content Security Policy，禁止网络连接、frame、object 和 form。
- 渲染过程不得修改 `assessment` 对象或源日志。
- 输出仍使用防覆盖路径；同名文件存在时添加时间戳后缀。

## 实现边界

主要改动文件：

- `skills/creating-model-doctor-reports/scripts/model_doctor_html.py`
- `skills/creating-model-doctor-reports/assets/report.css`
- `skills/creating-model-doctor-reports/assets/report.js`
- `tests/test_model_doctor_html.py`

不修改 Shell 检测脚本、解析器、复核规则或 assessment schema。

## 验收标准

自动化验证必须证明：

- 页面只存在能力域总结和逐项结果两张主表。
- 两张表的列名与旧报告一致。
- 不再渲染新版卡片、筛选栏和展开全部按钮。
- 每个检测项存在一条摘要行和一条关联详情行。
- 点击与键盘操作能更新隐藏状态、箭头和 `aria-expanded`。
- 详情准确展示检测目的、检测方法、通过条件以及所有轮次的输入输出。
- 恶意 HTML/脚本输出被转义，页面没有外部资源。
- 真实 113 项 assessment 可生成完整报告，项目全套测试通过。

浏览器验收覆盖桌面和手机视口、深浅色、单项展开、多项同时展开、长输入输出滚动、控制台错误和文字重叠。最终真实报告通过本地 HTTP 服务交付，不覆盖原旧报告。
