# AgentCheck 用户使用手册

适用程序：**0.4.8 试用候选版** · 检测规则：`agentcheck/12` · 更新：2026-10-14

本手册面向已经拿到 AgentCheck 程序的用户：**不需要源码，不需要编译，也不需要安装 Node、Bun、Python 或 OMP。** 按下面的步骤填写模型连接信息，即可自己完成检测、查看报告和反馈问题。

## 1. 运行前准备

### 选对程序

| 你的环境 | 应使用的程序 | 本手册操作方式 |
| --- | --- | --- |
| Apple Silicon / M 系列 Mac | macOS arm64 构建的 `agent-check` | “终端”中的 Zsh 或 Bash；也可使用随包桌面界面 |
| Linux x86_64 服务器 | Linux x86_64 构建的 `agent-check` | Bash；可通过 SSH 登录服务器后执行 |
| Windows、Intel Mac 或其他架构 | 不要直接使用上述两个程序 | 先向交付方确认对应构建及验收范围 |

macOS 与 Linux 已有原生 CLI 实测，但不代表所有系统版本均兼容。当前仍是试用候选版，Windows、Responses 真实服务、完整跨平台验收及正式签名/公证尚未完成；以交付方说明为准。

解压后的常见文件如下；如果只收到单个程序，向交付方索取校验值，配置可按本手册自行创建。

| 文件 | 作用 |
| --- | --- |
| `agent-check` | 启动程序，已内置所需运行组件 |
| `model.example.json` | 不含密钥的配置模板 |
| `使用手册.md` | 本手册 |
| `SHA256SUMS` | 文件校验清单；有此文件时按下一节核验 |
| `licenses/` | 内置组件许可文件，请保留 |

### 准备模型连接信息

请向模型服务管理员确认以下内容，不要凭产品名称猜配置：

- **服务地址**：例如 `https://model.example.com/v1`，或管理员给出的完整接口地址。
- **模型名称**：接口实际接受的模型标识。
- **API Key**：有权访问该模型的密钥。
- **接口协议**：`chat-completions` 或 `responses`。不知道时先问管理员，不要在失败后随意换协议。

运行电脑必须能访问该服务；内网服务需要先接入对应网络或 VPN。程序目录、缓存及结果目录需要当前用户有读写/执行权限，磁盘需有足够空间保存运行组件和多次检测记录。

> **正式检测会产生模型调用费用，并增加服务负载。** 它包含长输入及逐档增加的并发请求。请使用获准测试的账号和时间窗口，避免在生产高峰或他人压测时运行；网络、网关、配额和背景负载都会影响结果。程序内置组件不需要现场下载，但正式检测仍需要访问你的模型服务。

## 2. 首次检测：一步一步操作

以下命令适用于 Bash / Zsh。**只复制代码框中的命令，不复制三个反引号；凡标明示例的地址、模型名和路径都要替换。**

### 第 1 步：解压并进入程序目录

- **Mac**：双击压缩包解压，打开“终端”，输入 `cd `（末尾有空格），将解压后的文件夹拖入终端，再按回车。
- **Linux**：解压交付包，用 `cd` 进入含 `agent-check` 的目录；如果通过 SSH 检测，下面的命令都在服务器上执行，不是在自己的电脑上执行。

不要直接在压缩包预览窗口中运行。路径有空格时加引号，例如：

```sh
cd "/path/to/AgentCheck"
```

`/path/to/AgentCheck` 只是示例，请换成实际解压目录。先核对文件完整性，再运行程序。

**有 `SHA256SUMS` 时，按系统选一条校验命令：**

macOS：

```sh
shasum -a 256 -c SHA256SUMS
```

Linux：

```sh
sha256sum -c SHA256SUMS
```

清单中的文件都应显示 `OK`。若不一致，停止使用并重新获取完整交付包，不要修改清单来让校验通过。没有清单时，可运行对应的 `shasum -a 256 ./agent-check` 或 `sha256sum ./agent-check`，与交付方通过可信渠道提供的值比较。

校验通过后执行：

```sh
chmod +x ./agent-check
./agent-check --version
```

本手册对应输出 `agent-check 0.4.8`；如果拿到的是其他版本，先确认随包手册是否匹配。

### 第 2 步：运行离线自检

```sh
./agent-check --offline-self-test
```

首次自检会释放并核对运行组件，**不需要 API Key，不会调用模型**。成功输出的 JSON 应包含以下字段（实际输出还会有本机路径等字段）：

```json
{
  "bundled": true,
  "omp_version": "omp/18.1.13",
  "gui_opened": false,
  "model_requests": 0
}
```

自检失败先看[常见问题](#5-常见问题)，不要继续正式检测。`bundled` 不是 `true` 时，先确认是否误拿了开发构建。**自检通过只说明程序组件可运行，不表示模型检测通过。**

### 第 3 步：创建 `model.json`

如果包里有模板，复制一份后再改，不覆盖原模板：

```sh
cp -n model.example.json model.json
```

已有 `model.json` 时，这条命令不会覆盖它。如果没有模板，用纯文本编辑器创建文件名为 `model.json` 的文件，填入：

```json
{
  "base_url": "https://model.example.com/v1",
  "model": "replace-with-your-model",
  "api_key_env": "MODEL_API_KEY",
  "protocol": "chat-completions"
}
```

| 配置项 | 你需要怎么填 |
| --- | --- |
| `base_url` | 换成管理员提供的 HTTP / HTTPS 服务地址，不是网页登录页面 |
| `model` | 换成真实模型标识，不要保留示例文字 |
| `api_key_env` | 保持 `MODEL_API_KEY`，下一步在终端输入密钥 |
| `protocol` | 填管理员确认的 `chat-completions` 或 `responses` |

保存为 UTF-8 纯文本。JSON 使用英文双引号，不允许注释、尾逗号；注意不要保存成 `model.json.txt` 或富文本文件。

地址补全示例（**均为占位地址，不能直接用于测试**）：

| 配置地址 | 协议 | 实际请求地址 |
| --- | --- | --- |
| `https://model.example.com/v1` | `chat-completions` | `https://model.example.com/v1/chat/completions` |
| `https://model.example.com/llm/v1` | `responses` | `https://model.example.com/llm/v1/responses` |
| `https://model.example.com/v1/chat/completions` | `chat-completions` | 保持完整地址不变 |

已有网关路径前缀会保留；仅填写域名时默认补上 `/v1`。完整接口地址与协议不一致会被拒绝。`127.0.0.1` 表示**运行 AgentCheck 的这台机器**：在自己电脑填写它，不会连接到另一台模型服务器。

### 第 4 步：在同一终端输入 API Key

```sh
printf '请输入 API Key（不回显）: '
read -r -s MODEL_API_KEY
printf '\n'
export MODEL_API_KEY
```

粘贴真实密钥后按回车。屏幕不显示字符是正常的；密钥作为输入读取，不写进这条命令的历史。**后续检测必须在这个终端启动**，新开终端需要重新输入。不要用 `echo` 打印密钥来检查是否设置成功。

也支持私有配置中的 `api_key`，但它会把密钥明文存入文件；推荐使用上面的环境变量方式。两种方式同时配置时，程序优先使用 `api_key`。仅当服务管理员确认接口无需鉴权时，才可使用其指定的非空占位值；这不用于绕过服务鉴权。

### 第 5 步：开始完整检测

```sh
./agent-check \
  --config ./model.json \
  --no-gui \
  --report-dir ./results
```

这条命令固定使用终端，适用于两种已验证平台。执行后依次观察：

1. **先检查连接**：通过后才开始正式检测。失败会显示 HTTP 状态码和脱敏后的原始错误；没有 HTTP 响应时显示底层连接异常。此时不要把后面的未执行项目当成模型能力失败。
2. **显示检测进度**：共八项检测；OMP 三类任务各执行两次。某次任务结束，不表示整类已经完成；进度到 100% 也不表示全部通过。
3. **生成报告**：看到“正在生成报告”时继续等待，直到输出 HTML / ZIP 路径或终端返回提示符。不要提前关闭终端。

检测耗时取决于服务速度与当前负载，不是固定时长。普通完整请求通常最多等待 180 秒；直接工具调用项单次请求为 600 秒、整项最多 1200 秒；OMP 每次任务最多 240 秒，多轮内部两轮合计计时。预算是保护上限，不是预计完成时间。更完整的预算见第 4 节。

### 第 6 步：打开报告并保留记录

结果在刚才目录下的 `results/AC-.../`，终端会给出本次完整路径。

- **Mac**：用 Finder 打开 `results`，进入本次 `AC-...` 目录，双击 `report.html`。桌面交互运行也会尝试自动打开。
- **Linux / SSH**：不会自动弹出浏览器。通过你已有的 SFTP / 文件传输工具，将本次整个 `AC-...` 目录下载到自己的电脑，再打开其中的 `report.html`。
- **需要 PDF**：在 HTML 中点击“打印 / 保存 PDF”，或使用浏览器打印功能。PDF 不会自动生成。
- **需要技术复核**：保留 `result.json`、`records.zip` 和检测编号。不要只发送“通过 / 未通过”的截图。

报告的判断方法见[第 4 节](#4-检测内容报告与退出码)。测试结束后，可按[反馈清单](#6-测试结束与问题反馈)整理信息。

## 3. 图形界面与其他用法

### macOS：不编辑配置文件，直接用界面检测

如果拿到的 macOS 包包含桌面界面，可在程序目录运行：

```sh
./agent-check --offline-self-test --gui --report-dir ./results
```

这个启动命令只检查组件、打开本机记录，**不会自动请求模型**。界面打开后：

1. 点击 **“新建检测”**。
2. 填写 **服务地址、模型名称、API Key、接口协议**，核对界面显示的实际请求地址。此路径不读取终端中的 `model.json`，密钥也需要在表单填写。
3. 点击 **“检查连接并开始”**。连通性通过后自动开始正式检测；失败会在弹窗显示原始错误，修改配置后再提交。
4. 在工作台查看进度。结束后点击 **“查看报告”**，或到 **“检测记录”** 查看以前的结果。

Linux 本版使用 CLI。普通命令省略 `--no-gui` 时，也会在可用的桌面环境中打开 GUI 并继续同一次检测，不是 CLI 和 GUI 各测一遍；自动启动失败时可回退 CLI。

### 中途停止与重新检测

- **CLI**：按一次 `Ctrl+C`，等待程序停止、保存已有结果并返回提示符。
- **GUI**：点击“停止检测”，在确认框中确认，等待保存完成。
- 不要强杀进程、断开服务器会话或删除锁文件来结束检测；强制退出后的自动恢复尚未完成验收。
- 重测是在修正配置/服务问题后再次执行原命令，或在 GUI 中点击“重新检测”/“新建检测”。**每次都是新的完整检测，不是从上次断点继续**，也会产生新的模型用量。
- 新检测目录不会覆盖旧结果，也不会用新规则修改旧报告。请保留同一轮的 HTML、JSON 和 ZIP，避免混用。

### 保存最终 JSON 与进度日志

当前终端已设置密钥、`model.json` 已填写时，可用：

```sh
log_dir=$(mktemp -d "./agentcheck-logs-XXXXXXXX")
./agent-check \
  --config ./model.json \
  --json \
  --no-color \
  --report-dir ./results \
  > "$log_dir/result.json" 2> "$log_dir/progress.log"
run_exit=$?
printf '退出码：%s\n日志目录：%s\n' "$run_exit" "$log_dir"
```

日志目录每次新建，不会覆盖上次日志。此模式的进度写到文件，终端暂时没有持续输出是正常的；需要查看时，用文本编辑器打开 `progress.log`。配置或连通性检查失败时，最终 JSON 可能为空，应先看日志和 `results/startup/`。

### 常用参数

| 参数 | 使用场景 |
| --- | --- |
| `--config <文件>` | 从 JSON 读取服务地址、模型与密钥来源 |
| `--no-gui` | 始终在终端运行；不单独关闭报告自动打开 |
| `--no-open-report` | 不自动弹出 HTML，仍保存结果和显示路径 |
| `--json` | 强制 CLI，最终 JSON 写 stdout，进度写 stderr，不弹出报告 |
| `--report-dir <目录>` | 指定结果根目录；路径有空格时加引号 |
| `--no-color` | 关闭终端颜色，方便保存日志 |
| `--protocol <协议>` | 覆盖配置中的协议；必须与完整接口地址匹配 |
| `--url <地址>` / `--model <名称>` | 不使用配置文件时提供地址与模型；密钥仍从 `MODEL_API_KEY` 读取 |
| `--offline-self-test` | 不调用模型的运行组件检查 |
| `--help` / `--version` | 查看帮助或程序版本 |

使用 `--config` 时不要期望 `--url`、`--model` 覆盖配置文件。`--gui` 不与 `--no-gui` 或 `--json` 混用。

## 4. 检测内容、报告与退出码

### 八项检测分别看什么

| 检测项 | 对用户意味着什么 |
| --- | --- |
| 接口与响应 | 普通、流式请求能够完整响应，前轮消息可正确回传 |
| 工具调用 | 模型能按定义选择工具、填写参数、接收并使用工具结果；不以服务端 `strict` 模式为前提 |
| 结构化输出 | 返回的数据能解析、字段与内容正确；兼容 JSON 代码块会明确标注，不等同原生严格 Schema 支持 |
| 长上下文 | 验证至少 128K tokens 的容量要求，继续探测容量；不考长文理解能力 |
| 并发能力探测 | 在普通短文本负载和规定时延下，给出有证据的建议档位或未确认原因 |
| 连续工具执行 | 真实 OMP 读取两个小文件、各一条记录，合并并实际写入结果 |
| 工具故障恢复 | 明确告知一次临时读取失败后，能否恢复工具操作并完成相同任务 |
| 多轮继续执行 | 同一会话继续处理已有文件，只修改指定字段并保留其余内容 |

后三项各执行两次，共六次任务；输入、文件与工具轨迹由程序独立核验，不以模型说“完成了”为准。结论只覆盖本次服务、模型与固定 OMP 的组合，不认证底层模型身份，也不代表通用业务能力或长期可靠性。

### 报告先看哪里

1. **检测结论**：本轮整体状态、通过/未通过/未确认数量及适用条件。
2. **检测结果与基线对照**：逐项核对结果；没有真实基线时不展示虚构参考值。
3. **使用建议**：查看未通过、未确认或附条件通过的原因与下一步。
4. **页尾技术附件**：按需展开样本、逐项证据和并发明细，或下载真实记录。

| 状态 | 正确理解 | 建议操作 |
| --- | --- | --- |
| 通过 | 本次规定要求已有证据支持 | 同时阅读适用条件，不直接外推到所有业务 |
| 未通过 | 已确认存在不满足本次要求的记录 | 看具体字段、错误或请求原因，修正后再测 |
| 未确认 | 证据不足、运行受阻或没有正常完成 | 排查服务、网络、配置和运行环境，不直接说模型“不行” |
| 未执行 | 尚未运行到这一项 | 检查前置连接是否通过、是否取消或预算耗尽 |

**“未通过”不等于报告生成失败，“未确认”不等于通过。** 一次后续成功不会覆盖之前失败；任务已经恢复但文件写错，仍需按结果错误处理。

### 并发建议怎么用

- 使用固定普通短文本请求，按 `1、2、4、8…` 增加并发，不评价正文知识准确性。平均完整响应时间须 ≤ **10 秒**、P95 ≤ **20 秒**；少于 20 个请求时用最慢耗时代替 P95。180 秒仅是单请求硬超时。
- 只有某档失败全部属于连接传输异常时，整档结束后等待 1 秒，**完整复核同一档一次**。复核合格再升档，否则停止；每条请求仍只尝试一次，两轮不能拼成一轮全通过。
- 限流、超时、空回复、截断、鉴权、格式、HTTP 服务错误及混合失败不走连接复核。首次错误、等待、两轮请求与耗时都保留，不能重试到全绿。
- 高档位连接异常未排除时，此前合格档位可作为**带稳定性风险的试用起点**。有效的至少 2 并发建议可满足并发项，但附带风险仍须处理；没有合格档位不建议。
- “建议 64 并发”不是“最大只能 64”，也不是适用于长输入、复杂任务的承诺。以实际业务负载另行评估，注意账号、网关和当时背景负载。

并发复核计入原预算，预算不足不发部分复核负载；用户取消后不继续复核。旧报告按原规则保留，不用新策略补判。

### 等待与保护预算

| 范围 | 当前保护上限 |
| --- | --- |
| 普通完整 HTTP 请求 | 180 秒；相关重试共享同一请求时限 |
| 直接工具调用检测 | 单请求 600 秒，整项 1200 秒，单次输出预算 20000 tokens |
| 真实 OMP 单次任务 | 240 秒，多轮的两轮合计 |
| 并发探测 | 100,000 个请求、32 轮、60 分钟，另受本机连接资源限制 |
| 直接接口检测阶段 | 最多 104 分钟；再为 OMP 与收尾保留保护时间 |

这些是防止无限等待的保护上限，不代表每次测试都会用满。并发请求不做单条自动重试；其他请求的重试也不会无限延长任务期限。上下文只测到下界时会显示“至少支持 X tokens，最大上限待确认”，超时不能证明找到了最大容量。

### 报告文件在哪

使用首次检测命令时，目录结构如下：

```text
results/
├── startup/                     # 模型连通性检查记录
└── AC-日期时间-唯一编号/
    ├── report.html              # 给使用者看的报告
    ├── result.json              # 本轮机器可读结果
    ├── records.zip              # 脱敏请求、响应与任务证据
    ├── evidence-index.json      # 证据索引和 SHA-256
    └── ...                      # 原始观察、任务文件等
```

如果只完成了连通性失败记录，可能只有 `startup` 而没有正式报告，这是预检阻止后续检测的正常行为。不要删除锁文件来强行启动第二轮；等当前同一结果目录的检测结束或正常取消。

没有指定 `--report-dir` 时：

| 平台 | 默认结果目录 |
| --- | --- |
| macOS | `~/Library/Application Support/AgentCheck/results` |
| Linux | `$XDG_DATA_HOME/AgentCheck/results`；未设置时为 `~/.local/share/AgentCheck/results` |

设置了 `AGENTCHECK_DATA_DIR` 时，默认改为该目录下的 `results`。指定 `--report-dir` 则以显式目录为准。

macOS 桌面交互运行会尝试自动打开报告；Linux、SSH、CI、JSON 模式和用户取消不会弹窗。自动打开失败不改变检测结论，按保存路径手动打开即可。HTML 支持按需打印 PDF 和下载内嵌 ZIP；若浏览器限制下载，可直接取目录中的 `records.zip`。单独分享 HTML 时，外部证据链接未必可用，最好连同 ZIP 或整个结果目录一起保留。

### CLI 退出码

| 退出码 | 含义 |
| --- | --- |
| `0` | 本次正式 CLI 检测通过 |
| `1` | 有已确认未通过项，报告可能已完整生成 |
| `2` | 未完成或启动错误；结合日志区分原因 |
| `130` | 正式检测阶段被用户取消，已有结果保留 |

离线自检成功也返回 `0`，不表示模型通过。连接检查阶段取消走启动错误路径，返回 `2`；GUI 交接成功的入口返回 `0` 只说明界面接管，最终结果看 GUI 与报告。

## 5. 常见问题

| 现象 | 怎么处理 |
| --- | --- |
| `No such file or directory` / 找不到程序 | 确认已解压，终端位于含 `agent-check` 的目录；运行时保留开头的 `./`，有空格的路径加引号 |
| `Permission denied` | 执行 `chmod +x ./agent-check`；确认文件系统允许执行，结果和缓存目录可写；组织策略限制时联系管理员 |
| `bad CPU type` / `Exec format error` | 程序与操作系统或 CPU 不匹配，向交付方索取对应构建 |
| macOS 安全机制阻止打开 | 核对来源和校验值，联系交付方或组织 IT 处理签名/分发；不要关闭系统安全机制 |
| 离线自检失败 / 运行组件校验失败 | 保留完整错误及版本，检查磁盘空间、目录权限和交付完整性；联系交付方，不自行下载任意 OMP 替换内置版本 |
| 配置不是有效 JSON / 无法读取配置 | 检查文件位置、UTF-8、英文双引号、尾逗号及扩展名；路径有空格时加引号 |
| 密钥环境变量未设置 | 在启动检测的同一个终端重新执行第 2 节第 4 步；不要把示例文字当密钥 |
| HTTP 401 / 403 | 按服务端原始正文核对密钥、账号权限和网关策略，不反复试错 |
| HTTP 404 / 地址与协议不匹配 | 核对接口完整路径、模型标识、网关前缀与协议；`127.0.0.1` 只指当前运行机器 |
| 连接关闭、证书错误或超时 | 保留原始异常链；检查访问网络、VPN/代理、证书和服务日志，不直接归为模型能力不足 |
| HTTP 429 / 5xx | 联系服务管理员核对额度、限流和服务状态；处理后再测，不为全绿重复刷测 |
| 并发有建议但附连接风险 | 只能按报告作为试用起点；核对首次与复核记录，排查连接稳定性，不能当成已确认上限 |
| 本机连接资源不足 | 已保留有效结果；先核对系统文件描述符/连接限制，必要时由管理员调整；不是服务容量极限 |
| 并发或上下文显示未确认 | 看本轮停止原因、时延、容量下界及证据；未确认不等于失败，也不等于通过 |
| 终端看似不刷新 | JSON/重定向模式查看 `progress.log`；其他模式看当前步骤和已用时间，先不要重复启动 |
| 同一结果目录已有检测运行 | 等待当前检测结束或正常取消，不删除锁文件强行并行 |
| 没有自动打开 HTML | Linux/SSH/JSON/取消时本就不自动打开；按输出路径取报告；连接检查未通过则可能没有正式报告 |

## 6. 测试结束与问题反馈

完成后可在当前终端清除密钥变量：

```sh
unset MODEL_API_KEY
```

分享前检查记录内容：**程序会脱敏已知密钥，但地址、模型输出、任务路径和服务返回正文仍可能含敏感信息。** 脱敏不等于可以公开上传，按你所在组织要求审核后再发送。

反馈给交付方时提供：

- 程序版本（`./agent-check --version`）、操作系统与 CPU 架构。
- 检测编号、检测时间、接口协议，以及是否通过 SSH / VPN / 代理运行。
- 启动命令（去掉密钥）和完整错误原文；不要只截最后一行。
- 有正式结果：`report.html`、`result.json`、`records.zip`；必要时提供 `progress.log`。
- 连接检查未通过：提供进度/错误日志和对应的 `results/startup/` 记录，不必等待不存在的正式报告。

**不要发送真实 API Key、含密钥的 `model.json`、终端环境变量全集或其他账号凭证。** 服务变更、修复配置后重新检测，保留旧记录用于比较，不手工修改原判定。
