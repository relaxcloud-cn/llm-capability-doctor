# AgentCheck 使用说明

无需安装。按电脑类型选择对应程序：

| 电脑类型 | 程序文件 |
| --- | --- |
| Mac（M 系列芯片） | `agent-check-macos-arm64` |
| Windows（64 位 Intel / AMD） | `agent-check-windows-x86_64.exe` |
| Linux（ARM64） | `agent-check-linux-arm64` |
| Linux（64 位 Intel / AMD） | `agent-check-linux-x86_64` |

如果拿到的是压缩包，先解压；程序文件名若为 `agent-check`，将下面命令中的文件名改为 `agent-check`。

## 1. 准备三项信息

向模型服务方获取：**完整接口地址、模型名称、密钥（API Key）**。

## 2. 一条命令开始检测

在程序所在文件夹打开终端，把下面的服务域名、完整接口地址、模型名称和密钥换成自己的。`NO_PROXY` 填服务域名（不带 `https://` 和路径），让这个服务直接连接；如果服务必须通过代理访问，去掉命令中设置 `NO_PROXY` 的部分。

**Mac / Linux：**Mac 使用下面命令；Linux 将文件名换成上表对应的 Linux 程序名。

```sh
chmod +x ./agent-check-macos-arm64 && NO_PROXY='model.example.com,localhost,127.0.0.1' ./agent-check-macos-arm64 --url 'https://model.example.com/v1/chat/completions' --model '你的模型名称' --api-key '你的密钥' --no-gui --report-dir ./results
```

**Windows CMD：**在程序文件夹的地址栏输入 `cmd` 并回车，复制下面这一行执行：

```bat
set "NO_PROXY=model.example.com,localhost,127.0.0.1" && agent-check-windows-x86_64.exe --url "https://model.example.com/v1/chat/completions" --model "你的模型名称" --api-key "你的密钥" --no-gui --report-dir ".\results"
```

如果服务方要求使用 Responses 接口，请填写对应地址，并在检测命令末尾加上 `--protocol responses`。

程序会先检查连接，再自动检测。等待提示检测结束，不要提前关闭终端。

**注意：检测会消耗模型额度，请先确认允许检测且额度充足。命令中的密钥可能保留在终端历史中，不要截图或转发。**

## 3. 查看报告

检测结束后，打开程序文件夹中的 `results`，进入本次检测的文件夹，双击 **`report.html`**。如果在服务器上运行，先把该文件夹下载到电脑再打开。

报告会说明哪些项目通过、哪些需要处理；“未确认”表示这次没有测出可靠结论，不等于模型不行。需要 PDF 时，在报告中点击“打印 / 保存 PDF”。

## 遇到问题

- **提示 `Permission denied`**：运行 `chmod +x ./程序文件名`，将文件名换成实际使用的程序，再执行检测命令。
- **连接不上或出现报错**：核对地址、模型名和密钥；仍有问题，把不含密钥的错误截图发给交付人员。
- **提示 `unsupported scheme socks5h`**：确认命令中的 `NO_PROXY` 已换成实际服务域名；如果服务必须通过代理访问，请联系交付人员。
- **提示 `UnknownIssuer`、`certificate is not trusted` 等证书错误**：优先让系统信任服务方提供的内部 CA，或请服务方修复证书链。临时排查可在原检测命令末尾加 `--insecure`；它会跳过 HTTPS 证书链和服务端名称校验，API Key 存在被截获风险，不建议长期使用。此开关同时作用于连接检查和后续检测；移除后恢复校验，不会自动跳过。
- **想中途停止**：在终端按一次 `Ctrl+C`，等待保存完成。

再次运行同一命令即可重新检测，旧报告会保留。

> Windows 和 Linux x86_64 版本尚未完成目标电脑上的运行验证。如启动失败，请联系交付人员，不要关闭系统安全保护。
