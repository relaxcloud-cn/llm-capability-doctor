# AgentCheck CLI 使用手册

版本：0.4.6 客户试用候选版 · 文档更新：2026-10-13

**本包适用于 Apple Silicon（M 系列芯片）的 Mac。** 可通过终端检测模型接口与任务执行能力，并生成本机报告。首次使用按第 2 节操作。

本包尚未完成正式发布验收，未签名、公证。Windows、Linux、Intel Mac 不适用本包；Responses 真实服务、干净系统兼容性及完整异常场景尚未完成验收。请用于试用评估，具体结论结合报告证据核对。

## 1. 文件与运行条件

解压后目录名为 `AgentCheck-CLI-v0.4.6-macOS-arm64`。

| 文件 | 用途 |
| --- | --- |
| `agent-check` | 单文件程序，约 196 MB；按本手册使用 `--no-gui` 运行 CLI |
| `使用手册.md` | 本使用手册 |
| `model.example.json` | 无密钥配置模板，需替换服务地址和模型名称 |
| `SHA256SUMS` | 包内文件的 SHA-256 校验值 |
| `licenses/` | 随内置组件提供的许可文本 |

程序已内置运行组件，无需安装 Node、Bun、Python 或 OMP。该可执行文件也包含桌面界面，但本手册所有正式检测命令均使用 CLI。省略 `--no-gui` 且桌面可用时，程序可能自动打开 GUI。

运行需要：当前用户可写的缓存与结果目录，以及可访问的模型服务、模型名称和有效 API Key。建议预留至少 2 GB 可用空间用于组件释放和记录；多次检测会继续占用空间。已验证环境为 macOS 26.5.2 / arm64，其他 macOS 版本兼容性仍需实测。

**正式检测会发送真实模型请求，并产生服务侧用量。** 长上下文可能发送较大的输入；并发探测会同时发出多个短请求，不是一次简单对话。请使用有足够额度和并发权限的测试账号。检测耗时受模型速度、限流和超时影响，建议预留 30 分钟；慢服务下可能更久。单次完整请求超时为 180 秒；直接检测保护预算为 90 分钟（其中并发最多 60 分钟），另为任务、清理和报告保留最多 13 分钟，不代表每次都会用满。可按 `Ctrl+C` 取消。

## 2. 首次运行：5 步

以下命令适用于 macOS 自带的 zsh 终端。配置内容需使用客户自己的服务信息。

### 第 1 步：解压并进入目录（约 30 秒）

双击 ZIP 解压。打开“终端”，输入 `cd `（末尾有一个空格），将解压后的文件夹拖入终端，再按回车。

在该目录运行：

```sh
chmod +x ./agent-check
shasum -a 256 -c SHA256SUMS
```

所有文件应显示 `OK`。若校验失败，请重新获取完整压缩包。

### 第 2 步：运行离线自检（预计 5–30 秒）

```sh
./agent-check --offline-self-test
```

自检会释放并核对内置组件，不需要密钥，不会请求模型。成功输出 JSON，其中应有：

```json
{
  "bundled": true,
  "omp_version": "omp/18.1.13",
  "gui_opened": false,
  "model_requests": 0
}
```

实际输出还包含本机组件路径。离线自检通过只说明组件可以运行，不表示模型能力通过。

### 第 3 步：填写模型配置（约 1 分钟）

复制模板，后续只编辑 `model.json`，保留原模板用于校验：

```sh
cp -n model.example.json model.json
```

用纯文本编辑器打开 `model.json`，修改 `base_url` 与 `model`。JSON 必须使用英文双引号，不能添加注释或末尾多余的逗号。

```json
{
  "base_url": "https://model.example.com/v1",
  "model": "replace-with-your-model",
  "api_key_env": "MODEL_API_KEY",
  "protocol": "chat-completions"
}
```

`model.example.com` 和 `replace-with-your-model` 均为占位内容，不能直接用于检测。

| 配置项 | 填写说明 |
| --- | --- |
| `base_url` | 模型网关基础地址，例如 `https://服务域名/v1`，或完整接口地址 |
| `model` | 服务实际接受的模型标识，不一定等于产品展示名 |
| `api_key_env` | 保存密钥的环境变量名称；建议保持 `MODEL_API_KEY` |
| `protocol` | `chat-completions` 或 `responses`；后者尚未完成真实服务验收 |

基础地址会自动补上 `/chat/completions` 或 `/responses`。仅填写域名时会补上 `/v1` 和对应接口路径；已有网关前缀会保留。完整接口地址与 `protocol` 必须一致。

### 第 4 步：在当前终端输入密钥（约 15 秒）

```sh
read -r -s 'MODEL_API_KEY?请输入 API Key（不回显）: '
printf '\n'
export MODEL_API_KEY
```

粘贴密钥后按回车。输入过程中不显示字符是正常现象。这种输入方式不把密钥写进上述命令或配置模板；新开终端后需要重新设置。

也支持在本机私有 JSON 配置中使用 `"api_key": "实际密钥"`，替换 `api_key_env`。该文件将包含明文密钥，不应随反馈或安装包发送。两项同时存在时优先使用 `api_key`。

### 第 5 步：启动 CLI 检测并查看报告

```sh
./agent-check \
  --config ./model.json \
  --no-gui \
  --report-dir ./results
```

程序先检查连接，再执行正式检测。终端会显示逐项进度，结束后输出 HTML 报告与 ZIP 记录路径。在 Finder 打开 `results` 中对应的 `AC-...` 目录，双击 `report.html` 查看报告。

再次运行同一命令会创建新的检测编号与目录，不覆盖旧结果。检测期间需要取消时按一次 `Ctrl+C`，等待保存完成并返回命令提示符。系统强制结束或断电后的自动恢复尚未完成验收。

## 3. 常用 CLI 命令与参数

### 保存 JSON 结果与进度日志

```sh
./agent-check \
  --config ./model.json \
  --json \
  --no-color \
  --report-dir ./results \
  > ./latest-result.json 2> ./latest-progress.log
run_exit=$?
printf '退出码：%s\n' "$run_exit"
```

此命令在 CLI 中运行，进度被保存到文件，因此当前终端不会持续显示进度。`latest-result.json` 和 `latest-progress.log` 会被下一次相同命令覆盖；`results/AC-...` 中的历次结果仍各自保留。

`--json` 将最终结果写到标准输出，将进度和错误写到标准错误。配置或连接失败等启动错误可能不会生成最终 JSON，先查看 `latest-progress.log`。退出码为 `1` 时也可能已经完整生成报告，表示发现未通过项。

### 不使用 JSON 配置文件

在当前终端已设置 `MODEL_API_KEY` 的前提下，可直接指定服务：

```sh
./agent-check \
  --url 'https://model.example.com/v1' \
  --model 'replace-with-your-model' \
  --protocol chat-completions \
  --no-gui \
  --report-dir ./results
```

请替换地址和模型名。使用 `--config` 时，地址和模型从配置文件读取；不要同时依赖 `--url` 或 `--model` 覆盖配置。

### 参数速查

| 参数 | 作用 |
| --- | --- |
| `--config <文件>` | 读取模型 JSON 配置 |
| `--url <地址>` / `--model <名称>` | 不使用配置文件时，指定服务地址与模型 |
| `--protocol <协议>` | 指定协议；可覆盖配置文件中的 `protocol` |
| `--no-gui` | 固定在 CLI 中运行；不单独关闭桌面环境下的报告自动打开 |
| `--no-open-report` | 不自动打开 HTML 报告，保留手动查看入口和文件路径 |
| `--json` | 固定 CLI，输出最终 JSON，且不自动打开报告；不与 `--gui` 混用 |
| `--report-dir <目录>` | 指定结果目录，路径含空格时用引号括起 |
| `--no-color` | 禁用终端颜色 |
| `--offline-self-test` | 检查内置组件，不请求模型 |
| `--help` / `--version` | 查看帮助或程序版本 |

密钥通过环境变量或本机私有配置传入，不需要放到命令行参数中。

## 4. 检测内容、报告与退出码

### 检测内容

| 检测项 | 核对内容 |
| --- | --- |
| 接口与响应 | 服务响应与基本输出是否符合检测要求 |
| 工具调用 | 普通工具选择、参数及结果回传，不要求服务端 strict 模式；参数定义和实际结果仍须正确；该项每次请求输出上限 20000 tokens、超时 600 秒，阶段预算 1200 秒 |
| 结构化输出 | 核对 JSON 内容；唯一代码块内字段正确时兼容通过，同时标注原生严格格式未满足 |
| 长上下文 | 可验证的上下文容量；下界不等于已确认最大值 |
| 并发能力探测 | 普通短文本请求，正常结束且有非空正文，不要求 JSON；翻倍升档，平均 ≤ 10 秒、P95 ≤ 20 秒，首次不达标即停止；仅在证据允许时给出粗略建议 |
| 连续工具执行 | 多步工具任务完成情况与实际文件内容 |
| 工具故障恢复 | 收到工具错误后能否恢复并交付正确结果 |
| 多轮继续执行 | 同一会话接受新要求后能否正确继续修改 |

后三项各执行两次，共 6 次任务，按最多 2 个任务并行调度。报告依据本次测试证据生成，不代表所有场景或未来任务均能通过。

并发使用固定普通短文本请求“请用一句简短的中文打个招呼。”，输出预算为 2048 tokens。不要求模型返回 JSON、特定措辞或原样回显；带说明文字的正常回复也可计入。每次请求通过本地保存的 HTTP 证据编号关联，不依赖模型回显随机标识。本项不评价答案质量；JSON 内容与格式由独立的结构化输出项检查。

并发按 1、2、4、8、16、32、64、128… 翻倍增加，32 不是固定停止点。每档只测一轮，全部请求得到有效协议响应、正常结束且正文非空，并且平均响应时间 ≤ 10 秒、P95 ≤ 20 秒才通过。耗时从发出请求到收到完整响应计算，不是首 token 延迟。P95 使用 nearest-rank：将本档耗时从小到大排序，取第 `ceil(请求数 × 0.95)` 个；少于 20 个请求时改用最慢耗时 ≤ 20 秒。等于阈值视为达标。

出现请求失败或响应过慢就停止。若因限流、请求硬超时或响应过慢停止，可保留上一合格档位作为本次负载的粗略建议；若出现空正文、截断、拒绝、未请求的工具调用、无效协议响应、连接错误、普通服务错误或证据冲突，则容量边界未确认，不据此生成建议。例如 16 并发通过，32 并发全部返回但平均 12 秒，结论仍为“建议并发 16”，并标明响应过慢。若连 1 并发都不达标，则不给出建议。报告保留各档成功数、失败数、平均、P95 / 小样本最慢及不达标原因；响应过慢不会伪装成请求失败。180 秒仅为单请求硬超时，不是性能合格线。不做二分缩小区间或反复确认。

每个请求只尝试一次，缺少 token 用量明细不会阻断探测。若 1 并发也失败，则不给出可用并发建议。鉴权错误、取消或保护预算触发时保留已有结果，标明未完成。默认保护预算为 100,000 个并发探测请求、32 轮和 60 分钟，另受本机连接资源约束；保护预算不是服务上限。可按 Ctrl+C 取消并保存已有结果。

建议值是本次账号、网关、网络和固定普通短文本负载下，满足请求完成率与响应时间标准的粗略可用档位，不是答案正确率或服务精确极限。这组耗时标准不用于长上下文或真实智能体任务；部署、配额和负载变化后可重测。0.4.0 及以前的 JSON 回显记录保留原负载与原结论，不按新标准重新判定，也不能直接拿新旧负载的档位作同条件比较。

结构化输出的“兼容通过”要求代码块内的数据和字段均正确；字段缺失、内容错误、无效 JSON 或多个候选代码块仍不能通过。接入方若只接受原生 JSON，仍需落实报告中的格式兼容建议。

“通过”表示已取得本项通过证据；“未通过”表示已确认问题；“未确认”表示证据不足、受阻或未完成；“未执行”表示尚未运行。服务异常、用量字段缺失或取消，不应被直接理解为模型能力失败。

报告正文分为“检测结论、检测结果与基线对照、使用建议”三个章节。功能结果和性能数据只展示一次；没有真实、可比的参考数据时不显示空对照列。通过项的使用建议不等于检测失败，主表可筛选全部、含建议、未通过，以及存在时的未确认/未执行项目。

页尾“检测记录与技术附件”默认折叠，按要求展示证据有效性、满足情况和引用。可点击原始文件链接，或从 ZIP 中按索引路径查找；单独移动 HTML 后应使用 ZIP 内的文件。`result.json` 保存本次注册计划、逐项裁决、兼容条件与总评依据。新记录保存检测程序版本；旧记录缺失版本时显示未记录，不冒充当前版本。SHA-256 用于核对文件完整性，不代表服务自报计量或模型身份已获第三方认证。旧版结果保留生成时的结论，不按新规则自动重判。

### 文件位置

使用本手册命令时，结果保存在解压目录的 `results` 下：

```text
results/
  startup/                 连接检查记录
  AC-日期时间-唯一编号/
    result.json            本次结构化结果
    report.html            本次 HTML 报告
    records.zip            本次检测记录压缩包
    evidence-index.json    证据编号、相对路径、大小及 SHA-256
    observations/          各检测项的原始观察
    ...                    请求证据与任务文件
```

不指定 `--report-dir` 时，默认目录为 `~/Library/Application Support/AgentCheck/results`；若设置了 `AGENTCHECK_DATA_DIR`，则使用该目录下的 `results`。默认组件缓存为 `~/Library/Caches/AgentCheck`。

桌面 GUI 在检测正常结束并保存报告后自动打开 HTML，无需手动查找；macOS/Windows 本机交互式 CLI 同样会请求默认应用打开。未通过或未确认也会打开报告供核对，主动取消不弹窗。SSH、CI、非交互终端、Linux 和 `--json` 模式仅保留路径；`--no-open-report` 可在其他场景关闭自动打开。打开失败不会改变检测结论，仍可手动查看已保存的 HTML。

PDF 不自动生成，也不会随 HTML 一起弹出。报告支持浏览器打印 / 保存 PDF，以及下载内嵌的真实检测记录 ZIP。打印包含完整检测摘要，不因当前筛选遗漏项目，也不自动展开全部技术证据。本机 Chromium 已验证这些行为；其他浏览器的显示或下载受限时，可直接取结果目录内的 `records.zip`。脚本关闭时正文仍可阅读，但交互和浏览器内下载不可用。

反馈建议提供检测编号、`result.json` 与相关日志；记录可能包含服务地址、模型输出和任务路径，发送前按客户要求检查内容。不要发送 `model.json` 中的真实密钥。

### CLI 退出码

| 退出码 | 含义与处理 |
| --- | --- |
| `0` | 本次检测通过 |
| `1` | 有已确认的未通过项；查看报告中的具体原因 |
| `2` | 检测未完成或启动错误；结合日志区分配置、服务与运行环境问题 |
| `130` | 正式检测阶段响应用户取消；查看已保存的结果 |

以上为正式 CLI 检测语义；离线自检成功也返回 `0`。连接检查阶段取消由启动错误路径返回 `2`。GUI 交接成功的入口退出码仅表示界面启动，不代表检测结论。

## 5. 常见问题与反馈

| 现象或错误 | 常见原因 | 处理方法 |
| --- | --- | --- |
| `Permission denied` | 可执行权限丢失，或目录不可写 | 对程序执行 `chmod +x ./agent-check`；结果目录改为当前用户可写位置 |
| `bad CPU type` / 无法执行此文件 | 操作系统或架构不匹配 | 确认使用 M 系列 Mac；向交付方获取对应平台构建 |
| macOS 安全策略阻止启动 | 本候选版未签名、公证，或组织策略限制 | 联系交付方或组织 IT 处理签名/分发要求；本手册不要求关闭系统安全机制 |
| 配置不是有效 JSON | 中文引号、尾逗号或字段类型错误 | 对照模板修正，使用 UTF-8 纯文本保存 |
| 密钥环境变量未设置 | 当前终端未设置变量 | 重新执行第 2 节第 4 步，并在同一终端运行检测 |
| API 密钥未通过验证 | 密钥错误、已过期或无模型权限 | 核对密钥与服务授权；检查是否误用了其他网关的密钥 |
| 模型或接口地址不存在 | 模型名称、网关路径或协议错误 | 核对 `base_url`、`model` 和 `protocol` |
| 无法连接模型服务 / 请求超时 | 网络、代理、证书或服务状态异常 | 核对当前终端到服务的访问条件，并联系服务管理员确认状态 |
| 限流或服务错误 | 额度、并发限制或网关异常 | 检查服务侧日志、额度和并发权限，修复后重跑 |
| 结果目录已有检测运行 | 同一结果根目录有正在执行的检测 | 等待当前检测结束或正常取消，避免删除锁文件强行并行 |
| 并发显示未确认 | 单请求失败、配置受阻，或探测被取消、预算不足 | 查看逐档记录；token 用量缺失不会阻断此项 |
| 上下文最大值待确认 | 大请求超时、计量缺失或还未找到容量边界 | 保留已验证下限；超时不代表已找到最大容量 |

本包不包含客户配置、真实密钥或交付方的历史检测记录。软件内置组件的许可文件位于 `licenses/`，请随程序保留。

完成测试后，可在当前终端执行 `unset MODEL_API_KEY` 清除该环境变量。反馈时说明操作系统版本、芯片、启动命令（不含密钥）、检测编号和错误文本。

**下一步：进入解压目录，先运行 `./agent-check --offline-self-test`（约 5–30 秒）。**
