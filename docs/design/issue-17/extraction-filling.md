# 信息提取与结构化填写：题库与评分设计

父任务：#17。类型：设计。版本：0.1，2026-09-09。

既定方向是信息提取与结构化填写。下文为本次设计方案，不是已执行结果；本任务不实现检测器、运行模型或开展验收。

## 客户问题与边界

模型能否从材料中找到正确字段，分清对象和关系，并且不遗漏、不编造？#16 检查结构能否生成，本项检查结构中填的内容是否正确。两者可以复用证据，不把同一失败重复记为独立事故。

## 评分设计

主指标为整条记录完整正确数 / 已评分有效记录数。诊断项分别呈现字段准确情况、漏填、错填、无依据填写和对象串值，不将字段数更多的题通过隐性权重放大。

每题事先列出所有应检查字段和期望状态：有值、明确未知、明确为空、不适用。字段分母由题目固定，不只统计模型填写出来的字段；额外编造字段另记违规。若原始输出无法按既定接口/格式解析，该有效作答不满足整题正确；格式问题与值错误分别解释。

日期、金额单位、大小写、实体别名和数组顺序的允许归一化必须预先定义。不能为挽救个别模型输出临时改规则，也不因正常等义值表达而误扣分。结构化输出可用模式作为固定条件记录，不静默切换 JSON 模式来获得更好成绩。

## 说明样例（原创，非正式题库与实测）

材料：“订单 A 的联系人为小林，订单 B 的金额为 200 元；未给出订单 B 联系人。”要求只填写 B 的金额和联系人，未知联系人用 `null`。

| 回答                                | 预期解释                                                          |
| ----------------------------------- | ----------------------------------------------------------------- |
| `{"amount":200,"contact":null}`     | 完整正确。                                                        |
| `{"amount":200,"contact":"小林"}`   | 对象串值，并且无依据填写。                                        |
| `{"amount":200}`                    | 缺少题目要求的未知状态字段。                                      |
| `{"amount":"200元","contact":null}` | 按该题预先固定的金额字段类型和归一化规则判断，不临时宽松处理。    |
| 有效回答包含非法 JSON               | 整题不正确；与 #16 的格式证据关联，不自动诊断所有字段内容均错误。 |
