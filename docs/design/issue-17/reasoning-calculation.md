# 逻辑推理与计算：题库与评分设计

父任务：#17。类型：设计。版本：0.1，2026-09-09。

本项只设计题型、答案与成绩口径，不运行模型或评分器，不开展验收。

## 客户问题与边界

模型能否依据给定事实和规则得出正确结果？首版面向基础业务推导，不增加编程、专业知识问答或高难竞赛类别，不要求公开内部思维链。

## 首版子项与题量方案

| 子项       | 题型方向                                     | 初始设计数量 |
| ---------- | -------------------------------------------- | ------------ |
| 条件判断   | 按已给规则判断是否满足条件，覆盖边界值。     | 8 题         |
| 时间与顺序 | 根据明确先后关系或日期排序，不依赖当前日期。 | 8 题         |
| 数量比较   | 比较数量、差值及明确单位的数值。             | 8 题         |
| 基础计算   | 给定数据的加减乘除、比例与简单统计。         | 8 题         |
| 多条件推导 | 组合少量明确规则，含信息不足或无解情况。     | 8 题         |

共 40 题，每题 1 份计分回答。题目明确单位、精度、舍入方式和时间基准；答案不依赖联网或现实常识补充。数量是设计起点，不称为普遍能力保证。

## 来源与选用

研究 [BBH 固定快照](https://github.com/suzgunmirac/BIG-Bench-Hard/tree/9ee07bd481feebf959a6b59d61ea57bdcf30964d) 中贴近本范围的逻辑、顺序和计算任务，并参考 [DROP 作者论文](https://aclanthology.org/N19-1246/) 的材料计算方向。

BBH 是挑战性任务集合，不能把它的全部类别或成绩门槛直接映射成业务适用性。本设计优先取方法和贴近用途的子项；不纳入本产品范围外的语言谜题、编程或专业知识。仓库根许可不替代上游任务数据使用条件；DROP 本轮只研究论文，数据与评分脚本未作最终选用。

原版题、抽样子集、中文翻译和原创业务题分别记录身份。若改提示、答案抽取、是否展示推导或问题内容，就不得以原版完整 BBH/DROP 名义报告成绩。

## 评分设计

主指标为结果完整正确题数 / 已评分有效题数。数值按题目固定的单位与容差核验，集合或排序按允许表达验收；没有预先约定时不得随意宽松匹配。

答案、单位和必要条件均正确才算整题正确；合法等义表达不扣分。过程解释仅在题目明确需要时核验可观察的关键步骤，不索取或评价隐藏思维链，不因文字更长加分。

模型明确给出错误数值、违反题设约束或在信息不足时编造答案，属于有效错误。未取得可用响应、题目本身无唯一答案却未声明等属于不同原因，不能混入同一错误分母；题目缺陷需留存并按版本修正所有受影响成绩。

## 说明样例（原创，非正式题库与实测）

题目：“物品单价 25 元，买 3 件，满 70 元减 10 元，无其他费用。实付多少元？”

| 回答             | 预期解释                                 |
| ---------------- | ---------------------------------------- |
| “65 元”          | 正确。                                   |
| “人民币六十五元” | 合法等义表达。                           |
| “75 元”          | 漏用折扣条件。                           |
| “60 元”          | 计算或条件应用错误。                     |
| “需要知道运费”   | 题目已明确无其他费用，不能借此回避作答。 |

- 正确、错误、合法替代、缺失信息与无效执行说明样例。
