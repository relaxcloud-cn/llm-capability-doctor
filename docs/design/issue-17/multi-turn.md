# 多轮对话与条件承接：题库与评分设计

父任务：#17。类型：设计。版本：0.1，2026-09-09。

本任务只设计题库、状态答案和分类成绩。不运行对话、不选定模型裁判、不实施验收。

## 客户问题与边界

对话继续时，模型是否保留有效条件、接受新条件、放弃过期条件，并区分对象？不同于 #16 的最小历史接收，本项考查条件变化后的回答正确性，不考服务自动记忆，也不搭建 Agent 环境。

## 首版子项与题量方案

| 子项         | 对话变化                               | 初始设计数量 |
| ------------ | -------------------------------------- | ------------ |
| 追问与补充   | 在原目标上增加明确事实或继续追问。     | 8 段         |
| 条件修改     | 日期、数额或要求被更新，后续使用新值。 | 8 段         |
| 条件撤销     | 撤回某个限制，不保留已经无效的条件。   | 8 段         |
| 对象切换     | 两个对象之间来回询问，条件不串用。     | 8 段         |
| 保留未变要求 | 修改一个条件时，其他要求仍应保持。     | 8 段         |

合计 40 段，每段 3 个用户回合和对应模型回答。计分单位是完整对话，不把 120 个回合冒充 120 个独立对话样本；语言由父任务确认。

## 来源与选用

参考 [Multi-IF 代码快照](https://github.com/facebookresearch/Multi-IF/tree/1cdb53ed18499ad729e0766e5d3099dd5344406f) 的多轮指令评估，以及 [SGD](https://github.com/google-research-datasets/dstc8-schema-guided-dialogue/tree/e852981ae34990f4358979625854259302feaa78) 的状态标注思路。

Multi-IF 代码 README 声明 Apache-2.0，而 [作者数据卡](https://huggingface.co/datasets/facebook/Multi-IF) 标注 CC BY-NC 4.0。两者分别记录，不以代码许可推定数据可随产品分发；本方案暂不将其原始数据设为默认分发题库。SGD 数据条件也需独立处理。

初始设计采用原创、受控的条件变化说明样例；是否进一步选取外部实际样本须另记原版/改编身份和使用条件。不能只因来源名叫“多轮”就宣称已覆盖条件撤销和对象切换。

## 评分与对话组织

每一轮有预先固定的有效事实、当前约束、已撤销条件和期望答案范围。主指标为连续各轮均正确的完整对话数 / 已评分有效对话数；逐轮正确情况和首次偏离轮次只作诊断。

后续请求携带实际模型历史，不用标准答案悄悄替换它的上一轮回复。期望状态由题目事实和用户更新决定，模型上一轮的错误不应成为下一轮的“正确事实”。用户脚本不依赖模型随机措辞；需要条件分支时，分支与评分必须预先设计。

如果尚未观察到有效错误但对话因执行异常未完成，整段结果无法确定，单列未完成。若已观察到有效错误，则整段已经不可能连续全对，仍计为错误，后续异常不能把它移出错误分母；同时保留未完成标记。完成程度与对错是两个维度，不只保留走完的优秀对话来宣称全量成绩。

## 说明样例（原创，非正式题库与实测）

| 回合 | 用户信息                                                    | 期望有效状态                                 |
| ---- | ----------------------------------------------------------- | -------------------------------------------- |
| 1    | “项目 A 预算 100 元，负责人小林。”                          | A：100 元、小林。                            |
| 2    | “A 的预算改为 120 元，负责人不变。另有项目 B，预算 80 元。” | A：120 元、小林；B：80 元、负责人未知。      |
| 3    | “分别列出 A、B 的预算和负责人。”                            | 不沿用 A 的旧预算，不把小林填成 B 的负责人。 |

最后一轮答对但中间存在有效错误的对话，不计为连续全对。等义表达根据固定答案规则允许，不按句子完全一致机械判错。

## 设计交付

- 40 段三回合对话的变化类型、状态表、脚本与语言规格。
- 整段和逐轮诊断的分母、历史组织与缺测规则。
- 条件修改、撤销、对象混淆、等义答案及中断的说明样例。
- 仅回填设计到 #17，后续实现与测试由其他任务负责。
