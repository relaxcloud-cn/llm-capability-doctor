# 长材料理解与信息利用：题库与评分设计

父任务：#17。类型：设计。版本：0.1，2026-09-09。

本任务只设计长材料任务与成绩表达，不探测上下文容量，不调用模型或执行测试。

## 客户问题与边界

材料变长后，模型是否还能找到、关联和正确使用信息？#16/#38 负责最大上下文；本项只在已有可靠输入范围内观察答题表现。若总窗口尚未测出，但已有可信输入下界，可仅使用下界内的长度，不重新进行容量探测。

## 首版子项与题量方案

| 子项         | 固定考查目标                               | 基础任务数 |
| ------------ | ------------------------------------------ | ---------- |
| 分散事实查找 | 从多个位置找出指定事实，覆盖前中后位置。   | 8 题       |
| 跨段关联     | 连接明确关联的对象与属性，不依赖外部知识。 | 8 题       |
| 信息汇总     | 汇总预先确定的事实集合，检查遗漏和多报。   | 8 题       |
| 干扰排除     | 正确信息与相似但不相关材料同时出现。       | 8 题       |
| 信息缺失识别 | 材料未提供答案时不编造。                   | 8 题       |

40 个基础任务，每个任务扩展到最多 3 个可用长度档。最多 120 次长度条件观察，不冒充 120 个独立基础任务。初始档位提案为参考计数下 4K、16K、64K token；不适用档位明确未测，不强行发送超范围请求。

## 来源与选用

参考 [NVIDIA RULER 固定快照](https://github.com/NVIDIA/RULER/tree/c3f5e3b4f87f97e048793bb510a3a6b19a46bf3a) 的可控长度、检索、关联和汇总任务方法。已读取 README 和根许可证；代码许可不能代替其外部语料或问答数据的使用条件。

设计优先采用受控合成材料与可固定答案的任务，不默认打包作者脚本可下载的文章或外部问答集。若更换材料、语言、任务模板或长度，不声称原版完整 RULER 成绩。作者的有效长度或榜单阈值不是本产品容量上限，也不是服务可用性门槛。

## 可比条件设计

同一基础任务在各长度档保持答案、推理步数和关键事实数量相同，只按固定规则增加干扰材料与改变位置。位置方案、材料哈希和种子预先固定，不随着模型表现改题。

跨模型比较优先使用同一材料文本和题目 ID，同时记录参考计数、被测服务实际计数及输入余量。不同 tokenizer 的同名 token 档不天然等价；不把各模型各自重建的不同材料当成严格同题比较。

只比较共同可用的长度与任务集合。较小模型未覆盖的大档位单列，不记为 0 分，也不把较大模型的长档与较小模型的短档直接相减排名。

## 评分设计

按长度分别显示完整正确题数 / 已评分有效题数，并列事实遗漏、多报、关联错误和干扰误用。若某题只要求一个答案集合，按预先固定的集合等价规则；不要求同样的解释文字。

同题不同长度可给出变化趋势，但不把所有长度平均成一个隐含容量分或全局总分。没有足够有效题目时突出覆盖缺口。不能因短档表现差就事后删除该题来提高长档成绩。

## 说明样例（原创，非正式题库与实测）

材料中分别给出“项目 R 的负责人是小周”和“小周所在团队为 T2”，并插入固定的无关项目记录。题目询问 R 的团队。

正确答案为 T2。把负责人同名的另一条记录错连到 R 属于关联错误。三个长度档保持这条两段关联关系不变，不额外增加推理步骤。缺失关键关系的变体应承认信息不足，不猜团队。
