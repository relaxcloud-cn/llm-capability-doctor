# 文本理解与指令执行：题库与评分设计

父任务：#17。类型：设计。版本：0.1，2026-09-09。

六类能力范围来自 #17；下文具体题量、子集和评分是本次设计方案，不冒充已实测或用户逐条确认。本任务只产出设计文档与说明样例，不安装执行器、不调用模型、不实施验收。

## 客户问题与边界

模型能否读懂所给材料，并完整满足明确要求？结果分别解释“内容答对没有”和“要求执行完整没有”。不重复 #16 的 JSON/消息接口支持检查，不生成整体可用性结论。

## 首版子项与题量方案

| 子项             | 题型方向                                           | 初始设计数量 |
| ---------------- | -------------------------------------------------- | ------------ |
| 材料事实理解     | 从短材料中回答有确定依据的问题，区分已知与未提供。 | 8 题         |
| 条件筛选与归纳   | 根据明确条件选出对象或必需事实，避免主观文风评分。 | 8 题         |
| 单项输出要求     | 指定字段、列表项数、必须包含或禁止包含的内容。     | 8 题         |
| 多项要求同时满足 | 内容正确同时满足两项以上明确约束，逐条记录。       | 8 题         |
| 信息不足处理     | 无材料依据时承认缺失，不补造事实。                 | 8 题         |

合计 40 题，每题首轮生成 1 份回答，不从多次生成中挑最好的一次。数量为产品设计起点，不声称具有统计代表性；语言在父任务统一确认后冻结。

## 来源与选用

优先参考 [IFEval 作者目录](https://github.com/google-research/google-research/tree/e6890f85757dd84e27ca6df2dd30651dafad28e0/instruction_following_eval) 的可验证指令和逐指令/整题计分。已读取该快照的 README 和 `evaluation_lib.py`；其严格与宽松评估是不同口径，不能只报较高者。

材料理解补充参考 [DROP 作者论文](https://aclanthology.org/N19-1246/) 的基于材料作答方向，但本轮不据论文就批准数据分发。数据、评分脚本和各自使用条件尚须记录后才能选题。

本产品若抽样、翻译、增加材料或改变验收，则使用自己的题库名称和版本，标注“参考/改编”，不报完整 IFEval 或 DROP 官方成绩。中文字符、词数、大小写等约束不能机械照搬英文规则。不得把只测格式的结果包装成文本理解能力。

## 评分设计

主指标为“整题完整正确数 / 已评分有效题数”，整题必须同时满足内容答案与所有必需约束。详情分别列内容正确率、逐约束满足率及典型错误，不加权混成另一总分。

题目预先给定答案集合、必需事实点、合法别名、顺序规则及缺失信息处理。格式无关的同义表达允许通过；在明确考格式的子项中仍按约束评分。自然语言表达存在未覆盖歧义时记待评分，不默认为错或自动剔除以提高成绩。

对于完全原创的约束题，本设计以原始回答的严格规则为主；若采用 IFEval 宽松口径，只能另列诊断项并明确改写方式，不能覆盖主结果。不将另一模型一句“答案正确”视为充分裁决依据。

## 说明样例（原创，非正式题库与实测）

材料：“A 项目预算 3 万，B 项目预算 5 万，负责人未提供。”要求：“只列预算超过 4 万的项目；另说明负责人是否已知。”

| 回答                     | 预期解释                                 |
| ------------------------ | ---------------------------------------- |
| “B；负责人未知。”        | 内容和要求均满足。                       |
| “B；材料未说明负责人。”  | 合法等义答案。                           |
| “A、B；负责人未知。”     | 筛选错误。                               |
| “B；负责人李某。”        | 无依据填写。                             |
| 客户端超时未取得有效回答 | 无效执行，不计为内容错误，覆盖缺口单列。 |
