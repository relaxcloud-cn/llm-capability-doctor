# 连续运行稳定性：固定时段观察设计

父任务：#18。模块：模型性能实测。状态：设计草案，2026-09-09。本轮不实现、不实测、不开展验收，不授权持续请求客户模型。

## 目标与范围

回答“在固定负载下连续运行一段时间，是否变慢或错误增多”。重复执行与连续运行归一类，不另加重复成功率类别；完整返回不是业务答案正确，短测不证明生产长期可靠性。

## 客户结果

| 展示内容                         | 口径                                       |
| -------------------------------- | ------------------------------------------ |
| 实际观察时长、负载和请求数       | 计划时长与实际时长分开。                   |
| 每分钟首响/耗时趋势              | 按派发时间归组，终态可在排空阶段补齐。     |
| 每分钟吞吐及错误事件             | 按结束事件时间归组，不与派发队列分母混合。 |
| 完整、错误、超时、取消、长度覆盖 | 保留全部派发请求，不以成功子集代替整轮。   |

不增加稳定性总分、自动合格线或生产 SLA。仅在条件可比时给首尾变化。

## 固定设计

流式输入约 512 token，目标输出 256 token，固定并发 2。预热 2 次并等待完成，正式派发窗 600 s 或 1200 次请求，先到为止；单请求超时 120 s，窗口关闭后最多排空 120 s。

按 60 s 分桶。请求到终态后补齐其派发桶的完整比例与延迟；吞吐按实际结束事件所属窗口统计。派发窗结束仍在途的请求不悄悄从分母删除，排空与取消分别记录。

首尾趋势采用第一个和最后一个完整分钟桶；各自至少 10 个有效请求才计算中位数相对变化，否则仅展示原值、样本数和趋势。缺失或零基值不计算百分比。不把不同输出长度的变化一律归因于服务退化。

不自动重试；429、权限错误及共用保护条件终止继续派发。请求数上限提前达到时报告实际时长，不靠重复循环凑满十分钟。保护停止后的高负载组不自动继续。

## 设计反例

| 观察                 | 预期表达                                       |
| -------------------- | ---------------------------------------------- |
| 运行两分钟就遇到限流 | 显示两分钟及原因，不写“十分钟通过”。           |
| 首分钟样本少于 10    | 不计算首尾百分比退化。                         |
| 末尾请求超时         | 归回派发队列并记录终态，不删除末尾慢请求。     |
| 十分钟没有错误       | 只说明本窗口未观察到异常，不证明长期生产稳定。 |
