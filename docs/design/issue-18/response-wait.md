# 响应等待：正文首响与完整耗时设计

父任务：#18。模块：模型性能实测。状态：设计草案，2026-09-09。本轮不实现、不实测、不开展验收。

## 目标与范围

回答“请求发出后多久开始看到正文、多久完整结束”。区分流式与非流式，不测答案正确性，不把第一个空事件或推理片段当成正文首响。

## 客户结果

| 模式   | 主指标                                 | 辅助信息                                              |
| ------ | -------------------------------------- | ----------------------------------------------------- |
| 流式   | 正文首响中位数/P95，完整耗时中位数/P95 | 有效样本数、完整/派发数、异常数量、实际输入输出长度   |
| 非流式 | 完整耗时中位数/P95                     | 首响显示不适用，不用完整返回时间冒充流式首 token 时间 |

没有业务响应时限时不自动判合格或不可用。原始时间线、环境和请求条件在详情展开。

## 固定设计

输入约 512 token，目标输出 256 token，单并发。流式和非流式分别预热 3 次，各正式派发 40 次；每次总超时 120 s，每模式正式组最多 80 分钟。两种模式保持材料与其他设置一致，明确实际输出并非保证相同。

从交给 HTTP 客户端发送前开始计时，包含连接与服务链路，不包含调度器排队。流式以第一个包含非空白正文字符的片段定义正文首响；角色、空值、纯推理都不提前结束等待计时。

完整耗时截至正常完成证据和响应消费结束；失败或超时保留终止耗时，不混入成功分布。非流式不反推不可观测的首 token 时刻。

输入/输出档位、token 来源、预热、百分位和停止规则采用共用稿。任务短答单列长度覆盖，不删去失败获得更好延迟。

## 设计反例

| 观察                       | 预期表达                                   |
| -------------------------- | ------------------------------------------ |
| 先空事件，再推理，最后正文 | 主首响从正文到达计算，其余事件作为详情。   |
| 首字很快，但最终超时       | 保留已观察到的首响和超时，不算完整成功。   |
| 仅 12 个有效请求           | 展示中位数、范围和样本数，不展示请求 P95。 |
| 非流式 2 s 返回            | 完整耗时 2 s，不声称首 token 为 2 s。      |
