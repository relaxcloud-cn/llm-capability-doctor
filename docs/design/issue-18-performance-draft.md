# 模型性能实测设计草案

版本：0.1。日期：2026-09-09。父任务：[#18](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/18)。

本轮只做设计：沿用父任务已确定的五类范围，补齐客户结果、指标口径、有限负载与异常表达。不开发执行器、不安装候选工具、不请求客户模型、不启动压测或验收。以下数值是本产品首版设计方案，不是官方推荐、已校准阈值或对客户服务施压的授权。

### 1.1 不测什么

不探测最大上下文、最大输出长度或最大用户容量，不评答案正确率或 Agent 任务水平，不设性能总分。不增加缓存对比、突发恢复、硬件监控、费用预算或未确认的业务时限指标。

默认只设计文本 Chat Completions 性能场景。工具调用的功能性流式支持已归 #16/#40，本轮不擅自增加工具执行或 Agent 全流程耗时场景。

### 1.2 与 #16、#17 的边界

| 情况                                   | 本模块处理                                                                     |
| -------------------------------------- | ------------------------------------------------------------------------------ |
| 上下文最大值尚未测出，但有可靠输入下界 | 在已验证可接收范围内选长度档，不要求先得到精确总窗口，也不在本模块继续搜上限。 |
| 没有最大输出量结论                     | 仅选择预先指定的有限输出任务并记录实际长度，不把长度控制参数测试重新加回来。   |
| 流式能力不具备或尚未确认               | 流式子项显示不适用或前提未确认；非流式请求耗时单独保留，不伪造流式速度。       |
| 输出很快但任务答错                     | 性能记录不替代 #17 成绩；长度是否达标与内容质量分开。                          |
| 同一请求被多个模块引用                 | 复用证据 ID，不重复统计成独立请求或独立事故。                                  |

## 2. 客户结果结构

主视图用“数值 + 条件 + 异常数量”，不用规格项的通过/未通过直接替代性能数值。没有客户已确认的响应要求时，不自动给出“合格”“不合格”“服务不可用”。

| 示例行     | 示例主结果                                  | 条件摘要                                                      |
| ---------- | ------------------------------------------- | ------------------------------------------------------------- |
| 响应等待   | 正文首响中位数 0.8 s；完整耗时中位数 5.2 s  | 流式，单并发，512 输入/256 目标输出 token；完整 38/40，超时 2 |
| 生成流畅度 | 块间隔 P95 为 90 ms；最大间隔 1.4 s         | 同一长度组；有效间隔数与请求数分开展示                        |
| 并发 4     | 完整吞吐 0.8 请求/s；超时 3，限流 2         | 实际并发与窗口可展开，不称支持 4 个用户                       |
| 连续运行   | 已观察 10 分钟；完整 186/190，异常 4        | 并发 2；按分钟展示趋势，不称长期可靠                          |
| 长输出     | 目标 2048 token，实际中位数 1610，达标 4/15 | 标注长度覆盖不足，不能当作 2048-token 速度成绩                |

以上均为虚构展示值，不是模型实测。状态分为完成、部分完成、已停止、未执行；适用性另记，不能因没有样本而显示零延迟或零错误率。

## 3. 指标字典

### 3.1 时间线

计时均使用同一客户端单调时钟，单位内部统一为秒；报告等待和总耗时用秒，块间隔用毫秒。连接复用、客户端位置、代理路径和软件版本作为环境条件记录。

| 时间点          | 设计定义                                                                                         |
| --------------- | ------------------------------------------------------------------------------------------------ |
| `t0`            | 请求获得并发槽位后、交给 HTTP 客户端发送之前；包含该次连接和服务链路等待，不包含测试调度器排队。 |
| `t_first_event` | 第一个完整协议事件可供解析时；仅用于详情，不叫正文首响。                                         |
| `t_reasoning`   | 第一个可识别的非空推理片段到达；仅在接口可区分时记录。                                           |
| `t_body`        | 首个包含非空白字符的正文片段到达；此前只有角色、空值或推理片段不触发。                           |
| `t_last_body`   | 最后一个非空正文片段到达，包括正文中有意义的空白片段。                                           |
| `t_end`         | 正常完成证据齐备且响应消费结束；不得将首字节或最后一个正文块自动当作完整结束。                   |
| `t_terminal`    | 请求失败、取消或超时时的终止点；不作为成功 `t_end`。                                             |

无流式时只能观测整份正文及完整结束，正文首响不填为零或推算值。推理与正文混在无法识别的字符串中时，报告“首个文本”，不擅自宣称已测纯正文首响。

### 3.2 指标与公式

| 指标                  | 计算口径                                               | 样本与限制                                                         |
| --------------------- | ------------------------------------------------------ | ------------------------------------------------------------------ |
| 正文首响              | `t_body - t0`                                          | 完整成功请求为主统计；失败请求已观察到的首响单列，不混入成功分布。 |
| 完整请求耗时          | `t_end - t0`                                           | 只对完整结束请求计算；超时耗时和失败终止耗时单列。                 |
| 首响后的正文输出时段  | `t_last_body - t_body`                                 | 至少两个不同到达时刻；不是服务端 GPU 解码耗时。                    |
| 正文块间隔            | 相邻非空正文片段的到达时间差                           | 一个协议内容片段是一块；不以 TCP 分包或单个 token 为单位。         |
| 最大停顿              | 单请求正文块间隔的最大值                               | 无足够块时缺失，不填 0；首响等待、正文后的收尾等待另记。           |
| 单请求正文字符速率    | 首个有效正文块之后新增的 Unicode 码点数 / 正文输出时段 | 排除首块及其前缀字符；单位字符/s，不等同于字节、token 或汉字数。   |
| 单请求正文 token 速率 | 首块之后实际新增的可见 token 数 / 正文输出时段         | 仅当具有可信且可分离的区间 token 计数；不得默认首块只有 1 token。  |
| 含等待的正文产出率    | 全部可见 token 数 / 完整请求耗时                       | 计数可靠时可单列，名称必须保留“含等待”，不得替代生成阶段速率。     |
| 完整请求吞吐          | 统计窗内完整结束请求数 / 统计窗秒数                    | 未结束、错误和超时不计完整量；属于系统量，不代替单请求速度。       |
| 完整返回比例          | 同一派发队列最终完整结束数 / 实际派发数                | 按派发队列追踪到结束；与窗口吞吐分母分开。                         |

token 来源优先使用语义已核实的服务端计数，或与服务 tokenizer 对齐后的本地整串计数。保留原值、来源与版本；不能把字符数、内容块数、混合推理的 completion 总量冒充正文 token。对各片段单独分词后求和可能与整串不一致，不以此伪造区间计数。

无法取得可靠 token 数时，展示字符速率和块间隔，tokens/s 留空并说明原因。不臆测隐藏推理 token 的时间位置。

### 3.3 聚合

每个接口模式、长度和负载组合独立聚合。请求级指标按请求统计，事件级间隔同时标明间隔数和请求数；不能把长响应的许多片段冒充许多独立请求。

请求数量不足 40 时展示中位数、最小值、最大值及样本数，不展示请求 P95；达到 40 时增加 P95。分位数使用排序后的最近秩法 `x[ceil(p*n)]`（1 起始），不是可靠性保证或置信区间。零样本显示无数据。首响、总耗时、速率使用各自有效分母，不默认数量相同。

全局块间隔分布与“每请求最大间隔”的分布分开。后者用于避免少数长响应占据全部流畅度统计。单块响应显示“无可计算间隔”，不称完全没有停顿。

## 4. 固定负载方案 v0.1

### 4.1 输入与输出材料

输入采用固定版本的虚构文本与请求 ID；核心任务保持简单，输出采用编号条目或固定材料续写，避免长推理。为每个长度档预先制作材料，输入长度含消息正文与已知封装开销，误差目标为名义值的 ±5%。不将随机 nonce 当作已经排除服务端缓存的证据。

输出长度是任务目标，不保证模型刚好生成这些 token。实际正文长度达到目标的 80%–120% 记为该目标档“长度达标”；这是设计分组容差，不是能力分数。正常但短答、自然提前结束、达到上限而截断、异常断流分别记录。超出范围的正常输出保留在全请求记录中，不混入目标长度档速度比较。

输出请求设置在同一对照组固定且记录。不得为了让某次请求达到目标临时改参数重测并覆盖原记录。选用有限长度不等于测试最大输出或参数生效。

### 4.2 负载矩阵

下列 token 档仅在计数可靠且输入范围已验证时启用；不能核实的档位标为前提不足，不悄悄按字符数替代 token。

| 类别/组      | 输入/目标输出 token                                          | 并发            | 预热                   | 正式测量与上限                                               |
| ------------ | ------------------------------------------------------------ | --------------- | ---------------------- | ------------------------------------------------------------ |
| 响应等待     | 512 / 256                                                    | 1               | 每种模式 3 次          | 流式、非流式各 40 次，固定次数；各最多 80 分钟               |
| 速度与流畅度 | 512 / 1024                                                   | 1               | 3 次                   | 流式 40 次，最多 80 分钟                                     |
| 并发承载     | 512 / 256                                                    | 1、2、4、8 逐档 | 每档并发数个请求，一轮 | 每档派发窗最多 120 s 或 300 次，先到为止，之后最多排空 120 s |
| 连续运行     | 512 / 256                                                    | 2               | 2 次                   | 派发窗 600 s 或 1200 次，先到为止，之后最多排空 120 s        |
| 长材料       | 2048、8192、32768 / 256                                      | 1               | 每档 3 次              | 每档 15 次，最多 30 分钟                                     |
| 长输出       | 512 / 1024、2048                                             | 1               | 每档 3 次              | 每档 15 次，最多 30 分钟；已有相同条件观测可引用但不增样本   |
| 历史增长     | 4、16、32 条 user/assistant 消息，每条约 128 token，输出 256 | 1               | 每档每种形态 3 次      | 每档历史形态与等总输入长度的平铺形态各 15 次，各最多 30 分钟 |

每个配置只执行一轮以上固定窗口，默认无自动重复整轮。历史组为交替消息并追加同一当前问题；不是 32 次串行 Agent 执行。平铺对照保持总输入 token、材料与输出目标一致，用来区分长度与消息组织影响。

单请求总超时 120 s；各固定次数组最大时长覆盖最慢超时情形，不是性能合格线。某档不适用就跳过并写明原因，不重新搜容量或用较短任务冒名替代。若 1024/2048 目标长期达不到，仍保留长度覆盖结果，不开展最长输出检测。

### 4.3 调度与窗口

并发使用闭环在途请求数控制：启动最多 C 个请求，结束一个才补一个；不承诺固定请求/s。记录在途并发时间曲线、实际平均并发、峰值、达标时段及客户端调度空隙。客户端发不满 C 时标记实际负载不足，不把它当成服务在目标负载下的成绩。

预热请求与正式请求不重叠，单独记录且不进入正式分母；预热失败也保留。预热一轮结束后重置统计时钟。并发档之间固定空闲 10 s，并记录顺序；不称已消除热状态或缓存影响。

派发窗口在开始后的时长或请求数上限处关闭。请求数上限提前达到时，以实际窗口计算吞吐，明确未覆盖完整设计时长。停止派发后的排空阶段单独计时，不能把排空完成的请求加入之前窗口的吞吐分子。

所有已派发请求保留到终态；排空期限后的未完成请求取消并记录。派发队列完成比例用包括排空的终态核算，吞吐只用窗口内完成事件核算，二者不得互换分母。

### 4.4 异常与停止

性能请求默认不自动重试，避免重试掩盖错误或改变负载；不继承 #16 工具调用的“失败两次复核”。需要复测时建立新轮次并完整保留原轮。

| 触发                                                                         | 设计动作                                         | 对客户的含义                                               |
| ---------------------------------------------------------------------------- | ------------------------------------------------ | ---------------------------------------------------------- |
| 单请求超时、5xx 或异常断流                                                   | 记录终态，在未触发保护停止时按原闭环补位         | 纳入异常数量，不计快速成功。                               |
| 401/403 或调用权限明确失效                                                   | 立即停止该服务后续性能派发                       | 接入阻断，不归为速度差。                                   |
| 出现 429 限流                                                                | 关闭当前档派发；保留并排空在途；不继续更高并发档 | 遇到服务限流，不直接等于算力极限；不自动补发。             |
| 按终止时间连续 5 次服务/网络失败，或至少 20 次请求已到终态后异常比例达到 20% | 保护停止当前档，不自动升级负载                   | 异常比例分母为当时已到终态请求；这是保护阈值，不是通过线。 |
| 用户停止、客户端故障或记录丢失                                               | 停止后续派发，记录取消与已取得事实               | 不能归咎于模型，也不能把部分测试写成已完成。               |

同一服务触发权限、限流或保护停止后，不自动开启后续并发/持续运行组。该限制是执行设计边界；本轮不实现调度器，也不设计恢复交互。

## 5. 长度与异常的两层统计

完整返回不等于达到目标长度，更不等于业务答案正确。每条请求分别记录传输/协议终态、实际长度、目标档达标状态；正常结束但短答仍是正常返回，不得从总分母删除。

全请求视图显示全部派发、完整、错误、超时、取消与长度覆盖。目标长度性能视图只比较该档达标且完整返回的请求，同时显示入组数量、未入组原因和实际长度分布。

如 40 次中只有 4 次达到目标，不能只显示这 4 次的漂亮速度。页面显著标为“长度覆盖不足”，并展示 4/40；不据此宣称目标长度下的稳定性能。

## 6. 连续运行与比较规则

连续运行以每 60 s 一个桶展示窗口内完成吞吐及终态事件；另按派发时间桶核算请求的最终完成比例和延迟，排空阶段补齐终态。两套时间归属在数据中分开，末尾未结束请求不从错误分母消失。

趋势比较使用首个和最后一个完整分钟桶，显示各自样本数与相对变化；任一桶不足 10 个有效请求时只画原始趋势，不给百分比变化结论。中位数为零或缺失时不做除法。不画跨长度、跨配置混合的单一速度线。

并发曲线展示各档正文首响、总耗时、单请求速率、窗口吞吐、异常和实际负载。最高已测档只叫最高已测档。短测无异常只叫本窗口未观察到异常，不推导生产可靠性。

已阅读 NVIDIA AIPerf 固定版本的指标说明，仅做文档适用性研究。未安装、运行、完成版本选型或验证本产品映射。

| 候选可复用部分                     | 本产品需要明确的差异或补充                                                    |
| ---------------------------------- | ----------------------------------------------------------------------------- |
| TTFT、首个非推理输出与请求延迟概念 | 主界面采用正文首响，不直接把包含推理的工具 TTFT 重命名。                      |
| 内容块间隔及单请求速率             | 工具 ITL 默认有首块 token 假设；本设计无可靠区间计数时不填生成 tokens/s。     |
| 并发调度、请求记录和聚合能力候选   | 需满足本设计的窗口/排空、异常保留、实际负载和目标长度分层，不能照搬汇总字段。 |

## 8. 设计反例

| 场景                                               | 正确的设计表达                                                |
| -------------------------------------------------- | ------------------------------------------------------------- |
| 0.1 s 空事件，0.3 s 推理，1.2 s 正文，4 s 正常结束 | 正文首响 1.2 s，完整耗时 4 s；前两者仅详情记录。              |
| 第一个内容块包含多个 token                         | 不把一块等同于一个 token，也不机械使用 `(N-1)` 计算生成速率。 |
| 40 次里 2 次超时，成功返回总共 38 次               | 成功延迟分母为 38；全请求分母仍为 40，超时单列。              |
| 120 s 窗口内完成 90 个，排空再完成 10 个           | 窗口吞吐为 0.75 请求/s；排空完成量另记。                      |
| 目标 2048，快速自然结束在 100 token                | 记录完整返回，但目标长度未达标；不能当作 2048-token 性能。    |
| 600 s 计划在 120 s 遇到限流停止                    | 显示实际观察 120 s 和停止原因，不声称已完成十分钟稳定性观察。 |

以上为纸面规则示例，不是已经执行的测试或验收。
