# 模型能力跑分设计草案

版本：0.1。日期：2026-09-09。父任务：[#17](https://github.com/relaxcloud-cn/llm-capability-doctor/issues/17)。

本轮只做设计。六类范围沿用父任务；题量、题型、主指标和选用方式为本次设计方案，不写成真实模型成绩，不开发执行器，不运行模型，不开展实现或验收。用户只需对产品方向分歧作决定，不逐项审批内部评分细节。

## 1. 客户最终看到什么

客户看到六张分类成绩，不是一张支持/不支持表，也不是六类加权总分。每类先呈现正确数量、已评分数量、覆盖情况与典型错误，条件和逐题依据可展开。

### 1.1 不做什么

不做编程能力、专业知识榜单、整体兼容分、服务可用性门槛、性能测量或 Agent 环境验证。不用一次简单调用成功代表高能力，不把可选接口不支持混为有效答题错误。

## 4. 题量与固定配置方案

### 4.1 初始题量

每类设计 5 个子方向，每方向 8 个基础样本，共 40 个基础样本。该数量是首版设计起点，不是官方标准或已证实的代表性门槛；用户可在设计 review 时修改。

| 类别       | 基础计分单位                     | 初始数量                 | 不混淆的数量                                               |
| ---------- | -------------------------------- | ------------------------ | ---------------------------------------------------------- |
| 文本与指令 | 一道完整任务                     | 40                       | 一题多项约束不算多道独立题。                               |
| 提取与填写 | 一条完整记录任务                 | 40                       | 字段数用于诊断，不当作独立任务数。                         |
| 工具选择   | 一道目标决策任务                 | 40                       | 多个工具调用仍可能属于一道任务。                           |
| 多轮条件   | 一段三回合对话                   | 40                       | 120 个回答回合不等于 120 段独立对话。                      |
| 长材料     | 一个基础任务在一个长度条件的观察 | 40 个基础任务，最多 3 档 | 最多 120 次观察按长度分别计，不虚报为 120 个独立基础任务。 |
| 推理计算   | 一道完整任务                     | 40                       | 多步运算不重复计题。                                       |

五个非长材料类别共 200 个基础计分单位；长材料另有 40 个基础任务。不能把各类题数、回合数和长度条件机械相加成一个总分分母。

### 4.2 选题与比较

按子方向分层选取，冻结样本 ID 和内容哈希。不能在看过某个被测模型输出后选择它擅长的题，或悄悄移除难题。选择集变动必须升级题库版本；旧新版本不直接计算改进幅度。

每个题库配置记录来源版本、原版/改编身份、语言、样本列表、提示版本、角色与历史组织、输出形式、实际请求设置、采样次数及答案规则。省略的参数也要记录为“服务默认”，不能假装服务默认已经固定或已知。

所有调用使用已定 Chat Completions 范围，首版计分回答采用非流式以减少无关组合；流式能力仍归 #16。使用生成长度设置只作为固定任务条件，不恢复 #16 已撤销的输出参数专项。设置导致回答截断时必须区分任务结果与测试配置问题，不通过悄悄加长或补问来替换原始计分回答。

正常任务每个计分单位保留第一次有效回答；有效错误不通过重试择优。执行异常的补试采用有限规则，具体等待与上限属于后续设计细化，不从 #16 的有效失败复核规则直接继承“最差一次决定全部成绩”。跨模型、跨版本比较前核对配置，条件不一致时不宣称严格可比。

### 4.3 长度条件

长材料初始参考档为 4K、16K、64K token（K=1024），仅选择已有可靠输入范围允许的档。参考 tokenizer、生成材料、输出预留与实际服务计数分别记录。

同一基础题保持答案、关联步数和关键事实数量不变；同一长度跨模型优先保持材料文本相同，报告实际计数差异。不因服务最大容量不同为每个模型换一套语义材料后直接排名。共同可用的题目与长度才可作严格对照。

## 5. 逐题计分与分类聚合

### 5.1 有效性与正确性分开

“有效”表示取得了足以按题目规则判断的作答，不表示作答正确。错误数值、填错字段、格式不合规、应调用却不调用，以及正常任务中的无理由拒答，不能因为模型没完成任务就移到无效执行。

没有响应、认证或网络异常、执行器故障与题目本身有缺陷分别记录。缺少前提而未发送的题目记录未覆盖及原因，不当成已作答错误，也不据此生成全量成绩。

正确的不调用、澄清缺失信息和合法的“材料不足”可能是满分答案，按具体题目判断；不能把所有拒绝/不调用归为同一种错误。

### 5.2 主指标与分母

对于一个固定类别或一个固定长度档，定义：

| 记号 | 定义                                                                                |
| ---- | ----------------------------------------------------------------------------------- |
| N    | 清单中应统计的计划计分单位数。                                                      |
| C、W | 已确定正确与错误的有效单位数。                                                      |
| Q    | 已有作答但评分规则暂不能确定结论的单位数。                                          |
| I、M | 执行问题导致未能确定结果的单位，以及未执行/前提不满足的单位。                       |
| V    | 已评分有效数，`V = C + W`；各单位只进入 C/W/Q/I/M 中一类，`N = C + W + Q + I + M`。 |

主结果展示 `C / V`，同时同屏展示已评分 `V / N`、待评分和未完成数。V 为 0 时显示无成绩，不展示 0% 或 100%。允许展示由原始计数换算的正确率，但不换算成六类统一百分制总分、不做加权总分，也不设置“达到某分即可用”的线。

只完成部分题目时必须标明部分成绩，不把 Q/I/M 默默消失。诊断的字段、约束、回合比例与整题比例不相加。出现题目缺陷时保留原条目和修订关系，以同一版本规则处理所有受影响模型，不只删掉某次失败。

### 5.3 多轮与错误后中断

多轮主指标要求连续各轮均正确。任一轮已出现有效错误，就已经确定整段不能全对，归 W；即使随后连接中断，也不把这段移出错误分母。若尚无有效错误但后续未完成，归 I 或 M，不能当作整段成功。

对话完成标记与对错另列；因此“未完成对话数”可以包含已确定错误的对话，但不能在 C/W/Q/I/M 求和时重复计入。逐轮诊断只记录有足够证据的回合。

### 5.4 等义答案与语义判定

有确定答案的题优先用预先设计的答案集合、数值容差、实体别名、集合或顺序规则。日期、单位与可空字段的处理写在题目里，不为某次输出临时放宽。

首版主分优先选择可核验内容，不增加开放式文风或文学质量评分。对于内容归纳，预先定义必要事实点和错误事实，不以参考答案逐字一致作为唯一标准。未覆盖但可能正确的表达进入 Q，不能简单扣分，也不能自动算通过。

本稿不选定额外的语义裁判模型或托管平台；如果后续确实需要自动语义裁判，其 rubric、允许答案、冲突复核方式应单独设计。人工或模型复核没有完成时保持待评分，不将“另一模型说正确”直接变成主成绩。最终题库应优先减少这类不确定性，但不能以排除所有难判错误的方式提高分数。

### 6.2 多轮说明

四段计划对话：一段连续全对，两段已出现有效错误（其中一段随后中断），另一段尚无错误但因网络异常未完成。预期 C=1、W=2、I=1、N=4，主结果为 1/3、已评分 3/4；不能把后续中断的已知错误删除成 1/2。

## 7. 需要对齐的产品决定

当前需要用户决定的是首版语言：默认以中文业务题为主，还是优先保留外部英文原题？这会影响题库身份、材料、语言约束和成绩解释，不应由设计者默认为已确认。

本稿建议中文优先，借鉴已核对的公开方法，并对实际改编题明确标识；英文原题可在后续作为单独题库，不与中文题混合成一个类别分母。这只是建议，尚未采用为用户决定。现有中文说明例题仅用于读懂设计，不等于已经确认正式题库语言。

默认题量、计分结构和子项已给出可 review 的具体方案，不再把每个内部细节变成用户问答。后续如果出现会改变产品范围或成绩含义的分歧，再逐个对齐。

## 8. 本轮设计交付范围

已写出六份子设计与统一草案，覆盖来源取向、题型、初始题量、计分单位、分母、等义答案、缺测和客户成绩示例。六个子 Issue 均作为设计材料公开，关联在 #17 下。

本轮没有编写完整外部题目清单、下载题库、冻结所有最终数据文件、实现评分器或运行校验。题库语言确认后，设计材料还需要补齐最终样本/生成规格及规则版本；这属于继续完善设计，不是要求本轮进入实现、实测或验收。
