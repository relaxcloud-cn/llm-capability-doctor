AgentCheck 检测项评审表

每个检测项只回答两件事：怎么检测，怎么判定。评审范围：当前 6 个模块全部检测项。

检测项检测逻辑判定逻辑
一、入口兼容性 ingress
HTTP 请求与鉴权使用配置的 URL、模型和 Bearer Key 发送最小 Chat Completions 请求。2xx 记为请求成功，401/403 记为鉴权或权限失败，网络异常记为不可判定。
错误码与重试记录请求返回的 HTTP 状态并按传输策略对 429、5xx 和网络错误重试。429/5xx/网络错误归为可重试或不可判定，不能归因于模型能力。
JSON 响应解析解析服务返回的 JSON，并读取顶层响应和首个 choice。JSON 可解析且存在可识别响应结构记为协议通过，否则记为协议失败。
模型身份记录请求模型名，并读取服务返回的 model 字段。只报告配置模型与服务返回模型的事实差异，不因名称差异直接判模型失败。
响应内容提取从 choices[0].message.content 或兼容的 text 字段提取内容。能按 Agent 需要提取内容记为支持，字段缺失或类型错误记为协议失败。
二、协议规格 specification
S01 协议可接受上下文上限从 32K 输入开始发送真实长度请求，成功后翻倍，直到达到配置上限或服务拒绝。2xx 且响应合法记为接受，明确上下文超限记为拒绝，其他异常记为不可判定，并输出最后成功长度。
S02 输出长度使用不同的 max_tokens 发送可计数的长输出请求，记录实际输出长度和结束原因。按参数是否接受、输出是否达到目标、是否自然结束或截断，分别判定支持、受限或不可判定。
S03 常用参数针对每个 Agent 依赖参数发送真实请求，每组只改变一个参数并保存请求体和响应。参数被接受且符合协议记为支持，明确拒绝记为不支持，无法排除服务异常记为不可判定。
S04 工具调用提供真实工具 Schema，分别测试必须调用、无需调用、多工具和错误参数场景。校验工具名、参数 Schema、调用次数和时机，协议不支持与模型选择错误分开判定。
S05 结构化输出使用 Agent 实际的 response format 或 JSON Schema 请求结构化输出。解析并校验 JSON、必填字段、类型、枚举和嵌套结构，分别判定通过、拒绝或结构错误。
S06 消息与多轮输入按真实 Agent 顺序发送 system、user、assistant、tool 消息和多轮历史。校验角色顺序、消息格式和请求可接受性，协议兼容与语义承接分开判定。
S07 流式输出分别发送文本流和工具调用流，读取 SSE 分块、增量内容、工具增量和终止事件。校验分块格式、顺序、内容拼接、工具参数完整性和正常终止，断流和非法分块分别归类。
三、基础能力 capability
C01 指令遵循：材料事实提供带明确约束的材料，要求模型只依据材料完成指定任务。检查必需事实、格式和禁用内容；硬约束满足记为通过，遗漏或越界记为失败，语义不确定交 OhMyPi。
C01 指令遵循：条件筛选提供多条材料和筛选条件，要求只返回满足条件的对象。用集合和条件校验结果完整性；集合正确记为通过，漏项或误选记为失败。
C01 指令遵循：单约束要求模型同时遵守一个明确输出限制并生成答案。规则校验输出限制，OhMyPi 判断语义是否真正遵守；任一关键约束失败则失败。
C01 指令遵循：多约束要求模型同时满足多个格式、内容和禁答约束。硬约束用代码校验，开放语义由 OhMyPi 按规则判定，证据不足记为不可判定。
C01 指令遵循：信息不足故意移除完成任务所需事实，观察模型是否识别缺失信息。模型明确指出缺失且不编造记为通过，编造或无依据下结论记为失败。
C02 信息抽取：单对象字段提供单对象材料，要求按字段输出结构化结果。Schema、字段值和必填项用规则校验，字段语义有歧义时由 OhMyPi 复核。
C02 信息抽取：多对象关系提供多个对象及关系，要求输出对象之间的关联。校验对象数量、ID 和关系集合，关系解释无法形式化时由 OhMyPi 判断。
C02 信息抽取：字段类型提供含数字、日期、枚举和布尔值的材料，要求按指定类型输出。按 Schema 和值解析判定类型，非法格式或类型转换错误记为失败。
C02 信息抽取：缺失值提供字段缺失的材料，要求使用约定的缺失表示。缺失字段必须标记为未提供或约定值，不得猜测补全。
C02 信息抽取：冲突信息提供相互冲突的材料，要求模型指出冲突并按规则处理。检查是否识别冲突和保留来源，未识别冲突或擅自取值记为失败。
C03 工具选择：工具选择提供多个工具和任务，要求模型选择完成任务所需工具。工具名和调用必要性用规则校验，选择错误记为失败。
C03 工具选择：参数填写提供任务所需字段，要求模型生成工具参数。按工具 Schema 校验参数完整性和字段值，缺失或错误记为失败。
C03 工具选择：参数类型要求模型为工具填写数字、枚举、数组等不同类型参数。解析参数并按 Schema 校验类型、范围和枚举值。
C03 工具选择：多工具提供需要连续或并行使用多个工具的任务并记录完整轨迹。校验工具集合、顺序或并行关系及参数，轨迹不满足要求记为失败。
C03 工具选择：正确不调用提供无需工具即可回答或禁止调用工具的任务。没有工具调用且最终结果符合规则记为通过，误调用记为失败。
C04 多轮：条件保持第一轮设定条件，第二轮要求依据未变条件继续处理。校验回答是否引用正确条件，语义承接由 OhMyPi 按证据判断。
C04 多轮：条件更新后续轮次修改前一轮条件，要求模型使用新条件。检查旧条件是否被替换、新条件是否生效，混用条件记为失败。
C04 多轮：条件撤销后续轮次明确撤销前一条件，观察模型是否停止使用该条件。最终结果不得继续依赖已撤销条件，否则失败。
C04 多轮：对象切换多轮中切换当前对象，要求模型只处理最新对象。校验对象标识和结果归属，串用历史对象记为失败。
C04 多轮：历史区分提供多个相似历史对象，当前轮要求区分并引用指定对象。校验引用对象和关键事实，无法仅靠结构确认时由 OhMyPi 判断。
C05 长上下文：局部定位在不同长度材料中埋入目标事实，要求模型定位并返回事实。按事实值和输入长度校验结果，未命中记为失败，服务拒绝记为不可测协议结果。
C05 长上下文：跨段关系把完成任务所需事实分散在不同段落，要求模型合并使用。校验必需事实和关系，遗漏或错误关联记为失败。
C05 长上下文：干扰排除加入相似但无关的干扰信息，要求模型只使用目标信息。检查是否选中正确事实并排除干扰，语义判断交 OhMyPi。
C05 长上下文：长度变化保持任务不变，仅改变材料长度并重复执行。比较各长度下的协议接受和任务正确性，不能把短长度结果外推到长长度。
C05 长上下文：文内计算要求模型使用长材料中的数字完成计算。由程序复算数值并校验引用事实，结果错误记为失败。
C06 推理：条件判断提供事实、规则和条件，要求输出可验证结论。用规则或参考答案验证结论，开放解释由 OhMyPi 辅助。
C06 推理：时间顺序提供带时间关系的事件，要求排序或判断先后。程序比较顺序和最终答案，顺序错误记为失败。
C06 推理：数量比较提供多个数量及单位，要求比较大小或选择结果。归一化单位后由程序计算校验，数值错误记为失败。
C06 推理：基础计算提供可独立复算的算式或数字问题。程序计算期望值并按容差、单位校验模型结果。
C06 推理：多条件推导提供多个相互依赖条件，要求模型完成组合推导。可形式化部分用程序校验，推导链和解释由 OhMyPi 按 rubric 判定。
四、性能 performance
P01 响应等待发送固定输入并分别测试流式、非流式请求，记录首事件、首可见内容和完成时间。按实际时间线统计 P50/P95；超时、错误和未完成请求不进入正常延迟指标。
P02 生成速度与流畅度发送目标输出长度的流式请求，记录可见 token、分块间隔和完成状态。计算 token 速率、分块暂停和完成率；输出观测值，不脱离配置阈值判断好坏。
P03 并发承载按 1、2、4、8 等并发档位同时发送请求并记录实际并发和结果。按每档成功率、错误率、延迟和限流情况判定承载表现，限流与服务失败分开记录。
P04 连续运行稳定性在受控时间窗口内连续发送固定请求，记录每次终态、错误和恢复情况。按完成率、异常终止、超时和连续失败统计稳定性，不能用单次成功代表稳定。
P05 长输入性能使用真实构造的 2K、8K、32K 等输入长度发送请求并记录 token 和耗时。按实际输入长度、请求是否接受、延迟和完成率分别报告，未达到目标长度的样本不得归入该档。
P05 长输出性能使用不同输出预算发送可计数的长输出请求并记录实际输出 token 和结束原因。按输出长度、生成速率、截断和超时统计，参数未真正生效时记为不可测。
P05 历史增长性能逐步增加多轮历史消息长度，按每个历史长度发送请求并记录耗时和终态。按历史长度档位比较接受率、延迟和错误类型，不能把一次失败直接归因模型。
五、Agent 兼容性 agent
A1 遵守任务规则给模型任务约束、工具和目标产物，记录完整多轮轨迹及最终结果。代码校验硬约束和产物，OhMyPi 判断开放语义是否遵守；关键约束失败即失败。
A2 工具与参数正确在工具场景中提供工具 Schema，记录模型发出的每个工具名和参数。按允许工具、参数 Schema、必填字段和类型逐项校验。
A3 使用工具返回执行工具并返回带有可验证事实的结果，观察模型后续请求和最终答案。代码确认返回已送达，OhMyPi 根据前后轨迹判断后续是否真正使用返回事实。
A4 多轮状态保持通过多轮工具调用改变条件或目标，记录每轮消息和状态变化。代码校验消息链完整，OhMyPi 判断模型是否保持并正确更新任务状态。
A5 工具失败处理让工具返回可恢复错误或不可恢复错误，观察模型是否重试、调整或结束。按错误类型和预期恢复策略校验轨迹，错误后继续错误操作或编造成功记为失败。
A6 信息不足处理隐藏完成任务所需信息或返回不完整工具结果，观察模型后续行为。模型请求补充、明确无法判断且不编造记为通过，凭空补全记为失败。
A7 操作权限配置允许和禁止的路径、工具及操作，记录权限决策和实际文件效果。允许操作正常完成，禁止操作未产生实际副作用；任何未授权写入直接失败。
A8 交付与结束要求模型生成指定产物并结束任务，记录产物、摘要和最终消息。代码校验产物存在、内容和结束状态，OhMyPi 判断最终说明是否与证据一致。
六、协议基线 baseline
BC01 响应外层发送非流式请求并保存完整响应 JSON。按参考结构校验外层必需字段、类型和可选字段。
BC02 候选结果容器读取响应中的 choices 及其元素。校验数组、元素对象、索引和候选结构是否符合基线。
BC03 回复消息读取首个候选的 message、role、content、refusal 和 finish reason。按字段存在性、可空性和类型判定结构兼容。
BC04 用量汇总读取 prompt、completion、total token 用量字段。校验字段类型和基本一致性，缺失记为差异而不是直接判整体不可用。
BC05 用量明细读取服务返回的输入、输出或缓存 token 明细。按可选字段和类型校验，未提供记为未观察到。
BC06 服务元数据读取响应中的服务附加元数据和模型标识。按基线字段规则比较结构，动态值不参与结构判定。
BC07 工具调用容器发送工具场景并读取 assistant message 中的 tool calls。校验数组、调用对象和函数容器结构。
BC08 函数名称与参数读取每个工具调用的函数名和 arguments 原始内容。校验字段类型和参数承载形式，参数业务内容另由工具规则判定。
BC09 流式外层发送流式请求并逐块解析 SSE 数据。校验每个分块是否为合法 JSON 和流式响应外层结构。
BC10 流式候选容器读取每个分块中的 choices 数组和候选对象。校验分块候选容器、索引和字段类型。
BC11 流式消息增量读取 delta 内容、role、finish reason 并按顺序拼接。校验增量结构、顺序和最终拼接结果，非法或缺失终止分别归类。
BC12 流式工具增量读取工具调用的分块增量并拼接函数名和 arguments。校验增量顺序、索引和最终参数是否可解析。
BC13 流式用量在流式结束或扩展字段中读取 usage 信息。按字段存在性、类型和出现位置判定支持或未观察到。
BC14 错误对象主动触发或捕获错误请求并保存完整错误 JSON。校验错误对象、错误类型、消息和字段结构，不能把错误响应当正常响应。
