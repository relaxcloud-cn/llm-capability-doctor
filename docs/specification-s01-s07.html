模型规格实测：S01–S07 检测逻辑与判定逻辑

回答"当前服务支持什么、实际验证到哪里、有哪些限制"。不回答能力强弱、不产出总分、不替代 Agent 任务验收，不把一次网络成功解释为能力通过。接口范围：OpenAI 风格 Chat Completions，除 S07 外一律非流式。

统一执行契约

每次请求必须记录

  • endpoint（脱敏稳定标识）、model（原样记录，不鉴定后台真实模型）、protocol、完整 request settings
  • 测试版本（文档版本 + 类别编号 + 样例编号 + 题目指纹）、运行环境、脱敏请求 / HTTP 状态 / 完整响应或完整事件序列
  • 同一对照请求只改变正在验证的一个因素；认证失败、服务不可达、全局限流等环境阻断应停止分支并标执行异常，不重复打满全部样例

重试与停止（全局上限）

初测 1 次 ── 有效但不合规 → 同条件复核 ≤ 2 次（首次有效失败始终保留，复核成功不覆盖） ── 执行异常（超时/限流/断连/无效 HTTP）→ 重试 ≤ 2 次，取得有效响应后转内容判定 ── 复核/重试不改题目、设置、证据版本；重试耗尽仍无有效证据 → inconclusive，不得改写成 failed

判定分层原则

  • 接口接受 ≠ 参数生效 ≠ 范围已验证：accepted / effective / verified_range 是三个独立事实层级，可同时保存，禁止互相晋升
  • 边界声明必须有失败侧证据：只有相邻"成功档 + 可归因失败档"才能写边界；单边成功只能写"已验证到 N"
  • 自然结束不是上限证据：模型提前说完不等于参数失效或到达上限
  • 环境错误不产生 unsupported：网络、超时、网关错误一律走 inconclusive；只有服务明确拒绝才可写 unsupported

状态语义（七档）

状态使用条件禁止解释
verified_range在明确记录的输入/输出/schema 范围内完成并满足规则不得写成服务理论最大值
effective受控对照证明目标控制改变了行为不得扩大到未测取值或任意组合
acceptedHTTP/协议层接受了字段，但没有足够行为证据不得写成参数已生效或能力已通过
unsupported有效响应明确拒绝或明确声明不支持该能力不得由一次环境错误推出
failed有效响应违反了本项规则不得被后续偶然成功覆盖
inconclusive证据不足：超时、限流、截断、计数缺失等不得冒充通过或失败
not_applicable当前协议、配置或样例条件不适用不得计为失败

类别结论 = 该类全部样例观察的聚合；任何一个样例达到更高层级即提升类别层级（verified_range > effective > unsupported > failed > accepted > not_applicable > inconclusive）。verified_range 必须同时满足"真实执行证据 + 显式 scope"。

S01 上下文容量 现状：已实现（固定四档真实输入）

回答：在固定输出余量 256 条件下，服务实际接受并完成到多大输入。不回答：长材料理解质量、最大输出能力、服务理论上限。

检测逻辑

  • 密度校准：先发约 4,000 字符固定文本，读 usage.prompt_tokens 算出该端点的字符/token 密度（clamp 0.5–16；拿不到 usage 用默认 3.0）
  • 固定四档：64K / 128K / 256K / 512K tokens 全部发送，不提前停止；按"档位 × 密度 × 1.05"构造真实长度填充文本（唯一首尾标记，尾部 "Reply only OK."）
  • 计数来源：优先服务端 usage.prompt_tokens；无 usage 时按校准密度估算并在报告中注明；差个几万 token 不重要
  • 封顶：512K 为最高探测档，不向上扩探
一档"通过" = HTTP 2xx + 可解析 chat-completion 结构 + 实测/估算 prompt_tokens ≥ 档位目标

判定逻辑

观察到的证据判定说明
2xx + 结构合法 + prompt_tokens ≥ 档位（usage 或估算）verified_rangescope 写"input ≤ 实测值 tokens"；估算时注明来源
非 2xx 且报文明确指向超长（context length / too many tokens / 超长 等）failed可归因容量拒绝，构成上界证据；四档全拒 → S01 失败
2xx 但 usage.prompt_tokens < 档位inconclusive疑似静默截断或计数口径不一致，不冒充通过
HTTP 413 / 5xx / 超时 / 其它非 2xxinconclusive网关体积限制、环境异常不归因模型窗口
2xx 但响应结构不可识别failed—
注意：被拒档记为 failed 并写入 limitation 作上界证据；类别聚合仍取最高优先级，已通过档的 verified_range 不受影响。证据中只保留 prompt 首尾各 64 字符，512K 原文不进报告。

S04 工具调用 现状：已实现（5 个真实工具请求）

回答：能否按给定工具定义生成正确的非流式调用。不回答：工具执行、回传续答、规划与工具选择质量（归 Agent 模块）。

检测逻辑

  • 固定工具：lookup_weather（一次埋入 string / integer / enum / boolean / array / 嵌套 object 六类参数）+ lookup_air_quality（city:string + index:integer，验证不串位）
  • 5 个固定样本各 1 次：题目直接给出全部参数值，不考推理；原 T01–T04 参数类型校验合并进一次调用
样本tool_choice调用形态必查事实
tools-all-typesrequired单工具单调用恰好 1 个 lookup_weather；city/days/unit/include_alert/locations/options.lang 类型与值全对、无多余字段
tools-none"none"禁止调用不返回 tool_calls 且有文本回答；返回调用即有效失败
tools-same-twicerequired同一工具调两次恰 2 个 lookup_weather；每次调用参数独立合规、城市集合 = {北京, 上海}
tools-two-distinctrequired两个不同工具各一次lookup_weather + lookup_air_quality 各 1 个；参数不串位、各按其 schema 校验
tools-forced指定 lookup_weather强制指定工具≥1 个调用且全部名为 lookup_weather，不许替换成其他工具或纯文字

（原 #36 矩阵为 9 类 × 3 组 = 27 次：T01–T04 合并为 tools-all-types；T09「缺必填字段仍按题生成」因判定偏模型行为而非协议契约，已砍掉。规格层不做复核重发，每样本只发初测 1 次；执行异常的重试仅发生在传输层，不计入样本次数。）

判定逻辑：三层顺序，逐层定位失败

① HTTP 成功 + 响应可解析 + choices[0].message 存在 ② tool_calls 容器存在 + 调用数量 + 函数名 + arguments JSON 可解析 ③ JSON Schema 校验：必填字段、类型、枚举、数组元素、禁止额外字段 任一层失败 → 保留失败层级 + 原始脱敏响应；复核成功不覆盖首次有效失败
事实判定
三层全部满足pass / verified
无调用、漏调用、文字代替调用、参数串位、JSON 合法但 schema 不符failed
服务明确拒绝工具字段或声明不支持unsupported
认证/超时/限流/截断等无足够有效响应inconclusive

设计：design/issue-36-tool-calling.md + issue-16 §6 · 实现：src/tool_probe.rs + LiveExecutor::execute_tool_call_probes

S05 结构化输出 现状：已实现（两模式各 1 次）

回答两个独立问题：①能否返回合法 JSON（只验证语法）；②能否满足给定结构（字段/类型/约束）。不回答：业务字段正确性、业务任务质量。

检测逻辑：同一短文本 × 两种模式各 1 次

子项请求设置通过条件失败条件
合法 JSON{"type":"json_object"}message.content 原文可被标准 JSON 解析器解析解析失败、夹杂不可解析前后文
指定结构{"type":"json_schema","json_schema":{...}}（仅服务声明支持时）JSON 可解析 + 必填字段存在 + 类型/枚举/非空/范围约束满足缺字段、类型错误、schema 声明禁止时出现额外字段
  • 判定材料：只取 choices[0].message.content 原文直接解析；禁止去代码围栏、补逗号/括号、自动转型、截去前后文后判通过（修补结果只能作诊断字段）
  • "响应外层是 JSON"、HTTP 成功、finish_reason、参数回显，都不能单独证明生成内容通过
  • 两个子项分别出结果，不允许用"JSON 通过"覆盖"结构失败"；失败定位到字段路径（如 tags[] 元素类型）

判定逻辑

事实判定
schema 请求原文满足全部约束，且该模式条件确实生效effective
服务明确拒绝该模式字段unsupported（不计入结构失败分母）
JSON 可解析但缺必填字段/类型错误/约束违反failed（定位字段路径）
超时/限流/截断/内容缺失inconclusive

设计：design/issue-39-structured-output.md · 实现：src/structured_probe.rs + LiveExecutor::execute_structured_probes（每样本只发初测 1 次，规格层无复核重发）

S06 消息与多轮输入 现状：已实现（4 个固定消息序列各 1 次）

回答：常见消息角色是否被接受；同一请求携带历史消息时能否完成最小跨轮信息传递。不回答：长期记忆、跨会话记忆、复杂对话质量。

检测逻辑

样例请求结构成功条件
M01system + user返回非空、可解析的 assistant 消息
M02system + user + assistant + user最后一轮正确引用历史中的唯一标记
M03多条 user + 一条 assistant 历史能区分当前问题与历史标记，结束正常
M04适用时加入 tool 角色消息（不要求工具闭环）消息被接受；协议不适用则 not_applicable
  • 唯一标记只出现于一个历史位置；答案只要求确认标记，不要求长篇生成
  • 不跨请求构造记忆；结论仅覆盖已测角色组合和"同请求携带历史"模式

判定逻辑

事实判定
角色被接受 + 标记被正确引用/区分 + 正常结束pass / verified
角色被拒绝、消息格式错误、响应为空、标记错引/丢失failed
tool 角色在当前协议不适用not_applicable（不计失败）
认证/网关/超时等执行异常inconclusive

S07 流式输出 现状：已实现（文本标记流 + 工具增量流各 1 次）

回答：普通文本和工具调用的增量能否被接收、按协议组装并正常结束。不回答：首字节延迟、吞吐、并发、稳定性（归性能模块）；结构字段差异归基线模块。

检测逻辑

  • 固定设置：stream:true、温度 0、短受控提示 + 唯一首尾标记；客户端必须保存原始字节、SSE 事件原文及顺序、事件时间、终止事件、组装结果
  • 文本场景（stream-text）：短受控提示要求回复带 STREAM_BEGIN/STREAM_END 首尾标记，组装内容须完整含标记且正常终止
  • 工具场景（stream-tool）：携带固定双工具 + tool_choice:required + 流式；增量按 index 归组拼接——单个片段可以是非法 JSON，拼接结果须为合法 JSON 且符合天气工具必填字段
  • 设计中的对抗切片场景（空事件穿插、跨块分片、缺 [DONE]、参数截断、交错调用）无法要求真实服务产生，落在 stream_probe 的合成事件流单测中覆盖
  • 网络分块数量 ≠ 语义增量数量；客户端主动取消单独记录，既不算服务正常结束，也不算模型失败

判定逻辑

文本通过 = 内容增量可解析 + 顺序正确 + 首尾标记完整 + 终止原因可识别 + 客户端未主动停止 工具通过 = 调用身份可归组 + 名称完整 + 参数片段按序拼接后 JSON 可解析 + 符合 schema + 正常结束可验证
事实判定
上述全部满足pass / verified
收到 [DONE] 但无完整内容 / 部分文本后断开 / 参数尾部断开 / 拼接后仍不可解析failed / inconclusive
服务明确拒绝 stream=trueunsupported
工具场景只有普通文字、没有工具增量failed / inconclusive（不能用文本流通过替代）
客户端主动停止记录停止原因，不归因模型
注意：空内容事件是合法事件不判负；收到部分参数片段不等于调用成功，必须等组装+解析+结束证据齐全。

设计：design/issue-40-streaming-output.md · 实现：src/stream_probe.rs + LiveExecutor::execute_stream_probes（StreamEvent 记录 tool_calls 增量原文；每样本只发初测 1 次）

下游消费与模块边界

  • verified_range 是下游模块的输入前提：能力跑分的长上下文样本按 validated_input_max_tokens 决定跳过或执行——规格实测产不出 verified range，下游就只能记 missing 而不是假装测过
  • 证据包：每个子项 ≥1 个可定位证据（脱敏请求+设置指纹、HTTP 状态/完整事件序列、计数来源与 finish_reason、初测/复核/重试关系、题目指纹与规则版本）；API key 不进入任何证据
  • 显示口径：客户视图必须同时展示结论 + 已测范围 + 条件 + 限制 + 证据位置；任何下界不得显示在"最大上限"字段
  • 责任边界：未通过某子项 ≠ 整套服务不可用；accepted 不计入通过；环境异常不写成模型失败；不推未测能力
